## 1. 배경·문제

개인 기술 블로그는 "글을 올릴 수 있다"만으로는 제 역할을 못 한다. 저자 1인이 6년 넘게 축적한 글이 재사용되지 않거나, 한국어권 밖 독자에게 닿지 않거나, 쌓일수록 원하는 글을 못 찾거나, 검색·AI 검색에 잡히지 않으면 축적 자체가 무의미해진다.

- 읽기 보조: 목차, 읽기 진행률바, 이전/다음 글, 브레드크럼, 예상 읽기 시간

- SEO/GEO: sitemap, robots(AI 크롤러 22종 allow), canonical/hreflang/x-default, OG 이미지, JSON-LD 7종
- **canonical↔sitemap 불변식** — canonical/hreflang/og:url이 절대 URL이며 sitemap의 대응 `<loc>`과 정확히 일치한다(R10, `seo.test.ts`가 게이트)
- 인기 글 Top 5: 커밋된 `data/popular.json` 기반, 비어 있으면 최신순 폴백
- 접근성: 본문 건너뛰기 링크, 시맨틱 랜드마크, 키보드 조작
- 계측: GA4, **검색 콘솔·네이버 소유권 확인 메타 태그**(NFR7 — 유실 전례가 있는 자산이다: `4d1f4573`)

| **M1** | 미측정 지표 기준선 확보 | GA4 콘솔에서 SM1(오가닉 세션/PV), SM2(조회수 ≥1회 글 비율), A3(로케일별 세션 비중)을 조회해 §2.2의 "현재값"을 실측치로 대체한다 | GA4 접근 권한 |
| **M2** | `popular.json` 복구 확인 | `refresh-popular` 수동 실행 후 `updatedAt ≠ null` 이고 `items`가 비어 있지 않으며, 배포 후 사이드바 Top 5가 최신순과 다른 순서로 표시된다 (RK1 해소, R9 → 충족) | M1, 시크릿 유효성 |
| **M4** | 배포 토폴로지 정합화 | `package.json:deploy`·CLAUDE.md가 실제 서빙 브랜치(`gh-pages`)와 일치하고, **`deploy.yml`의 트리거 브랜치 목록(`on.push.branches`)도 실제 체인과 일치하며**, GitHub Pages 설정 화면에서 서빙 소스가 확인·기록된다 (RK2 해소) | — |

> **M3는 결번이다**(직전 판에서 "미정 백로그 재검토"가 §7로 이월되며 제거됨). RK1↔M2·RK2↔M4 참조가 본문 여러 곳에 걸려 있어 번호를 당기지 않는다.

> **이월**: 미정 백로그(O1~O5) 재검토와 `comments` 필드 존치 여부(RK5)는 **별도 기획 라운드**로 넘긴다.

## 7. 인계 사항 (차기 기획 라운드)

- O1~O5 각각의 채택/보류/배제 판정 — 근거는 M1 기준선(트래픽·독자 구성)
- `comments` 프론트매터 필드 존치/제거 (RK5)
- SM3 목표치 설정 여부 재검토 (현재 합의: 목표치 없이 추이 관찰)
- **가정 A9의 운용** — 모더레이션·응대를 요구하는 기능이 제안될 때 "별도 판단 항목으로 분류"를 실제로 누가 언제 수행하는지. 제품 관찰로 판정 불가한 프로세스 약속이므로 기획 라운드에서 관리한다
