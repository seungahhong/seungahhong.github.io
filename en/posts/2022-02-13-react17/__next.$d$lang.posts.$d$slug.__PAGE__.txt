<h3 id="no-more-import-react-">No more 'import React ...'<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#no-more-import-react-"><span class="icon icon-link"></span></a></h3>
<p>To use JSX, you always had to import React (even if you didn't reference it explicitly).</p>
<p>This was because JSX code was transpiled into plain JavaScript through tools like Babel or TypeScript.</p>

<h3 id="consistent-errors-when-returning-undefined">Consistent errors when returning undefined<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#consistent-errors-when-returning-undefined"><span class="icon icon-link"></span></a></h3>
<p>In versions 16 and below, every component would always throw an error when it returned undefined.</p>
<p>However, due to a coding oversight, this error handling was missing for <code>forwardRef</code> and <code>memo</code> components, and it has now been added.</p>

<h3 id="no-event-pooling"><strong>No Event Pooling</strong><a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#no-event-pooling"><span class="icon icon-link"></span></a></h3>
<ul>
<li>Event pooling
Because there was an issue where using event objects in older browsers caused performance degradation, React created and managed a Synthetic Event pool.
<ul>
<li>When a user triggers a particular event
<ul>
<li>It passes a reference to a Synthetic Event object from the Synthetic Event pool (→ reducing object creation time)</li>
<li>It populates the Synthetic Event object with the event information</li>
<li>It runs the event listener defined by the user</li>
<li>It resets the Synthetic Event object (→ by assigning null so that GC can reclaim the memory, a step for memory efficiency)
This feature can cause errors to occur in asynchronous operations.</li>
</ul>
</li>
</ul>
<figure data-rehype-pretty-code-figure=""><pre tabindex="0" data-language="tsx" data-theme="github-light-high-contrast github-dark-high-contrast"><code data-language="tsx" data-theme="github-light-high-contrast github-dark-high-contrast" style="display: grid;"><span data-line=""><span style="--shiki-light:#0E1116;--shiki-dark:#F0F3F6">onChange</span><span style="--shiki-light:#A0111F;--shiki-dark:#FF9492">=</span><span style="--shiki-light:#0E1116;--shiki-dark:#F0F3F6">{</span></span>
<span data-line=""><span style="--shiki-light:#0E1116;--shiki-dark:#F0F3F6">(e)=>{</span></span>
<span data-line=""><span style="--shiki-light:#0E1116;--shiki-dark:#F0F3F6">  console.</span><span style="--shiki-light:#622CBC;--shiki-dark:#DBB7FF">log</span><span style="--shiki-light:#0E1116;--shiki-dark:#F0F3F6">(e.type);</span></span>
<span data-line=""><span style="--shiki-light:#0E1116;--shiki-dark:#F0F3F6">  console.</span><span style="--shiki-light:#622CBC;--shiki-dark:#DBB7FF">log</span><span style="--shiki-light:#0E1116;--shiki-dark:#F0F3F6">(e.target.value);</span></span>
<span data-line=""><span style="--shiki-light:#622CBC;--shiki-dark:#DBB7FF">  setTimeout</span><span style="--shiki-light:#0E1116;--shiki-dark:#F0F3F6">(()</span><span style="--shiki-light:#A0111F;--shiki-dark:#FF9492">=></span><span style="--shiki-light:#0E1116;--shiki-dark:#F0F3F6">{</span></span>
<span data-line=""><span style="--shiki-light:#0E1116;--shiki-dark:#F0F3F6">    console.</span><span style="--shiki-light:#622CBC;--shiki-dark:#DBB7FF">warn</span><span style="--shiki-light:#0E1116;--shiki-dark:#F0F3F6">(e.type); </span><span style="--shiki-light:#66707B;--shiki-dark:#BDC4CC">// 초기화로 인한 null</span></span>
<span data-line=""><span style="--shiki-light:#0E1116;--shiki-dark:#F0F3F6">   })</span></span>
<span data-line=""><span style="--shiki-light:#0E1116;--shiki-dark:#F0F3F6"> }</span></span>
<span data-line=""><span style="--shiki-light:#0E1116;--shiki-dark:#F0F3F6">}</span></span></code></pre></figure>
To resolve this issue, using React's persist to remove the event from the event pool and fall back to the traditional event approach works without any problems, but you give up the performance benefit.</li>
</ul>
<p>Starting from v17, React decided to no longer support the behavior that compensated for performance issues in legacy browsers.</p>
<p>However, the event.persist() method still exists, though calling it does nothing (kept for backward compatibility).</p>
<h3 id="changes-to-event-delegation"><strong>Changes to event delegation</strong><a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#changes-to-event-delegation"><span class="icon icon-link"></span></a></h3>
<p>First, let's look at the code that attaches an event handler in React.</p>
<figure data-rehype-pretty-code-figure=""><pre tabindex="0" data-language="jsx" data-theme="github-light-high-contrast github-dark-high-contrast"><code data-language="jsx" data-theme="github-light-high-contrast github-dark-high-contrast" style="display: grid;"><span data-line=""><span style="--shiki-light:#0E1116;--shiki-dark:#F0F3F6">&#x3C;</span><span style="--shiki-light:#024C1A;--shiki-dark:#72F088">button</span><span style="--shiki-light:#023B95;--shiki-dark:#91CBFF"> onClick</span><span style="--shiki-light:#A0111F;--shiki-dark:#FF9492">={</span><span style="--shiki-light:#0E1116;--shiki-dark:#F0F3F6">handleClick</span><span style="--shiki-light:#A0111F;--shiki-dark:#FF9492">}</span><span style="--shiki-light:#0E1116;--shiki-dark:#F0F3F6">></span></span></code></pre></figure>
<p>In vanilla DOM, it would work like this.</p>
<figure data-rehype-pretty-code-figure=""><pre tabindex="0" data-language="jsx" data-theme="github-light-high-contrast github-dark-high-contrast"><code data-language="jsx" data-theme="github-light-high-contrast github-dark-high-contrast" style="display: grid;"><span data-line=""><span style="--shiki-light:#0E1116;--shiki-dark:#F0F3F6">myButton.</span><span style="--shiki-light:#622CBC;--shiki-dark:#DBB7FF">addEventListener</span><span style="--shiki-light:#0E1116;--shiki-dark:#F0F3F6">(</span><span style="--shiki-light:#032563;--shiki-dark:#ADDCFF">'click'</span><span style="--shiki-light:#0E1116;--shiki-dark:#F0F3F6">, handleClick);</span></span></code></pre></figure>
<p>In React, event handlers are not attached to the actual declared DOM element but added to the document node.</p>
<p>This is called event delegation.</p>
<figure data-rehype-pretty-code-figure=""><pre tabindex="0" data-language="jsx" data-theme="github-light-high-contrast github-dark-high-contrast"><code data-language="jsx" data-theme="github-light-high-contrast github-dark-high-contrast" style="display: grid;"><span data-line=""><span style="--shiki-light:#0E1116;--shiki-dark:#F0F3F6">document.</span><span style="--shiki-light:#622CBC;--shiki-dark:#DBB7FF">addEventListener</span><span style="--shiki-light:#0E1116;--shiki-dark:#F0F3F6">(</span><span style="--shiki-light:#032563;--shiki-dark:#ADDCFF">'click'</span><span style="--shiki-light:#0E1116;--shiki-dark:#F0F3F6">, (</span><span style="--shiki-light:#702C00;--shiki-dark:#FFB757">e</span><span style="--shiki-light:#0E1116;--shiki-dark:#F0F3F6">) </span><span style="--shiki-light:#A0111F;--shiki-dark:#FF9492">=></span><span style="--shiki-light:#0E1116;--shiki-dark:#F0F3F6"> { </span><span style="--shiki-light:#66707B;--shiki-dark:#BDC4CC">// 실행된 컴포넌트 찾게 됨 });</span></span></code></pre></figure>
<p>React's event delegation approach</p>
<ul>
<li>An event occurs on the document</li>
<li>The React event system finds the component where the event actually occurred</li>
<li>The event is propagated to parent components through event bubbling</li>
</ul>

<ul>
<li><strong>Starting from React 17, events are delegated to the React Tree Root instead of the document.</strong></li>
</ul>
<p><img src="/blog-assets/2022/02/images/13/Untitled.png" alt="Untitled"></p>
<p>Even when multiple React components run, because events are handled at the base Root Element, the structure and event handling can operate independently.</p>
<p>This makes it easier to use React alongside other technologies. If jQuery exists on the outside and React exists on the inside, you can now stop event propagation down to the jQuery layer as expected.</p>
<p>However, there may be code that manually attaches an event using <strong><code>document.addEventListener</code></strong> on the DOM to detect all React events. This kind of code was possible in React 16, but starting from React 17 the propagation is blocked, so you cannot tell whether events are firing at the <strong><code>document</code></strong> level. This means you need to switch to the capture approach.</p>
