<h2 id="new-features">New Features<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#new-features"><span class="icon icon-link"></span></a></h2>
<h3 id="the-idle-state-has-been-removed">The idle state has been removed<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#the-idle-state-has-been-removed"><span class="icon icon-link"></span></a></h3>
<ul>
<li>
<p>A new fetchStatus was introduced to improve offline support</p>
</li>
<li>
<p>The idle state became unnecessary because of <code>fetchStatus: 'idle'</code>, which better captures the same state</p>
<ul>
<li>
<p><strong><code>status</code></strong>: represents information about <code>data</code>, the query's result value</p>
<ul>
<li>loading: there is no data yet</li>
<li>error: there is no data and an error occurred</li>
<li>success: data is available</li>
</ul>
</li>
<li>
<p><strong><code>fetchStatus</code></strong>: represents information about the <code>queryFn</code></p>
<ul>
<li>idle: the query is not doing anything</li>
<li>paused: the query attempted to fetch but was paused. Related to network mode</li>
<li>fetching: the query is fetching</li>
</ul>
</li>
<li>
<p>In v3, during a background refetch you could not tell the fetching state from isLoading, so isFetching was used</p>
<ul>
<li>In addition to isFetching, you can use fetchStatus.fetching</li>
<li>The point is that status could not properly represent the query's state.</li>
<li>The initial state value for a disabled query (an unused query) was changed to isLoading</li>
<li>isLoading → isInitialLoading</li>
<li>If you request (isFetching) a query that has no cached data (isLoading), then isInitialLoading === true</li>
</ul>
</li>
</ul>
</li>
</ul>

<h3 id="queries-and-mutations-per-default-need-network-connection-to-run">Queries and mutations, per default, need network connection to run<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#queries-and-mutations-per-default-need-network-connection-to-run"><span class="icon icon-link"></span></a></h3>
<ul>
<li>A networkMode option was added, providing an explicit offline mode for queries and mutations</li>
</ul>
<figure data-rehype-pretty-code-figure=""><pre tabindex="0" data-language="tsx" data-theme="github-light-high-contrast github-dark-high-contrast"><code data-language="tsx" data-theme="github-light-high-contrast github-dark-high-contrast" style="display: grid;"><span data-line=""><span style="--shiki-light:#A0111F;--shiki-dark:#FF9492">new</span><span style="--shiki-light:#622CBC;--shiki-dark:#DBB7FF"> QueryClient</span><span style="--shiki-light:#0E1116;--shiki-dark:#F0F3F6">({</span></span>

<span data-line=""><span style="--shiki-light:#0E1116;--shiki-dark:#F0F3F6">    },</span></span>
<span data-line=""><span style="--shiki-light:#0E1116;--shiki-dark:#F0F3F6">  },</span></span>
<span data-line=""><span style="--shiki-light:#0E1116;--shiki-dark:#F0F3F6">});</span></span></code></pre></figure>
<ul>
<li>
<p>networkMode has three possible values.</p>
<ul>
<li><strong><code>online</code></strong>: While offline, it does not fetch until a network connection is available, and in this state the query is marked as <code>fetchStatus:paused</code>.</li>
<li><strong><code>always</code></strong>: It attempts to fetch even while offline, just like when online. Since the request is sent while offline, it will end up in the <code>status:error</code> state.</li>
<li><strong><code>offlineFirst</code></strong>: Behaves the same as in v3. It stops retrying after the first call to queryFn.</li>
</ul>
</li>
</ul>
<h3 id="tracked-query-per-default-performance-improvement">Tracked Query per default (performance improvement)<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#tracked-query-per-default-performance-improvement"><span class="icon icon-link"></span></a></h3>
<ul>
<li>
<p><a href="https://github.com/TanStack/query/discussions/1554">Tracked Query</a>: an optimization that triggers re-renders only when the values actually accessed among useQuery's return values change</p>
</li>
<li>

</li>
</ul>

<h2 id="change-features">Change Features<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#change-features"><span class="icon icon-link"></span></a></h2>
<h3 id="new-api-for-usequeries">new API for useQueries<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#new-api-for-usequeries"><span class="icon icon-link"></span></a></h3>
<ul>
<li>A change in how multiple queries are passed to useQueries</li>
</ul>

<h3 id="query-keys-and-mutation-keys-need-to-be-an-array-query-keys-can-only-be-arrays">Query Keys (and Mutation Keys) need to be an Array (query keys can only be arrays)<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#query-keys-and-mutation-keys-need-to-be-an-array-query-keys-can-only-be-arrays"><span class="icon icon-link"></span></a></h3>
<ul>
<li>
<p>Query keys (or Mutation Keys) were changed to arrays</p>
</li>
<li>
<p>In v3, a key could be either a String or an Array. But in v4, only the Array form is allowed</p>
</li>
</ul>

<span data-line=""> </span>
<span data-line=""><span style="--shiki-light:#66707B;--shiki-dark:#BDC4CC">// v4</span></span>
<span data-line=""><span style="--shiki-light:#622CBC;--shiki-dark:#DBB7FF">useQuery</span><span style="--shiki-light:#0E1116;--shiki-dark:#F0F3F6">([</span><span style="--shiki-light:#032563;--shiki-dark:#ADDCFF">'todos'</span><span style="--shiki-light:#0E1116;--shiki-dark:#F0F3F6">], fetchTodos);</span></span></code></pre></figure>
<h3 id="onsuccess-is-no-loger-called-from-setquerydata">onSuccess is no loger called from setQueryData<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#onsuccess-is-no-loger-called-from-setquerydata"><span class="icon icon-link"></span></a></h3>
<ul>
<li>
<p>The onSuccess callback is no longer called when setQueryData is invoked.</p>
</li>
<li>
<p>The onSuccess callback is only called after an actual request has occurred.</p>
</li>
<li>
<p>If you want to actually subscribe to changes in data, it is recommended to use useEffect instead of onSuccess</p>
</li>
</ul>

<h3 id="the-cancel-method-on-promises-is-no-longer-supported">The cancel method on promises is no longer supported<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#the-cancel-method-on-promises-is-no-longer-supported"><span class="icon icon-link"></span></a></h3>
<ul>
<li>
<p>The cancel method that was used to support query cancellation is no longer available</p>
</li>
<li>
<p>Instead, for query cancellation, it is recommended to use the <a href="https://tanstack.com/query/v4/docs/react/guides/query-cancellation">newer API</a> (introduced in v3.30.0), which internally uses the <a href="https://developer.mozilla.org/en-US/docs/Web/API/AbortController">AbortController API</a> and provides an <a href="https://developer.mozilla.org/en-US/docs/Web/API/AbortSignal">AbortSignal instance</a> to the query function to support query cancellation</p>
</li>
</ul>
