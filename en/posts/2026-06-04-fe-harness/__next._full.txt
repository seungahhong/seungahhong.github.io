22:T6034,<h2 id="1-what-is-harness-engineering">1. What Is Harness Engineering?<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#1-what-is-harness-engineering"><span class="icon icon-link"></span></a></h2>
<p>It is the discipline of designing the <strong>entire execution environment</strong> surrounding an AI model (tools, feedback loops, safeguards, approval gates) to turn it into <strong>reliable software</strong>.</p>
<h3 id="the-evolution-of-ai-engineering-prompt-vs-context-vs-harness">The Evolution of AI Engineering (Prompt vs. Context vs. Harness)<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#the-evolution-of-ai-engineering-prompt-vs-context-vs-harness"><span class="icon icon-link"></span></a></h3>
<p>The way we work with AI has evolved from prompt engineering to context engineering to harness engineering. The focus has expanded beyond simply "what to ask," to "what context to inject," and ultimately to "how to design the entire execution environment in which the AI operates."</p>
<h3 id="the-anthropic-case--the-generator-evaluator-pattern">The Anthropic Case — the Generator-Evaluator Pattern<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#the-anthropic-case--the-generator-evaluator-pattern"><span class="icon icon-link"></span></a></h3>
<p>Anthropic applied a harness to long-running application development and published the results.</p>
<p><strong>Key findings</strong></p>
<ul>
<li>
<p><strong>The self-evaluation failure problem</strong></p>
<p>When a model is asked to evaluate its own output, it confidently praises mediocre results.</p>
<blockquote>
<p>"Separating the generator from the evaluator turned it into a far more tractable problem." — Anthropic</p>
</blockquote>
</li>
<li>
<p><strong>Context Window limits</strong></p>
<p>There is a fixed maximum number of characters (token capacity) that can be held in memory within a session. Sub-agents are spawned to keep the main context from being polluted.</p>
</li>
</ul>
<p><strong>Quantitative results</strong></p>






























<table><thead><tr><th>Item</th><th>Standalone Run</th><th>With Harness</th></tr></thead><tbody><tr><td>Time elapsed</td><td>20 min</td><td>6 hours</td></tr><tr><td>Cost</td><td>$9</td><td>$200</td></tr><tr><td>Core feature</td><td>Broken</td><td>Complete</td></tr><tr><td>Quality verdict</td><td>—</td><td>"The difference was immediately obvious"</td></tr></tbody></table>
<p>For a 22x increase in cost, whether the core feature actually worked was fundamentally different. The Evaluator provided <strong>concrete, immediately actionable feedback</strong>, such as broken API routes and missing DB wiring.</p>

<h3 id="design-principles">Design Principles<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#design-principles"><span class="icon icon-link"></span></a></h3>
<ol>
<li><strong>"One at a time"</strong>
<ul>
<li>grill-me asks only one question at a time to secure depth in the answers</li>
<li>Solves the shallow-answer problem caused by asking many questions at once</li>
</ul>
</li>
<li><strong>"Parallel, not sequential"</strong>
<ul>
<li>Independent skills/verification items are always processed concurrently in parallel</li>
<li>Each sub-agent operates with a clean context → no quality degradation</li>
</ul>
</li>
<li><strong>"Static analysis first, expensive E2E later"</strong>
<ul>
<li>Review (static) runs before Verify (E2E) → prevents unnecessary E2E costs</li>
</ul>
</li>
<li><strong>"AI executes, humans decide"</strong>
<ul>
<li>User approval is required for every Phase transition, skill selection, and fix decision</li>
<li>Clearly limits the scope of AI's autonomous execution</li>
</ul>
</li>
</ol>
<p><strong>In one line</strong>: An orchestrator for the entire development workflow that runs the five stages Research → PRD → Develop → Review → Verify in sequence and obtains user approval at each stage transition.</p>















































<table><thead><tr><th>Phase</th><th>Name</th><th>Core Action</th><th>Delegated to AI</th><th>User Approval</th></tr></thead><tbody><tr><td>1</td><td><strong>Research</strong></td><td>grill-me interview → requirements spec</td><td>One question at a time, codebase exploration</td><td>Confirm each step's result</td></tr><tr><td>2</td><td><strong>PRD</strong></td><td>planner→architecture→critic loop</td><td>3 sub-agents</td><td>Decide loop repeat/finalize</td></tr><tr><td>3</td><td><strong>Develop</strong></td><td>Skill selection → parallel code generation</td><td>Selected skills run concurrently</td><td>Skill selection, additional confirmation</td></tr><tr><td>4</td><td><strong>Review</strong></td><td>5-perspective parallel verification + re-review</td><td>5 Evaluators run concurrently</td><td>Item selection, fix decision</td></tr><tr><td>5</td><td><strong>Verify</strong></td><td>E2E browser + type/build</td><td>Scenario generation &#x26; execution</td><td>Tool selection, scenario approval</td></tr></tbody></table>
<p><strong>Early termination allowed</strong>: You can run only up to the desired stage, such as "just through analysis" or "just through development."</p>
<h3 id="phase-by-phase-details">Phase-by-Phase Details<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#phase-by-phase-details"><span class="icon icon-link"></span></a></h3>
<h4 id="phase-1-research">Phase 1: Research<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#phase-1-research"><span class="icon icon-link"></span></a></h4>
<figure data-rehype-pretty-code-figure=""><pre tabindex="0" data-language="markdown" data-theme="github-light-high-contrast github-dark-high-contrast"><code data-language="markdown" data-theme="github-light-high-contrast github-dark-high-contrast" style="display: grid;"><span data-line=""><span style="--shiki-light:#0E1116;--shiki-dark:#F0F3F6">초기 분석 → grill-me 인터뷰(1개씩) → 코드베이스 조사 → 명세 작성 → 확인</span></span>
<span data-line=""><span style="--shiki-light:#0E1116;--shiki-dark:#F0F3F6"> ↓ 승인      ↓ 응답 × N회           ↓ 승인          ↓ 승인    ↓ 승인</span></span></code></pre></figure>
<ul>
<li><strong>grill-me</strong>: Asks strictly one question at a time, detects contradictions with previous answers, and investigates directly when the codebase can answer the question</li>
<li><strong>Deliverable</strong>: A requirements specification at an actionable level</li>
</ul>
<h4 id="phase-2-prd">Phase 2: PRD<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#phase-2-prd"><span class="icon icon-link"></span></a></h4>
<figure data-rehype-pretty-code-figure=""><pre tabindex="0" data-language="markdown" data-theme="github-light-high-contrast github-dark-high-contrast"><code data-language="markdown" data-theme="github-light-high-contrast github-dark-high-contrast" style="display: grid;"><span data-line=""><span style="--shiki-light:#0E1116;--shiki-dark:#F0F3F6">┌→ planner(계획) → architecture(설계) → critic(비평) ─┐</span></span>
<span data-line=""><span style="--shiki-light:#0E1116;--shiki-dark:#F0F3F6">│              심각도 상 리스크 1+ → 루프 반복 (최대 3회) │</span></span>
<span data-line=""><span style="--shiki-light:#0E1116;--shiki-dark:#F0F3F6">└────────────────────────────────────────────────────────┘</span></span>
<span data-line=""><span style="--shiki-light:#0E1116;--shiki-dark:#F0F3F6">              심각도 상 0건 → PRD 확정</span></span></code></pre></figure>
<ul>
<li><strong>Critic's 7 perspectives</strong>: Scalability / Stability / Security / Performance / Compatibility / Operations / Omissions</li>
<li><strong>Deliverable</strong>: Implementation plan + technical architecture + risk matrix</li>
</ul>
<h4 id="phase-3-develop">Phase 3: Develop<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#phase-3-develop"><span class="icon icon-link"></span></a></h4>
<figure data-rehype-pretty-code-figure=""><pre tabindex="0" data-language="markdown" data-theme="github-light-high-contrast github-dark-high-contrast"><code data-language="markdown" data-theme="github-light-high-contrast github-dark-high-contrast" style="display: grid;"><span data-line=""><span style="--shiki-light:#0E1116;--shiki-dark:#F0F3F6">Step 1: 스킬 선택 (멀티체크)        Step 2: 추가 스킬 확인</span></span>
<span data-line=""><span style="--shiki-light:#0E1116;--shiki-dark:#F0F3F6">□ a11y (웹접근성)                    "추가로 적용할 스킬 있나요?"</span></span>
<span data-line=""><span style="--shiki-light:#0E1116;--shiki-dark:#F0F3F6">□ semantic-html                      → 명시적 응답 필수</span></span>
<span data-line=""><span style="--shiki-light:#0E1116;--shiki-dark:#F0F3F6">□ seo-geo (SEO/GEO)</span></span>
<span data-line=""><span style="--shiki-light:#0E1116;--shiki-dark:#F0F3F6">□ tdd (테스트 주도)</span></span>
<span data-line=""><span style="--shiki-light:#0E1116;--shiki-dark:#F0F3F6">           ↓</span></span>
<span data-line=""><span style="--shiki-light:#0E1116;--shiki-dark:#F0F3F6">    선택 스킬 전부 동시 병렬 실행</span></span></code></pre></figure>
<ul>
<li><strong>Integration priority</strong>: TDD > semantic-html > a11y > seo-geo</li>
</ul>
<h4 id="phase-4-review">Phase 4: Review<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#phase-4-review"><span class="icon icon-link"></span></a></h4>
<figure data-rehype-pretty-code-figure=""><pre tabindex="0" data-language="markdown" data-theme="github-light-high-contrast github-dark-high-contrast"><code data-language="markdown" data-theme="github-light-high-contrast github-dark-high-contrast" style="display: grid;"><span data-line=""><span style="--shiki-light:#0E1116;--shiki-dark:#F0F3F6">5개 관점 동시 실행:</span></span>
<span data-line=""><span style="--shiki-light:#0E1116;--shiki-dark:#F0F3F6">┌──────────┬──────────┬──────────┬───────────┬────────────┐</span></span>
<span data-line=""><span style="--shiki-light:#0E1116;--shiki-dark:#F0F3F6">│/simplify │ /review  │ security │lighthouse │qa-inspector│</span></span>
<span data-line=""><span style="--shiki-light:#0E1116;--shiki-dark:#F0F3F6">│ 코드간소    │ 품질리뷰   │ 보안감사   │ 성능측정    │ 경계면검증    │</span></span>
<span data-line=""><span style="--shiki-light:#0E1116;--shiki-dark:#F0F3F6">└──────────┴──────────┴──────────┴───────────┴────────────┘</span></span>
<span data-line=""><span style="--shiki-light:#0E1116;--shiki-dark:#F0F3F6">                    ↓ 결과 통합</span></span>
<span data-line=""><span style="--shiki-light:#0E1116;--shiki-dark:#F0F3F6">         수정 필요 → 재리뷰 루프 (최대 3회)</span></span>
<span data-line=""><span style="--shiki-light:#0E1116;--shiki-dark:#F0F3F6">         수정 없음 → 배포 가능 판정</span></span></code></pre></figure>
<ul>
<li><strong>Deployment criteria</strong>: /review Critical 0, security Critical/High 0, lighthouse ≥ 50</li>
</ul>
<h4 id="phase-5-verify">Phase 5: Verify<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#phase-5-verify"><span class="icon icon-link"></span></a></h4>

<span data-line=""><span style="--shiki-light:#0E1116;--shiki-dark:#F0F3F6">(전체/E2E/빌드)  (Chrome/Playwright  (PRD 인수조건    (PASS/WARNING</span></span>
<span data-line=""><span style="--shiki-light:#0E1116;--shiki-dark:#F0F3F6">                  /Agent-Browser)     → 브라우저 동작)  /FAIL)</span></span></code></pre></figure>
<ul>
<li><strong>E2E tool selection is mandatory for the user</strong> (no default, because environments differ)</li>
<li><strong>Type/build</strong>: npm run typecheck + npm run build</li>
</ul>

<h2 id="3-future-improvements">3. Future Improvements<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#3-future-improvements"><span class="icon icon-link"></span></a></h2>
<h3 id="building-harnesses-for-various-development-environments">Building Harnesses for Various Development Environments<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#building-harnesses-for-various-development-environments"><span class="icon icon-link"></span></a></h3>
<p>We are expanding the current FE-focused harness to a <strong>variety of environments</strong>.</p>
<figure data-rehype-pretty-code-figure=""><pre tabindex="0" data-language="markdown" data-theme="github-light-high-contrast github-dark-high-contrast"><code data-language="markdown" data-theme="github-light-high-contrast github-dark-high-contrast" style="display: grid;"><span data-line=""><span style="--shiki-light:#0E1116;--shiki-dark:#F0F3F6">┌─────────────────────────────────────────────────────┐</span></span>
<span data-line=""><span style="--shiki-light:#0E1116;--shiki-dark:#F0F3F6">│          Orchestrator (환경 무관 범용 엔진)             │</span></span>
<span data-line=""><span style="--shiki-light:#0E1116;--shiki-dark:#F0F3F6">│    Research → PRD → Develop(선택) → Review(선택) → Verify(선택)│</span></span>
<span data-line=""><span style="--shiki-light:#0E1116;--shiki-dark:#F0F3F6">├─────────────┬──────────────┬────────────────────────┤</span></span>
<span data-line=""><span style="--shiki-light:#0E1116;--shiki-dark:#F0F3F6">│  FE 스킬 팩   │ 문서 스킬 팩    │   PRD 생성 스킬          │</span></span>
<span data-line=""><span style="--shiki-light:#0E1116;--shiki-dark:#F0F3F6">│  a11y       │ 기술 보고서 작성  │   요구사항 정의          │</span></span>
<span data-line=""><span style="--shiki-light:#0E1116;--shiki-dark:#F0F3F6">│  semantic   │ Wiki 자동 업로드 │   아키텍처 설계          │</span></span>
<span data-line=""><span style="--shiki-light:#0E1116;--shiki-dark:#F0F3F6">│  lighthouse │ 발표 자료 생성    │   리스크 분석           │</span></span>
<span data-line=""><span style="--shiki-light:#0E1116;--shiki-dark:#F0F3F6">└─────────────┴──────────────┴────────────────────────┘</span></span></code></pre></figure>
<p><strong>Key point</strong>: The Orchestrator's 5-stage flow is environment-agnostic. You only need to <strong>swap out the skills</strong>.</p>
<h3 id="building-toward-agent-engineering">Building Toward Agent Engineering<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#building-toward-agent-engineering"><span class="icon icon-link"></span></a></h3>
<p>The evolution from harness to agent engineering:</p>
<figure data-rehype-pretty-code-figure=""><pre tabindex="0" data-language="markdown" data-theme="github-light-high-contrast github-dark-high-contrast"><code data-language="markdown" data-theme="github-light-high-contrast github-dark-high-contrast" style="display: grid;"><span data-line=""><span style="--shiki-light:#0E1116;--shiki-dark:#F0F3F6">현재                              미래</span></span>
<span data-line=""><span style="--shiki-light:#0E1116;--shiki-dark:#F0F3F6">──────                            ──────</span></span>
<span data-line=""><span style="--shiki-light:#0E1116;--shiki-dark:#F0F3F6">인간이 하네스를 설계         →    AI가 하네스를 자기 개선</span></span>
<span data-line=""><span style="--shiki-light:#0E1116;--shiki-dark:#F0F3F6">AI가 실행, 인간이 승인       →    인간은 목표와 경계만 설정</span></span>
<span data-line=""><span style="--shiki-light:#0E1116;--shiki-dark:#F0F3F6">스킬이 정적 (SKILL.md 고정)  →    스킬 자동 튜닝 (A/B 테스트)</span></span>
<span data-line=""><span style="--shiki-light:#0E1116;--shiki-dark:#F0F3F6">실패 패턴을 인간이 분석      →    메트릭 기반 자동 진단</span></span></code></pre></figure>






























<table><thead><tr><th>Stage</th><th>Description</th><th>Human's Role</th></tr></thead><tbody><tr><td><strong>Stage 1</strong> Static harness (current)</td><td>Human designs, AI executes</td><td>Design + approval</td></tr><tr><td><strong>Stage 2</strong> Self-diagnosis</td><td>Metric collection → improvement proposals</td><td>Approve proposals</td></tr><tr><td><strong>Stage 3</strong> Self-improvement</td><td>Automatic skill tuning, A/B testing</td><td>Set policy</td></tr><tr><td><strong>Stage 4</strong> Autonomous agent</td><td>Automatically reconfigures the workflow</td><td>Set goals only</td></tr></tbody></table>
<p><strong>Ultimate goal</strong>: A development environment where developers focus <strong>solely on "what to build,"</strong> while the AI system autonomously guarantees quality, safety, and consistency.</p>
