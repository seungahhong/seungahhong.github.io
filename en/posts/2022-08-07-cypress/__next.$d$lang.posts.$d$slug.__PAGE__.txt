f:T2a673,<h2 id="what-is-e2e-testing">What is E2E Testing?<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#what-is-e2e-testing"><span class="icon icon-link"></span></a></h2>
<ul>
<li>E2E testing is a way to test the final product from the user's perspective. It refers to <strong>End-to-End Testing that verifies, from the user's point of view</strong>, whether the desired text is displayed correctly on a page and whether the correct behavior occurs when a button is clicked.</li>
</ul>
<h2 id="e2e-testing-considerations">E2E Testing Considerations<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#e2e-testing-considerations"><span class="icon icon-link"></span></a></h2>
<ul>
<li>It tests between <strong>Endpoints</strong>, running tests under the assumption of <strong>situations in which a real user uses the product</strong> (writing scenarios from the user's perspective).</li>
<li>In general, it <strong>performs scenario and functional testing through the GUI</strong> on the web or in apps.</li>
<li>It <strong>inspects the parts that are directly exposed to users</strong>.</li>
<li>It can even cover <strong>user-perspective testing</strong> that is impossible with unit tests.</li>
<li>Passing the endpoint tests means the feature works well, so if you can't run every kind of test, <strong>it's a good idea to at least run E2E Tests!</strong></li>
</ul>

  <summary>CLASS101 Cypress Adoption Case</summary>
  As the CLASS101 service grew day by day, the codebase grew along with it, and the probability of bugs increased accordingly.
  **When the service was small, the existing QA process—such as having someone manually test the UI—was sufficient**, but by now **the scope and time required had grown significantly, so a more systematic and new process was needed**.
  There are many software testing approaches, such as unit testing and integration testing, but they decided to **build E2E tests that run in an environment as close as possible to the user's**.

  Cypress is a web-based End-to-End JavaScript testing framework. It does not depend on Selenium, and it is a tool that lets you write and operate assertions more concisely by directly leveraging [Mocha](https://mochajs.org/), [Chai](https://www.chaijs.com/), and so on,

<ul>
<li>Through automated testing, you can find issues (bugs) before deployment, which allows you to <strong>improve the user experience</strong>.</li>
