What is E2E Testing?

  • E2E testing is a way to test the final product from the user's perspective. It refers to End-to-End Testing that verifies, from the user's point of view, whether the desired text is displayed correctly on a page and whether the correct behavior occurs when a button is clicked.

E2E Testing Considerations

  • It tests between Endpoints, running tests under the assumption of situations in which a real user uses the product (writing scenarios from the user's perspective).
  • In general, it performs scenario and functional testing through the GUI on the web or in apps.
  • It inspects the parts that are directly exposed to users.
  • It can even cover user-perspective testing that is impossible with unit tests.
  • Passing the endpoint tests means the feature works well, so if you can't run every kind of test, it's a good idea to at least run E2E Tests!

Key Cypress Commands

  • as Assigns an alias for later use. You can use as on top of commands like cy.get() and cy.wait(), and to use the alias you prefix it with @.

  • get A function used to get DOM elements (one or more).

  • should, and Used the same way as assertion or equal in a typical test framework.

  • visit A function used to visit a remote url.

  • fixture A function used to load a fixture that defines the data to be used in a test.

  • click A function that must be called when clicking a DOM element.

  • type A function that must be called when typing on the keyboard into a DOM element.

  • contains Gets the DOM element that contains the text.

  • eq Called to get the element at a specific index in an array of elements.

  • filter Called to get the elements that match a specific selector.

  • find Called when finding a child element by a specific selector.

  • focus When giving focus to a DOM element.

  • clear Used to delete the data of an input or textarea element.

  • focused Called to get the element currently in focus.

  • go Called when navigating forward/backward in the browser history.

  • each Called to iterate over an array or object that has a length property. Similar to JavaScript's map behavior.

  • intercept Provides spying that calls the actual api, stubbing that returns a response with pre-built data, and modification that lets you alter the request or response.

  • blur Blurs the focused element.

  • check Used when the input element type is a checkbox or radio.

Other Cypress Commands

  • children Used to get the child elements of each DOM element (same behavior as jQuery .children()).

  • closet Called to find the closest ancestor of an element (same as jQuery's closest feature).

  • dblclick Calls a DOM double-click.

  • debug Sets a debugger and logs the result of the previous command. However, to reach the debugger breakpoint, the developer tools must be open.

  • document Called to get the window.document of the currently active page.

  • end Used to break the chain of a previous command.

  • exec Runs a system command.

  • first Called to get the first element among the selected elements.

  • hash Called to get the url hash value of the current page.

Other APIs: https://docs.cypress.io/api/commands/and

Expected Results

  • Through automated testing, you can find issues (bugs) before deployment, which allows you to improve the user experience.
  • Through basic user end-to-end testing, you can pursue stabilization of the service.
  • You can raise the reliability of the development code and improve code quality.
  • When adding a new feature, testing the existing features together makes it possible to test for potential issues.
  • In the long run, you can save time and cost.
