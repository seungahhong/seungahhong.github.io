<h3 id="changes">Changes<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#changes"><span class="icon icon-link"></span></a></h3>
<ul>
<li>
<p>Introduction of the Environment API</p>
<ul>
<li>A new API designed to provide a development experience closer to production</li>
<li>Enhanced flexibility for framework and plugin authors</li>
<li>Guide: <a href="https://green.sapphi.red/blog/increasing-vites-potential-with-the-environment-api">Introducing the Environment API</a></li>
<li><img src="/blog-assets/2025/06/assets/29/image1.png" alt="env"></li>
<li>≤ v5</li>
<li><img src="/blog-assets/2025/06/assets/29/image2.png" alt="env2"></li>
<li>v6 ≥</li>
</ul>
</li>
<li>
<p>Node.js support updates</p>
<ul>
<li>Support for Node.js 18, 20, and 22; support for 21 has ended</li>
<li>A new major release is planned for after Node.js 18 reaches EOL</li>
<li><img src="/blog-assets/2025/06/assets/29/image3.png" alt="node"></li>
<li><img src="/blog-assets/2025/06/assets/29/image4.png" alt="node2"></li>
</ul>
</li>
<li>
<p>New features and changes</p>
<ul>
<li>Template expansion: templates such as Solid, Deno, and SSR are supported via pnpm create vite-extra.</li>
<li>Sass and PostCSS:
<ul>
<li>The default Sass compilation mode changes from legacy → modern (dart-sass support)</li>
<li>In vite 7.0, the compilation mode that uses node-sass (legacy) is scheduled for removal</li>
<li>Modern API: the latest approach officially recommended by Sass (compileAsync, compile)</li>
<li>Legacy API: the older approach (render, renderSync) — an API compatible with the deprecated node-sass</li>
</ul>
</li>
<li>Custom output file names for CSS libraries</li>
<li>Expanded support for asset references in HTML elements</li>
<li>Adjustment of the default array for resolve.conditions</li>
<li>JSON stringify</li>
</ul>
</li>
<li>
<p>Sass modern API used by default</p>
<ul>
<li>The default Sass compilation mode changes from legacy → modern (dart-sass support)</li>
<li>In vite 7.0, the compilation mode that uses node-sass (legacy) is scheduled for removal</li>
<li>Modern API: the latest approach officially recommended by Sass (compileAsync, compile)</li>
<li>Legacy API: the older approach (render, renderSync) — an API compatible with the deprecated node-sass</li>
</ul>
</li>
<li>
<p>Expanded targets for asset references in HTML elements</p>
<ul>
<li>Supported in vite 5.0</li>
</ul>
</li>
</ul>

<li>
<p>Change to the default value of resolve.conditions</p>
<ul>
<li>An array value that specifies which conditions to prioritize when resolving the conditional entries defined in the "exports" or "imports" fields of package.json while importing modules</li>
<li>Before the change (Vite 5):
<ul>
<li>resolve.conditions: [] (some conditions were added internally)</li>
<li>ssr.resolve.conditions: uses the value of resolve.conditions</li>
</ul>
</li>
<li>After the change (Vite 6):
<ul>
<li>resolve.conditions: ['module', 'browser', 'development|production']</li>
<li>ssr.resolve.conditions: ['module', 'node', 'development|production']</li>
</ul>
</li>
</ul>
</li>
</ul>
<h3 id="vite-v50--v60-migration">vite v5.0 → v6.0 Migration<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#vite-v50--v60-migration"><span class="icon icon-link"></span></a></h3>
<p>Trouble Shooting</p>
<ul>
<li>
<p>Error [ERR_REQUIRE_ESM]: require() of ES Module</p>
<ul>
<li>If your vite.config.ts configuration file uses import/export instead of require, add the type="module" property to package.json.</li>
</ul>

<ul>
<li>When upgrading to vite 6 and updating storybook from 7 → 8, the transition from CommonJS → ESM makes the __dirname used in CommonJS unavailable.</li>
<li>If you need to use it, you can still obtain the current file path via fileURLToPath.</li>
