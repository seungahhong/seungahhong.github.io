22:T174c4,<h2 id="0-background">0. Background<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#0-background"><span class="icon icon-link"></span></a></h2>
<p>Certain pieces of business logic (payments, authentication, campaigns, and so on) are implemented across multiple repositories spanning frontend and backend services, which creates an inefficiency: to find the relevant code, you have to search each repository individually.</p>
<p>Conventional GitHub search works purely on keywords, so meaning-based queries such as "payment processing logic" or "campaign creation flow" are not possible. In addition, when using Claude AI for code analysis, the AI cannot access the internal codebase directly, so providing context requires manual work.</p>
<p>To solve these problems, we built a RAG system that indexes code across multiple repositories in a unified way and provides semantic search along with Claude AI integration.</p>
<hr>
<h2 id="1-overview">1. Overview<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#1-overview"><span class="icon icon-link"></span></a></h2>
<p><strong>code-retrieval</strong> is a RAG (Retrieval-Augmented Generation) system that provides <strong>hybrid semantic + keyword search</strong> over code from multiple internal GitHub repositories.</p>
<p>Developers can use natural-language queries to find related code scattered across several repositories all at once, and it integrates directly with Claude AI to support code understanding and analysis tasks.</p>
<p>It offers two access paths.</p>
<ul>
<li><strong>REST API</strong> (FastAPI): for web UIs and external service integrations</li>
<li><strong>MCP server</strong> (FastMCP): for direct code search from Claude Desktop / Claude Code</li>
</ul>
<hr>
<h2 id="2-goals">2. Goals<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#2-goals"><span class="icon icon-link"></span></a></h2>
<p><strong>Core goals</strong></p>
<ul>
<li>Unify code across multiple repositories into a single search engine to reduce the time developers spend exploring code</li>
<li>Enable semantic code search through natural-language queries such as "payment processing function" or "campaign creation API"</li>
<li>Allow Claude AI to access the internal codebase directly to perform code analysis, review, and Q&#x26;A</li>
</ul>
<p><strong>Technical goals</strong></p>
<ul>
<li>Provide meaningful search results at the function and class level through AST-based structural code chunking</li>
<li>Maximize search quality with hybrid Dense (semantic) + Sparse (keyword) search plus reranking</li>
<li>Update efficiently with git diff-based incremental sync, avoiding full reindexing when code changes</li>
</ul>

<h3 id="62-indexing-flow">6.2 Indexing flow<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#62-indexing-flow"><span class="icon icon-link"></span></a></h3>
<ol>
<li><strong>Repo registration</strong>: register a GitHub URL or local path via the CLI, and store metadata in data/registry.json</li>
<li><strong>Code collection</strong>: git clone (or reference an existing local repo)</li>
<li><strong>File filtering</strong>: determine indexing targets based on file extension (.py, .ts, .kt, etc.), excluding node_modules/, .git/, and so on</li>
<li><strong>AST chunking</strong>: split into function/class/module units — using the ast module for Python and Tree-sitter for JS/TS/Java/Kotlin/Go/Rust</li>
<li><strong>Embedding generation</strong>: generate Dense (1024d) + Sparse (BM25) vectors simultaneously with FastEmbed</li>
<li><strong>Qdrant storage</strong>: safely upsert using the Insert-then-Delete pattern</li>
</ol>
<h3 id="63-search-flow">6.3 Search flow<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#63-search-flow"><span class="icon icon-link"></span></a></h3>
<ol>
<li><strong>Query preprocessing</strong>: Unicode NFC normalization → automatic extraction of camelCase/snake_case code keywords</li>
<li><strong>Embedding generation</strong>: convert the query into Dense + Sparse vectors</li>
<li><strong>Hybrid search</strong>: perform Dense search and Sparse search separately in Qdrant (prefetch_limit=100)</li>
<li><strong>RRF fusion</strong>: merge the two result sets into one with Reciprocal Rank Fusion</li>
<li><strong>Reranking</strong>: re-rank the top candidates with the BGE-Reranker-v2-M3 cross-encoder</li>
<li><strong>Result return</strong>: return top_k code chunks ordered by relevance (including GitHub links)</li>
</ol>
<h3 id="64-incremental-sync-flow">6.4 Incremental sync flow<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#64-incremental-sync-flow"><span class="icon icon-link"></span></a></h3>
<ol>
<li>git fetch → git reset --hard origin/branch</li>
<li>detect changed/deleted files with git diff --name-only old_sha..new_sha</li>
<li>deleted files: remove that file's chunks from Qdrant</li>
<li>re-chunk only the changed files → re-embed → Qdrant sync_file (insert-then-delete)</li>
</ol>

<h2 id="7-key-features">7. Key Features<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#7-key-features"><span class="icon icon-link"></span></a></h2>
<h3 id="71-ast-based-structural-code-chunking">7.1 AST-based structural code chunking<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#71-ast-based-structural-code-chunking"><span class="icon icon-link"></span></a></h3>
<p>Rather than plain text splitting, the system analyzes the syntactic structure (AST) of the code and splits it into meaningful units.</p>













































<table><thead><tr><th>Language</th><th>Parser</th><th>Chunking unit</th></tr></thead><tbody><tr><td>Python</td><td>ast module</td><td>Functions, classes, module-level code</td></tr><tr><td>JS/TS</td><td>Tree-sitter</td><td>Functions, classes, interfaces, arrow functions</td></tr><tr><td>Java</td><td>Tree-sitter</td><td>Methods, classes, interfaces</td></tr><tr><td>Kotlin</td><td>Tree-sitter</td><td>Functions, classes, object declarations</td></tr><tr><td>Go</td><td>Tree-sitter</td><td>Functions, methods, type declarations</td></tr><tr><td>Rust</td><td>Tree-sitter</td><td>Functions, impl, struct, trait, enum</td></tr><tr><td>Others (YAML, JSON, etc.)</td><td>Fixed size</td><td>~512-token units with 50-token overlap</td></tr></tbody></table>
<p><strong>Handling large classes</strong>: classes exceeding 100 lines are split into individual per-method chunks plus a class-header chunk</p>
<h3 id="72-hybrid-search-dense--sparse--rrf">7.2 Hybrid search (Dense + Sparse + RRF)<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#72-hybrid-search-dense--sparse--rrf"><span class="icon icon-link"></span></a></h3>
<ul>
<li><strong>Dense search</strong>: semantic similarity search with multilingual-e5-large (supports both Korean and English)</li>
<li><strong>Sparse search</strong>: exact keyword matching with BM25 (strong on code identifiers such as function and variable names)</li>
<li><strong>RRF fusion</strong>: combines the two result sets with Reciprocal Rank Fusion so they complement each other</li>
</ul>
<h3 id="73-bge-reranker-reranking">7.3 BGE-Reranker reranking<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#73-bge-reranker-reranking"><span class="icon icon-link"></span></a></h3>
<p>The first-stage search results (top_k x 3 candidates) are precisely re-ranked with a cross-encoder model.</p>
<ul>
<li><strong>FP16 inference</strong>: reduces memory use and improves speed</li>
<li><strong>Batch processing</strong>: batch scoring in groups of 32</li>
<li><strong>Metadata boost</strong> (optional): adds bonus points when function name, file path, or language match</li>
</ul>
<h3 id="74-mcp-tools-claude-integration">7.4 MCP tools (Claude integration)<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#74-mcp-tools-claude-integration"><span class="icon icon-link"></span></a></h3>
<p>Provides four tools that can be called directly from Claude Desktop / Claude Code.</p>






























<table><thead><tr><th>Tool</th><th>Function</th><th>Example</th></tr></thead><tbody><tr><td>code_search</td><td>Search code across multiple repos with a natural-language query</td><td>"payment processing function" → returns related code</td></tr><tr><td>find_function</td><td>Look up the exact definition location by function name</td><td>"payment" → function code + location</td></tr><tr><td>get_file_context</td><td>Retrieve all chunks of a specific file</td><td>"src/auth/login.ts" → all functions in the file</td></tr><tr><td>list_repos</td><td>List and show statistics for indexed repos</td><td>Per-repo status, chunk count, last sync time</td></tr></tbody></table>

<p><strong>Graceful fallback design</strong></p>
<ul>
<li>If the Ollama server is down or the model is missing: log a WARNING and continue operating normally with only the heuristic prefix</li>
<li>Failure to summarize an individual chunk: skip just that chunk and continue processing the rest</li>
<li>Timeout (over 30 seconds): skip that chunk</li>
</ul>

<h4 id="754-optional-feature-combination-matrix">7.5.4 Optional feature combination matrix<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#754-optional-feature-combination-matrix"><span class="icon icon-link"></span></a></h4>
<p>The three features can be used independently or in combination. Below is a summary of the possible combinations and their effects.</p>















































<table><thead><tr><th>Contextual Chunking</th><th>Ollama enrichment</th><th>Metadata boost</th><th>Effect</th></tr></thead><tbody><tr><td>OFF</td><td>OFF</td><td>OFF</td><td>Default mode. Search on code text only. Fastest and lightest</td></tr><tr><td>ON</td><td>OFF</td><td>OFF</td><td>Heuristic context (file path, imports, docstring, callers) is reflected in the embedding, improving search accuracy</td></tr><tr><td>ON</td><td>ON</td><td>OFF</td><td>Heuristic + LLM summary maximizes semantic embedding quality. <ul>
<li><strong>Quick start</strong>: all OFF (default) — use immediately with no environment setup</li>

<figure data-rehype-pretty-code-figure=""><pre tabindex="0" data-language="shell" data-theme="github-light-high-contrast github-dark-high-contrast"><code data-language="shell" data-theme="github-light-high-contrast github-dark-high-contrast" style="display: grid;"><span data-line=""><span style="--shiki-light:#66707B;--shiki-dark:#BDC4CC"># Run the server → http://localhost:8000 (interactive docs: /docs)</span></span>

<p>Main endpoints:</p>



































<table><thead><tr><th>Method / Path</th><th>Description</th><th>Key request body (JSON) fields</th></tr></thead><tbody><tr><td>POST <code>/api/search</code></td><td>Natural-language code search</td><td>query (required), top_k, repo, language</td></tr><tr><td>GET <code>/api/repos</code></td><td>List of registered repos</td><td>—</td></tr><tr><td>GET <code>/api/repos/{repo}/stats</code></td><td>Per-repo chunk/vector statistics</td><td>—</td></tr><tr><td>POST <code>/api/repos</code></td><td>Register a repo (background indexing)</td><td>url or local_path, branch, description</td></tr><tr><td>POST <code>/api/repos/{repo}/sync</code></td><td>Incremental sync of a repo</td><td>—</td></tr></tbody></table>
<p>The search response contains <code>results[]</code> (including code, file path, line, and github_url), <code>total_found</code>, <code>query_time_ms</code>, and <code>repos_searched</code>. You can review the request/response schema and try it directly at <code>/docs</code> (Swagger UI).</p>
