1b:Tbb81,<h2 id="vitest-50-performance-trace-view-and-the-migration-guide">Vitest 5.0: Performance, Trace View, and the Migration Guide<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#vitest-50-performance-trace-view-and-the-migration-guide"><span class="icon icon-link"></span></a></h2>
<p><strong>Vitest 5.0</strong> shipped on September 3, 2026 (first tag: <code>5.0.1</code>). Unlike Vite 8, this major isn't an engine swap — it's a cleanup that <strong>moves defaults toward the safer side and consolidates scattered artifacts and options into one place.</strong></p>
<p>Which splits how you feel it:</p>
<ul>
<li><strong>The new features are easy to see</strong> — Trace View, <code>vi.when</code>, nested projects</li>
<li><strong>The breakage is not</strong> — the <code>clearMocks</code> default, unawaited async assertions, the <code>-t</code> separator, artifact paths</li>
</ul>
<p>This post leans on the latter. Release notes tell you what got better; what you need on upgrade day is a list of <strong>what quietly changes color.</strong></p>

<h3 id="requirements-and-changes-at-a-glance">Requirements and Changes at a Glance<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#requirements-and-changes-at-a-glance"><span class="icon icon-link"></span></a></h3>





















<table><thead><tr><th>Item</th><th>Required version</th></tr></thead><tbody><tr><td><strong>Node.js</strong></td><td>>= 22.12.0</td></tr><tr><td><strong>Vite</strong></td><td>>= 6.4.0 (<strong>peer dependency</strong>)</td></tr><tr><td><strong>Vitest tag</strong></td><td>5.0.1 (2026-09-03)</td></tr></tbody></table>
<p>Vite becoming a <strong>peer dependency</strong> is the first gate. npm, pnpm, Bun, and Deno install it automatically; <strong>Yarn users must install it themselves.</strong></p>

<p>At a glance:</p>

<h3 id="performance">Performance<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#performance"><span class="icon icon-link"></span></a></h3>
<p>For this release the Vitest team built a new benchmark suite measuring apps from <strong>5 to 1,280 modules</strong> across pool and environment combinations — an attempt to say "it got faster" along axes instead of by feel.</p>





















<table><thead><tr><th>Axis</th><th>Improvement</th></tr></thead><tbody><tr><td><strong>VM pools</strong></td><td>53% faster on dependency-heavy apps</td></tr><tr><td><strong>Isolated suites</strong></td><td>Up to 25% faster on large suites</td></tr><tr><td><strong>Browser Mode</strong></td><td>16–18% faster in Chrome</td></tr></tbody></table>
<p>Three sources account for most of it:</p>
<ul>
<li><strong>Inline projects share a Vite server</strong> — no more transforming the same file once per project</li>
<li><strong><code>fsModuleCache</code></strong> — transformed modules are <strong>cached on the file system and persist across runs.</strong> Worth the most on repeated local runs and CI that warms a cache</li>
<li><strong>Fewer worker round trips, plus a smaller install through bundled dependencies</strong></li>
</ul>
<p>The reporter's duration breakdown now shows <strong>percentages</strong> — small, but it tells you at a glance whether transform or collect is the slow part.</p>
<blockquote>
<p>One caveat: these numbers <strong>depend on pool, environment, and module count.</strong> For a small unit suite on jsdom, 53% is somebody else's story — you'll feel install size and caching first.</p>
</blockquote>
<h3 id="new-features">New Features<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#new-features"><span class="icon icon-link"></span></a></h3>
<h4 id="1-trace-view-browser-mode">1. Trace View (Browser Mode)<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#1-trace-view-browser-mode"><span class="icon icon-link"></span></a></h4>
<p>The headline feature. Browser Mode can <strong>record every interaction and assertion as DOM snapshots</strong>, letting you <strong>replay a test step by step</strong> after it finishes.</p>
<figure data-rehype-pretty-code-figure=""><pre tabindex="0" data-language="ts" data-theme="github-light-high-contrast github-dark-high-contrast"><code data-language="ts" data-theme="github-light-high-contrast github-dark-high-contrast" style="display: grid;"><span data-line=""><span style="--shiki-light:#A0111F;--shiki-dark:#FF9492">export</span><span style="--shiki-light:#A0111F;--shiki-dark:#FF9492"> default</span><span style="--shiki-light:#622CBC;--shiki-dark:#DBB7FF"> defineConfig</span><span style="--shiki-light:#702C00;--shiki-dark:#FFB757">({</span></span>

<span data-line=""><span style="--shiki-light:#0E1116;--shiki-dark:#F0F3F6">    browser: {</span></span>
<span data-line=""><span style="--shiki-light:#0E1116;--shiki-dark:#F0F3F6">      traceView: </span><span style="--shiki-light:#023B95;--shiki-dark:#91CBFF">true</span><span style="--shiki-light:#0E1116;--shiki-dark:#F0F3F6">,</span></span>
<span data-line=""><span style="--shiki-light:#0E1116;--shiki-dark:#F0F3F6">    },</span></span>

<p>The value is concentrated in failures. Browser tests are hard to debug because <strong>the screen at the moment of failure is already gone</strong> — Trace View brings it back. That's aimed squarely at the "broke once in CI, won't reproduce locally" category.</p>
<h4 id="2-nested-projects-and-config-inheritance">2. Nested Projects and Config Inheritance<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#2-nested-projects-and-config-inheritance"><span class="icon icon-link"></span></a></h4>
<p>A monorepo-facing change. Two things moved together:</p>
<ul>
<li><strong>Inline projects inherit the root config by default</strong> (<code>extends</code> now defaults to <code>true</code>)</li>
<li><strong>Referenced config files can declare their own <code>projects</code></strong>, so projects form a hierarchy</li>
</ul>
<p>Filtering got shorter too:</p>
<figure data-rehype-pretty-code-figure=""><pre tabindex="0" data-language="bash" data-theme="github-light-high-contrast github-dark-high-contrast"><code data-language="bash" data-theme="github-light-high-contrast github-dark-high-contrast" style="display: grid;"><span data-line=""><span style="--shiki-light:#702C00;--shiki-dark:#FFB757">vitest</span><span style="--shiki-light:#023B95;--shiki-dark:#91CBFF"> -p</span><span style="--shiki-light:#032563;--shiki-dark:#ADDCFF"> app</span><span style="--shiki-light:#66707B;--shiki-dark:#BDC4CC">        # short for --project app</span></span></code></pre></figure>
<h4 id="3-viwhen--conditional-mocking-per-argument">3. <code>vi.when</code> — Conditional Mocking per Argument<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#3-viwhen--conditional-mocking-per-argument"><span class="icon icon-link"></span></a></h4>

<span data-line=""><span style="--shiki-light:#622CBC;--shiki-dark:#DBB7FF">test</span><span style="--shiki-light:#0E1116;--shiki-dark:#F0F3F6">(</span><span style="--shiki-light:#032563;--shiki-dark:#ADDCFF">'sort'</span><span style="--shiki-light:#0E1116;--shiki-dark:#F0F3F6">, </span><span style="--shiki-light:#A0111F;--shiki-dark:#FF9492">async</span><span style="--shiki-light:#0E1116;--shiki-dark:#F0F3F6"> ({ </span><span style="--shiki-light:#702C00;--shiki-dark:#FFB757">bench</span><span style="--shiki-light:#0E1116;--shiki-dark:#F0F3F6"> }) </span><span style="--shiki-light:#A0111F;--shiki-dark:#FF9492">=></span><span style="--shiki-light:#0E1116;--shiki-dark:#F0F3F6"> {</span></span>
<span data-line=""><span style="--shiki-light:#A0111F;--shiki-dark:#FF9492">  await</span><span style="--shiki-light:#622CBC;--shiki-dark:#DBB7FF"> bench</span><span style="--shiki-light:#0E1116;--shiki-dark:#F0F3F6">(() </span><span style="--shiki-light:#A0111F;--shiki-dark:#FF9492">=></span><span style="--shiki-light:#0E1116;--shiki-dark:#F0F3F6"> {</span></span>
<span data-line=""><span style="--shiki-light:#0E1116;--shiki-dark:#F0F3F6">    data.</span><span style="--shiki-light:#622CBC;--shiki-dark:#DBB7FF">slice</span><span style="--shiki-light:#0E1116;--shiki-dark:#F0F3F6">().</span><span style="--shiki-light:#622CBC;--shiki-dark:#DBB7FF">sort</span><span style="--shiki-light:#0E1116;--shiki-dark:#F0F3F6">();</span></span>
<span data-line=""><span style="--shiki-light:#0E1116;--shiki-dark:#F0F3F6">  });</span></span>
<span data-line=""><span style="--shiki-light:#0E1116;--shiki-dark:#F0F3F6">});</span></span></code></pre></figure>
<p>The reasoning is consistent: once a benchmark is a test, it <strong>inherits fixtures, hooks, retries, and filtering for free.</strong> Benchmarks lived in their own world; this folds them back into the main one. Results now flow through the <code>default</code> and <code>json</code> reporters instead of a separate path.</p>
<p>The cost is <strong>a lot of removals.</strong></p>

<p><strong>The change most likely to alter your tests quietly.</strong> Mock history is now <strong>cleared before each test.</strong></p>
<figure data-rehype-pretty-code-figure=""><pre tabindex="0" data-language="ts" data-theme="github-light-high-contrast github-dark-high-contrast"><code data-language="ts" data-theme="github-light-high-contrast github-dark-high-contrast" style="display: grid;"><span data-line=""><span style="--shiki-light:#66707B;--shiki-dark:#BDC4CC">// Used to pass</span></span>

<span data-line=""><span style="--shiki-light:#622CBC;--shiki-dark:#DBB7FF">  doWork</span><span style="--shiki-light:#0E1116;--shiki-dark:#F0F3F6">();</span></span>
<span data-line=""><span style="--shiki-light:#0E1116;--shiki-dark:#F0F3F6">});</span></span>
<span data-line=""><span style="--shiki-light:#622CBC;--shiki-dark:#DBB7FF">it</span><span style="--shiki-light:#0E1116;--shiki-dark:#F0F3F6">(</span><span style="--shiki-light:#032563;--shiki-dark:#ADDCFF">'b'</span><span style="--shiki-light:#0E1116;--shiki-dark:#F0F3F6">, () </span><span style="--shiki-light:#A0111F;--shiki-dark:#FF9492">=></span><span style="--shiki-light:#0E1116;--shiki-dark:#F0F3F6"> {</span></span>
<span data-line=""><span style="--shiki-light:#622CBC;--shiki-dark:#DBB7FF">  expect</span><span style="--shiki-light:#0E1116;--shiki-dark:#F0F3F6">(spy).</span><span style="--shiki-light:#622CBC;--shiki-dark:#DBB7FF">toHaveBeenCalledTimes</span><span style="--shiki-light:#0E1116;--shiki-dark:#F0F3F6">(</span><span style="--shiki-light:#023B95;--shiki-dark:#91CBFF">2</span><span style="--shiki-light:#0E1116;--shiki-dark:#F0F3F6">); </span><span style="--shiki-light:#66707B;--shiki-dark:#BDC4CC">// counting calls that leaked from 'a'</span></span>

<p>The direction is right — it stops mock leakage between tests. But <strong>tests that relied on that leakage now fail.</strong> You can revert:</p>
<figure data-rehype-pretty-code-figure=""><pre tabindex="0" data-language="ts" data-theme="github-light-high-contrast github-dark-high-contrast"><code data-language="ts" data-theme="github-light-high-contrast github-dark-high-contrast" style="display: grid;"><span data-line=""><span style="--shiki-light:#A0111F;--shiki-dark:#FF9492">export</span><span style="--shiki-light:#A0111F;--shiki-dark:#FF9492"> default</span><span style="--shiki-light:#622CBC;--shiki-dark:#DBB7FF"> defineConfig</span><span style="--shiki-light:#702C00;--shiki-dark:#FFB757">({</span></span>

<p><code>expect.poll</code> got strict in the same direction — it <strong>now rejects</strong> if the callback or assertion doesn't settle within the timeout. The callback receives an <code>AbortSignal</code> for cancellation.</p>

<figure data-rehype-pretty-code-figure=""><pre tabindex="0" data-language="ts" data-theme="github-light-high-contrast github-dark-high-contrast"><code data-language="ts" data-theme="github-light-high-contrast github-dark-high-contrast" style="display: grid;"><span data-line=""><span style="--shiki-light:#66707B;--shiki-dark:#BDC4CC">// After: throws</span></span>

<span data-line=""><span style="--shiki-light:#0E1116;--shiki-dark:#F0F3F6">});</span></span>
<span data-line=""> </span>
<span data-line=""><span style="--shiki-light:#66707B;--shiki-dark:#BDC4CC">// Correct placement</span></span>
<span data-line=""><span style="--shiki-light:#0E1116;--shiki-dark:#F0F3F6">vi.</span><span style="--shiki-light:#622CBC;--shiki-dark:#DBB7FF">mock</span><span style="--shiki-light:#0E1116;--shiki-dark:#F0F3F6">(</span><span style="--shiki-light:#032563;--shiki-dark:#ADDCFF">'./api'</span><span style="--shiki-light:#0E1116;--shiki-dark:#F0F3F6">); </span><span style="--shiki-light:#66707B;--shiki-dark:#BDC4CC">// ✅ file top level</span></span>
<span data-line=""><span style="--shiki-light:#622CBC;--shiki-dark:#DBB7FF">describe</span><span style="--shiki-light:#0E1116;--shiki-dark:#F0F3F6">(</span><span style="--shiki-light:#032563;--shiki-dark:#ADDCFF">'suite'</span><span style="--shiki-light:#0E1116;--shiki-dark:#F0F3F6">, () </span><span style="--shiki-light:#A0111F;--shiki-dark:#FF9492">=></span><span style="--shiki-light:#0E1116;--shiki-dark:#F0F3F6"> {});</span></span></code></pre></figure>

<p>From the rest of the migration guide, here are the items whose <strong>error message won't tell you the cause.</strong></p>

























































<table><thead><tr><th>Change</th><th>How it shows up</th></tr></thead><tbody><tr><td><strong>Coverage include/exclude</strong></td><td>Patterns match <strong>relative to project root</strong> and the "contains" behavior is gone. <p>Two more if you use Browser Mode: locators passed to custom commands are now <strong><code>SerializedLocator</code> objects</strong> with <code>selector</code> and <code>locator</code> fields, and <strong><code>render()</code> is async</strong> in <code>vitest-browser-vue</code> and <code>vitest-browser-svelte</code>, so it must be awaited. <code>browser.api</code> and <code>browser.isolate</code> are deprecated in favor of top-level <code>api</code> and <code>isolate</code>.</p>

<p>Which narrows the actual work to <strong>three lines:</strong></p>
<ol>
<li><strong>Raising <code>engines</code> to Node 22.12+ is the precondition</strong> — without it the rest isn't a discussion</li>
<li><strong>Take the <code>clearMocks</code> default as-is rather than disabling it</strong> — if tests break, that's information</li>
<li><strong>Skip every Browser Mode item</strong> — the list looks long, but <strong>the number of gates this repo actually has to pass is small</strong></li>
</ol>
<p>Item 3 is worth writing down. Read all 34 migration entries top to bottom and <strong>every one looks like your problem</strong>, when in reality you hit <strong>as many as the features you turned on.</strong> If you don't use Browser Mode, benchmarks, or custom reporters, more than half of them were never yours.</p>
<h3 id="wrapping-up">Wrapping Up<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#wrapping-up"><span class="icon icon-link"></span></a></h3>
<p>Vitest 5 is <strong>a release where the defaults, not the features, are the story.</strong> <code>clearMocks</code> turns on, locators get strict, warnings become failures, and scattered artifacts collapse into one directory. Every one of those points the same direction — <strong>making things that used to pass ambiguously stop passing.</strong></p>
<p>So more red after upgrading is usually <strong>not a bad sign.</strong> Assertions that verified nothing because they weren't awaited; counts that included a neighbor's mock calls — spots that were already empty are finally visible. The temptation to flip <code>clearMocks: false</code> is strongest right here, and <strong>that flag doesn't fix the problem; it hides it again.</strong></p>
<p><strong>Upgrade checklist:</strong></p>
<ul>
<li>✅ Confirm Node.js 22.12+ and Vite 6.4+ (on Yarn, install <code>vite</code> yourself)</li>
<li>✅ <code>clearMocks</code> on by default — fix the failing tests instead of disabling it</li>
<li>✅ Audit every unawaited <code>resolves</code>/<code>rejects</code></li>
<li>✅ Move <code>vi.mock</code> / <code>vi.hoisted</code> to the file top level</li>
<li>✅ Check that CI <code>-t</code> patterns don't span segments</li>
<li>✅ <code>test.sequential</code> → <code>{ concurrent: false }</code></li>
<li>✅ Move artifact paths to <code>.vitest/</code> — <code>.gitignore</code>, artifact uploads, and <strong>any stdout-parsing step</strong></li>
<li>✅ Re-check coverage include/exclude patterns (root-relative, wildcard-less means directory)</li>
<li>✅ Make setups reading <code>VITEST_POOL_ID</code> / <code>VITEST_WORKER_ID</code> 1-based</li>
<li>✅ On Browser Mode: strict locators · async <code>render()</code> · <code>SerializedLocator</code> · <code>browser.api</code> → <code>api</code></li>
</ul>
