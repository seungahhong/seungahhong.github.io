<h2 id="v17">v17<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#v17"><span class="icon icon-link"></span></a></h2>
<p><strong>OpenSSL 3.0</strong></p>
<p>Node.js now includes OpenSSL 3.0, which bundles <a href="https://github.com/quictls/openssl">quictls/openssl</a> that supports QUIC. With OpenSSL 3.0, FIPS support is once again available through the new FIPS module. For detailed instructions on building Node.js with FIPS support, see <a href="https://github.com/nodejs/node/blob/master/BUILDING.md#building-nodejs-with-fips-compliant-openssl">BUILDING.md</a>.</p>
<p>The OpenSSL 3.0 API should be largely compatible with the API provided in OpenSSL 1.1.1, but because the restrictions on allowed algorithms and key sizes have been tightened, we expect there will be some impact on the ecosystem.</p>
<p>If your application running on Node.js 17 encounters an <code>ERR_OSSL_EVP_UNSUPPORTED</code> error, it is likely that your application or a module you are using relies on an algorithm or key size that OpenSSL 3.0 no longer allows by default. As a way to temporarily work around these stricter restrictions, you can revert to the legacy provider by using the <code>--openssl-legacy-provider</code> command-line option.</p>
<p><strong>V8 9.5</strong></p>
<p>The V8 JavaScript engine has been updated to V8 9.5. This release includes additional supported types for the <code>Intl.DisplayNames</code> API and an expanded <code>timeZoneName</code> option for the <code>Intl.DateTimeFormat</code> API.</p>
<p>You can find more details in the V8 9.5 release post.</p>

<p><strong>HTTP connections kept alive by default</strong></p>
<p>The keepAlive option of the http/https modules controls whether the connection to the server should be maintained after a request completes. Originally, you had to manually set the keepAlive option to true. This option instructs the server to keep the connection open and reuse it for subsequent requests.</p>
<p>In Node.js 19, the keepAlive option is set to true by default. This addition significantly reduces the overhead of establishing new connections.</p>
<p><strong>WebCrypto API stabilization</strong></p>
<p>The WebCrypto API is Node.js's standard implementation of the Web Crypto API. With Node.js 19, you can now use the Ed25519, Ed448, X25519, and X448 algorithms.</p>
<p>You can access this API using the globalThis module or node:, a prefix introduced in Node.js 18 to distinguish core Node.js modules from third-party libraries.</p>
<p><strong>Custom ESM resolution adjustments</strong></p>
<p>Node.js 19 removes the previous experimental <strong>--experimental-specifier-solution</strong> flag. This provided experimental support for locating files using package specifiers, similar to how ECMAScript imports modules.</p>
<p>Node.js removed this flag because the functionality can be replicated using custom loaders. Custom loaders allow you to support more module formats or provide your own logic for loading and processing modules, so you can further process a module before loading it.</p>
<p><strong>Removal of DTrace/SystemTap/ETW support</strong></p>
<p>DTrace, SystemTap, and ETW (Event Tracing for Windows) are modules that provide dynamic tracing and analysis of running programs. Originally, Node.js used these to collect data about application activity, including performance indicators, errors, and other possible runtime occurrences.</p>
<p>In Node.js 19, Node.js removed support for DTrace, SystemTap, and ETW, because the complexity involved in keeping these modules up to date and maintaining them is not yet worth the effort. Therefore, support was discontinued in order to prioritize resources.</p>
