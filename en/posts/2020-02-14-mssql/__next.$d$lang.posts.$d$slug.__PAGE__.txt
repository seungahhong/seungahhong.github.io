f:Td857,<h2 id="terminology">Terminology<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#terminology"><span class="icon icon-link"></span></a></h2>
<ul>
<li>
<p>Transaction: Treating multiple data changes as a single logical unit of work so that everything is either completed or rolled back, maintaining data integrity</p>
</li>
<li>
<p>COMMIT: All transaction modifications are permanently applied as part of the database, and the resources used by the transaction are released</p>
</li>
<li>
<p>ROLLBACK: Reverts to the starting state and cancels all modifications made during the transaction</p>
</li>
<li>
<p>Trigger: When data in a specific table is modified, it automatically cascades the update internally to other related tables or columns, or maintains integrity</p>
</li>
<li>
<p>Cursor: The position in memory where a SQL statement is executed
It can directly access and fetch the result of a SQL statement that exists in memory (SELECT * FROM A)
The currently processed row</p>
</li>
</ul>
<h2 id="sql-server-overview">SQL Server Overview<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#sql-server-overview"><span class="icon icon-link"></span></a></h2>
<ul>
<li>
<p>Database: A collection of data organized so that the data and information required by users can be efficiently stored, managed, and</p>
<pre><code>                  integrated
</code></pre>
</li>
<li>
<p>Relational database</p>
</li>
</ul>
<ul>
<li>
<p>A database in which related data is not all contained in a single table but managed across several different tables, organizing the data by</p>
<p>assigning some relationship between the data</p>
</li>
</ul>
<ul>
<li>
<p>SQL Server service</p>
<ul>
<li>As a database engine, it processes Transact-SQL statements and manages all files that make up the databases on the server.</li>
</ul>
</li>
<li>
<p>SQL Server Agent</p>
<ul>
<li>
<p>A service related to automated management; it automates administration by creating jobs, alerts, operators, and so on.</p>
</li>
<li>
<p>For example, when the log exceeds 90%, it raises an alert, and when the alert occurs, it backs up the database log.</p>
</li>
</ul>
</li>
<li>
<p>MS DTC (Microsoft Distributed Transaction Coordinator)</p>
<ul>
<li>A series of operations used to process distributed data as a single transaction</li>
</ul>
</li>
<li>
<p>Full-Text Search</p>
<ul>
<li>
<p>A Microsoft search service that queries text and strings under various conditions</p>
</li>
<li>
<p>To use this feature, you must create and maintain a full-text index.</p>
</li>
</ul>
</li>
<li>
<p>Analysis Server</p>
<ul>
<li>A server component of Microsoft SQL Server 2000 Analysis Services that provides fast analytical access to data warehouses and data marts</li>
</ul>
</li>
<li>
<p>Database objects</p>
</li>
</ul>
<ol>
<li>
<p>Index: An object used to enable fast data retrieval or to enforce data integrity</p>
<p>Data integrity: Maintaining and guaranteeing the accuracy and consistency of data</p>
</li>
<li>
<p>View: A virtual table defined to reuse frequently used or complex queries</p>
</li>
<li>
<p>Trigger: A special kind of stored procedure that runs automatically when data is changed</p>
</li>
<li>
<p>Rule: Performs the same role as a CHECK constraint and is used by binding to a table column or a user-defined data type.</p>
<p>EXEC sp_bindrule 'ZipCode_rule', 'ZipCode'</p>
</li>
</ol>
<ul>
<li>Purpose of system databases</li>
</ul>
<ol>
<li>
<p>Master: Stores all data related to the server.</p>
</li>
<li>
<p>TempDB: Used as a temporary workspace when creating temporary tables or when accompanying clauses such as ORDER BY, DISTINCT</p>
</li>
<li>
<p>Model: The database that serves as the model when creating a new database</p>
</li>
<li>
<p>MSDB: Records content related to automated management.</p>
</li>
<li>
<p>Distribution: Used for log distribution when replication is configured.</p>
</li>
</ol>
<h2 id="transact-sql-basics">Transact-SQL Basics<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#transact-sql-basics"><span class="icon icon-link"></span></a></h2>
<ul>
<li>Types of SQL statements</li>
</ul>
<ul>
<li>
<p>Data Manipulation Language (DML): Data insert, query, update, delete (INSERT, SELECT, UPDATE, DELETE)</p>
</li>
<li>
<p>Data Definition Language (DDL): Defines the characteristics and properties of a database, and creates, modifies, and deletes tables, indexes, views, etc. (CREATE, ALTER, DROP)</p>
</li>
<li>
<p>Data Control Language (DCL): Controls access permissions on database objects (GRANT, REVOKE, DENY)</p>
</li>
</ul>
<ul>
<li>Three ways to alias a column</li>
</ul>
<p>SELECT GETDATE() AS DateTime, 2 Quantity, UnitPrice=450</p>
<ul>
<li>Identifiers</li>
</ul>
<ul>
<li>
<p>Database object names</p>
</li>
<li>
<p>When a reserved word or special character is included, a delimiter is used to distinguish the identifier.</p>
</li>
<li>
<p>Delimiters are [] , "" (SET QUOTED_IDENTIFIER ON session option; when OFF it is used as a string)</p>
</li>
</ul>
<p>SELECT *</p>
<p>FROM [MY TABLE] // distinguished when a whitespace character is included</p>
<p>WHERE [ORDER] = 10 // distinguished for some reserved words</p>
<ul>
<li>
<p>Logical operators: precedence - NOT, AND, OR</p>
</li>
<li>
<p>ORDER BY (sorting queried data)</p>
</li>
</ul>
<ul>
<li>Constraint: ntext, text, image cannot be used in an ORDER BY clause.</li>
</ul>
<p>SELECT type, AVG(price) AS avgPrice</p>
<p>FROM titles</p>
<p>WHERE royalty = 10</p>
<p>GROUP BY type</p>
<p>HAVING AVG(price) &#x3C; 80</p>
<ul>
<li>DISTINCT and GROUP BY clauses</li>
</ul>
<ul>
<li>
<p>DISTINCT is mainly used to query UNIQUE (duplicate-removed) columns or records</p>
</li>
<li>
<p>GROUP BY groups the data and returns the result.</p>
</li>
</ul>
<p>e.g.)</p>
<p>-- Removing duplicate data using DISTINCT
SELECT DISTINCT deptno FROM emp;</p>
<p>-- Removing duplicate data using GROUP BY
SELECT deptno FROM emp GROUP BY deptno;</p>
<h3 id="deptno">DEPTNO<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#deptno"><span class="icon icon-link"></span></a></h3>
<pre><code>30
20
10
</code></pre>
<ol>
<li>
<p>When is each used?</p>
<p>GROUP BY: Used when distinguishing specific groups using aggregate functions</p>
<p>DISTINCT: Used when removing duplicate data without distinguishing specific groups</p>
</li>
</ol>
<p>e.g.)
SELECT COUNT(DISTINCT d.deptno) "Deduplicated Count",
COUNT(d.deptno) "Total Count"
FROM emp e, dept d
WHERE e.deptno = d.deptno;</p>
<p>-- When an aggregate function is needed, GROUP BY must be used.
SELECT deptno, MIN(sal)
FROM emp
GROUP BY deptno;</p>
<ul>
<li>Difference between SELECT INTO / INSERT INTO</li>
</ul>
<ul>
<li>SELECT INTO: Used when the source exists and you want to create a new destination table (only the source table is needed - since it is copied)</li>
<li>INSERT INTO: Must be used when both the source table and the destination table already exist</li>
</ul>
<ol>
<li>When is each used?</li>
</ol>
<ul>
<li>
<p>SELECT INTO: Mainly used to create a temporary table for sub-tasks while keeping the source table intact during complex operations.</p>
</li>
<li>
<p>INSERT INTO: Used to copy data from the source table</p>
</li>
</ul>
<ol start="2">
<li>
<p>How to use SELECT INTO</p>
<p>-Used when the source exists and you want to create a new destination table</p>
<p>-SELECT * INTO AA FROM A</p>
<pre><code>  -Creates a table named AA with the same columns and data as table A
</code></pre>
<p>1-1 If you want to bring only specific columns of table A,</p>
<pre><code>      SELECT * INTO AA

         FROM ( SELECT COL1, COL2, COL3.....

                           FROM AA

                     ) AS TEMP

 -Brings only specific columns of table A, creates a table named AA, and inserts the data.
</code></pre>
</li>
<li>
<p>How to use INSERT INTO</p>
</li>
</ol>
<ul>
<li>
<p>INSERT INTO B SELECT * FROM A</p>
<p>-In the above, table A and table B must have the same schema. (Same data structure, same format tables)</p>
</li>
<li>
<p>INSERT INTO B SELECT COL1,COL2,COL3 FROM A</p>
<p>-If there are fewer columns than A, specify the columns after SELECT</p>
</li>
</ul>
<ul>
<li>Join: An operation that queries two or more tables to produce a single result</li>
</ul>
<ol>
<li>Inner Join (INNER JOIN) / Outer (OUTER JOIN)</li>
</ol>
<p>● INNER JOIN</p>
<ul>
<li>
<p>ANSI standard: SELECT a.id, a.val aval, b.val bval FROM A a INNER JOIN B b ON a.id = b.id;</p>
</li>
<li>
<p>Transact-SQL: SELECT a.id, a.val aval, b.val bval FROM A a ,B b WHERE a.id = b.id;</p>
</li>
</ul>
<p>● LEFT OUTER JOIN</p>
<ul>
<li>
<p>ANSI standard: SELECT a.id, a.val aval, b.val bval FROM A a LEFT OUTER JOIN B b ON a.id = b.id;</p>
</li>
<li>
<p>Transact-SQL: SELECT a.id, a.val aval, b.val bval FROM A a , B b WHERE a.id *= b.id;</p>
</li>
</ul>
<p>● RIGHT OUTER JOIN</p>
<ul>
<li>
<p>ANSI standard: SELECT a.id, a.val aval, b.val bval FROM A a RIGHT OUTER JOIN B b ON a.id = b.id;</p>
</li>
<li>
<p>Transact-SQL: SELECT a.id, a.val aval, b.val bval FROM A a , B b WHERE a.id =* b.id;</p>
</li>
</ul>
<ul>
<li>UNION</li>
</ul>
<ul>
<li>
<p>JOIN: Parallel combination of two tables or results</p>
<p>UNION: A serial combination that merges query results vertically (top and bottom)</p>
</li>
<li>
<p>To use GROUP BY and HAVING clauses on the entire UNION result, use a temporary table or a derived table</p>
</li>
</ul>
<p>SELECT stor_ID AS StoreID, Qty*2 AS Quantity
INTO #SalesTemp FROM sales</p>
<p>SELECT StoreID, SUM(Quantity)
FROM
( SELECT Stor_ID AS StoreID, Qty AS Quantity FROM sales
UNION ALL
SELECT * FROM #SalesTemp
) t
GROUP BY StoreID</p>
<p>Result)</p>
<p>6380 24
7066 375</p>
<ul>
<li>DELETE / UPDATE</li>
</ul>
<ul>
<li>
<p>DELETE FROM authors WHERE au_lname = 'McBadden'</p>
</li>
<li>
<p>UPDATE authors SET state = 'PC' WHERE state = 'CA'</p>
</li>
</ul>
<ul>
<li>INSERT</li>
</ul>
<ul>
<li>
<p>When the INSERT statement is used with a VALUE clause, the INTO clause can be omitted</p>
</li>
<li>
<p>Columns that do not need to be specified in an insert</p>
<ol>
<li>
<p>Columns that allow NULL</p>
</li>
<li>
<p>Columns with a default value</p>
</li>
<li>
<p>Columns with an auto-increment attribute</p>
</li>
<li>
<p>Columns with Rowversion or Timestamp</p>
</li>
</ol>
</li>
</ul>
<ul>
<li>TRUNCATE TABLE / DELETE</li>
</ul>
<ul>
<li>
<p>Same as a DELETE statement without a WHERE clause</p>
</li>
<li>
<p>DELETE: Auto-increment attribute is retained / TRUNCATE: Auto-increment attribute is reset</p>
</li>
<li>
<p>DELETE is fast and uses fewer transaction log resources -After DELETE removes a row, it records a transaction log entry for each row</p>
</li>
<li>
<p>TRUNCATE does not log per-row deletions, so DELETE triggers do not fire</p>
<p>Trigger: Something that automatically cascades to other related tables or columns internally when data in a specific table is modified, in order to maintain integrity</p>
</li>
</ul>
<h2 id="db-creation-and-management">DB Creation and Management<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#db-creation-and-management"><span class="icon icon-link"></span></a></h2>
<ul>
<li>
<p>Database: A unit of management that maintains consistency by grouping objects related to a business unit you want to manage into a single logical</p>
<pre><code>                  storage unit, and it is also a unit of recovery
</code></pre>
</li>
<li>
<p>Basic composition of a database: File group / data file / log file</p>
<ol>
<li>
<p>File group: A logical collection of multiple data files</p>
<pre><code>             Can be considered for improving performance by distributing across disks.
</code></pre>
</li>
<li>
<p>Database file: Can be divided into data files and log files, referring to the physical storage unit that records data.</p>
<pre><code>                        Primary file: Stores the database startup information and data / Secondary files: Other files

                        Transaction log file: Stores the log information needed for data recovery
</code></pre>
</li>
<li>
<p>Extent: The basic unit allocated to tables and indexes (one extent consists of 8 contiguous pages (64KB))</p>
<pre><code>           When the previously allocated storage space is insufficient, a new extent is allocated and used starting from the first page.
</code></pre>
</li>
<li>
<p>Data file: The physically reserved space where extents can be allocated</p>
</li>
<li>
<p>Page: A page is the basic unit of data storage in SQL Server</p>
</li>
</ol>
</li>
<li>
<p>Creating a database</p>
<ol>
<li>
<p>Database: Composed of multiple data files and log files</p>
</li>
<li>
<p>When there are multiple physical drives, data files are distributed across multiple file groups to distribute hard disk I/O.</p>
<p>The log size varies depending on the amount of data modification and the log backup schedule, and is basically 10~25%</p>
</li>
</ol>
</li>
</ul>
<p>CREATE DATABASE [Testpubs] ON PRIMARY
(NAME = N'Testpubs_Data'
,FILENAME = N'C:\TEMP\Testpubs_Data.MDF'
,SIZE = 5, MAXSIZE=100
,FILEGROWTH=10%)
LOG ON
(NAME = N'Testpubs_Log'
,FILENAME = N'C:\TEMP\Testpubs_Log.LDF'
,SIZE = 2
,FILEGROWTH=1MB)</p>
<p>● ON: Explicitly defines the data file where the data portion is stored</p>
<p>● PRIMARY: Defines the primary file</p>
<p>● NAME: The logical name</p>
<p>● LOG ON: Explicitly defines the disk file where the database log is stored.</p>
<p>● FOR LOAD: An option to recover from database backup data and initialize it</p>
<p>● FOR ATTACH: An option to attach a database from an existing set of operating system files</p>
<ul>
<li>Increasing file size and adding a new file</li>
</ul>
<p>ALTER DATABASE [Testpubs] MODIFY FILE
(NAME = 'Testpubs_Data'
,SIZE = 10)</p>
<p>ALTER DATABASE [Testpubs] ADD FILEGROUP [Second]</p>
<p>ALTER DATABASE [Testpubs] ADD FILE
(NAME = N'Testpubs_Data2'
,FILENAME = N'C:\Temp\Testpubs_Data2.NDF'
,SIZE = 1, FILEGROWTH = 10%
) TO FILEGROUP [Second]</p>
<ul>
<li>Using file groups</li>
</ul>
<ul>
<li>
<p>File groups explicitly allocate space to store tables and indexes, as well as BLOB-type data, i.e., Image, text, and ntext data types.</p>
</li>
<li>
<p>BLOB (Binary Large Object)</p>
</li>
</ul>
<p>ALTER DATABASE [Testpubs] ADD FILEGROUP [FG_Index]
ALTER DATABASE [Testpubs] ADD FILEGROUP [FG_BLOB]</p>

,SIZE = 1
,FILEGROWTH = 10%) TO FILEGROUP [FG_Index]</p>

TEXTIMAGE_ON [FG_BLOB]</p>
<ul>
<li>Shrinking a database</li>
</ul>
<ol>
<li>Automatic file shrink: Periodically shrinks the file while leaving 25% free space and returns it to the OS.</li>
</ol>
<p>DBCC SHRINKFILE(Testpubs_Data, 25) - Runs periodically at 30-minute intervals</p>
<ol start="2">
<li>Manual file shrink</li>
</ol>
<p>● EMPTYFILE: Moves all data to another file in the same file group and leaves the file empty</p>
<pre><code>                     For the purpose of physically moving the file to another space and removing it
</code></pre>
<p>DBCC SHRINKFILE(Testpubs_Data2, EMPTYFILE)</p>
<p>ALTER DATABASE Testpubs REMOVE FILE Testpubs_Data2</p>
<p>● NOTRUNCATE: Retains the freed file space in the file and does not return the freed space to the operating system.</p>
<p>● TRUNCATEONLY: Returns unused space in the file to the operating system, reducing the file size without moving data.</p>
<pre><code>                            When using TRUNCATEONLY, target_size is ignored.
</code></pre>
<p>DBCC SHRINKFILE(Testpubs_Data, 5, [EMPTYFILE | NOTRUNCATE|TRUNCATEONLY )</p>
<ol start="3">
<li>Manual database shrink</li>
</ol>
<ul>
<li>
<p>Used to shrink all data files and log files in the specified database.</p>
</li>
<li>
<p>ALTER DATABASE and DBCC SHRINKFILE cannot make it smaller than the final size explicitly set.</p>
</li>
</ul>
<p>DBCC SHRINKDATABASE(Testpubs, 25) Shrinks while leaving 25% free space (NOTRUNCATE , TRUNCATEONLY )</p>
<ul>
<li>
<p>Changing and deleting a database</p>
<ol>

<ul>
<li>COMPUTE BY</li>
</ul>
<ol>
<li>Summary of the difference between COMPUTE and GROUP BY</li>
</ol>
<p>GROUP BY returns a single result set. For each group, there is one row containing the grouping columns and aggregate functions that show the subtotals for that group. The SELECT list can include only the grouping columns and aggregate functions. It does not show the raw data.
COMPUTE (BY) shows the raw data, and is often used when querying subtotals and grand totals together with the raw data.
The columns in the COMPUTE BY clause must be specified in the ORDER BY clause.
SELECT stor_id, ord_num, title_id, payterms, qty
FROM sales
WHERE stor_id LIKE '706%'
ORDER BY stor_id, qty DESC
COMPUTE AVG(qty), SUM(qty) BY stor_id</p>
<p>COMPUTE AVG(qty), SUM(qty)</p>
<p>SELECT qty, AVG(qty), SUM(qty)
FROM sales
WHERE stor_id LIKE '706%'
GROUP BY qty
ORDER BY qty</p>
<h2 id="index-design-and-usage">Index Design and Usage<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#index-design-and-usage"><span class="icon icon-link"></span></a></h2>
<ul>
<li>Terminology</li>
</ul>
<ul>
<li>
<p>Index page: The page where the actual index is stored</p>
</li>
<li>
<p>Data page: The page where the actual data is stored</p>
</li>
<li>
<p>Covered Query: A query built as a non-clustered index using a composite key of the queried columns and the condition columns</p>
</li>
</ul>
<ul>
<li>Index</li>
</ul>
<ul>
<li>Used to improve the response time of queries</li>
</ul>
<ul>
<li>Reasons for using indexes</li>
</ul>
<ul>
<li>
<p>Mainly improves the execution speed not only of data retrieval but also of updates with search conditions</p>
</li>
<li>
<p>Used to enforce uniqueness and prevent duplicate data from occurring.</p>
</li>
</ul>
<ul>
<li>Disadvantages of indexes</li>
</ul>
<ul>
<li>
<p>Indexes require additional storage space, and when there are many indexes, it takes more time to execute insert, update, and delete commands on the data.</p>
</li>
<li>
<p>Additionally, more processing time is needed to maintain and manage them.</p>
</li>
</ul>
<ul>
<li>Clustered index</li>
</ul>
<ul>
<li>
<p>An index that sorts and stores the data rows in the table based on the key value; data within a page is sorted based on the index key</p>
</li>
<li>
<p>Getting one piece of data from a large amount of data; since the data itself is sorted, range searches are used more efficiently.</p>
</li>
<li>
<p>A case where the data storage and the index storage coexist, and the data is stored in the order of the index.</p>
</li>
</ul>
<ul>
<li>Non-clustered index</li>
</ul>
<ul>
<li>
<p>An index in which the data storage and the index storage are separated into separate spaces, while holding a pointer that can be used to find the row in the data</p>
<p>storage</p>
</li>
<li>
<p>When a clustered index does not exist, it holds a RID (row identifier) pointer, and when a clustered index exists, it holds the clustered index key value</p>
<p>as the pointer.</p>
</li>
</ul>
<ul>
<li>Index design</li>
</ul>
<p>● When an index is useful</p>
<ul>
<li>
<p>When searching for rows that exactly match a specific search key value (WHERE emp_id = 357)</p>
</li>
<li>
<p>When searching for rows with a search key value in a specific range (WHERE job_lvl BETWEEN 9 and 12)</p>
</li>
<li>
<p>When searching for rows in table T1 that match rows in table T2 based on a join predicate</p>
</li>
<li>
<p>When producing query output sorted by a specific column (ORDER BY Qty DESC)</p>
</li>
<li>
<p>When ensuring PRIMARY KEY and UNIQUE constraints to enforce uniqueness</p>
</li>
<li>
<p>When ensuring referential integrity between two tables where a FOREIGN KEY constraint is defined</p>
</li>
</ul>
<p>● When an index is not useful</p>
<ul>
<li>
<p>Columns with few distinct values: When there is little uniqueness, such as gender</p>
</li>
<li>
<p>Long string data type columns (because there is a limit to the index that can fit on one page)</p>
</li>
<li>
<p>Columns that are rarely searched</p>
</li>
<li>
<p>Indexes cannot be created on the bit, text, ntext, and image data types</p>
</li>
<li>
<p>Do not use indexes on small tables (because index traversal time can be longer than a table scan)</p>
</li>
</ul>
<p>● Additional guidelines for index design</p>
<ul>
<li>
<p>Since all indexes must be adjusted when the table's data changes, creating many indexes on a table degrades INSERT, UPDATE, and DELETE performance</p>
</li>
<li>
<p>Performance improves for queries that do not modify data, such as SELECT statements.</p>
</li>
</ul>
<ul>
<li>
<p>Data and index storage structure</p>
<p>● Clustered table with a clustered index</p>
<ul>
<li>Data rows are stored in order based on the clustered index key.</li>
</ul>
<p>● Table without a clustered index (heap)</p>
<ul>
<li>Not stored in any particular order, and there is no special order for the data page sequence.</li>
</ul>
<p>● Index ID (can be checked in sysindexes)</p>
<ul>
<li>
<p>For a table without a clustered index, indid value: 0</p>
</li>
<li>
<p>Clustered index indid value: 1</p>
</li>
<li>
<p>Non-clustered index indid value: 2~250</p>
</li>
<li>
<p>Table with text, ntext, image columns: 255</p>
</li>
</ul>
<p>● Root and FirstIAM</p>
<ul>
<li>
<p>The root column of sysindexes points to the top of the index B-tree.</p>
<p>FirstIAM -IAM (collection of the table's data pages) -data row header</p>
</li>
</ul>
</li>
<li>
<p>Various ways to search for data</p>
<p>● Table scan: In a table without a clustered index, uses the IAM page chain to perform I/O on all pages of the table</p>
<pre><code>                    FirstIAM -brings all pages containing data through the start pointer of the IAM page chain
</code></pre>
</li>
</ul>

<pre><code> - When scanning the entire clustered index, it does not use the intermediate-level index of the clustered index but performs I/O on the leaf

   nodes of the clustered index, i.e., all data pages, through the IAM.
</code></pre>
<p>● Clustered index with previous/next page pointers</p>
<pre><code> - In a clustered index, sequentially performs I/O on all pages starting from the first or last page through the previous/next page pointers within

   the data pages. (Queried through the previous and next page pointers)

                              find the data page
</code></pre>

<p>● Clustered index seek</p>
<pre><code> -  Performs a B-Tree search from the index root node to obtain the result
</code></pre>
<p>SELECT _ FROM OrderX
