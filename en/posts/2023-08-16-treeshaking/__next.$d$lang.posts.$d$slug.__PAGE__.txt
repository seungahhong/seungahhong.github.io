23:T5e75,<h3 id="overview">Overview<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#overview"><span class="icon icon-link"></span></a></h3>
<p>An optimization technique that <strong>removes unnecessary code</strong>, much like shaking a tree to knock off its dead branches.</p>
<ul>
<li>When using Webpack version 4 or higher, basic tree shaking is provided out of the box for ES6 modules (modules that use <code>import</code> and <code>export</code>).</li>
<li>React applications created with Create React App also use Webpack, so tree shaking is possible there as well.</li>
</ul>

<h3 id="tree-shaking-configuration"><strong>Tree Shaking Configuration</strong><a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#tree-shaking-configuration"><span class="icon icon-link"></span></a></h3>
<p>If you check the <a href="https://v4.webpack.js.org/guides/tree-shaking">webpack official documentation</a>, there are four things you need to do to set up tree shaking.</p>
<ul>
<li>Use the ES6 module format (e.g., import / export)</li>
<li>Prevent compilation to CommonJS (using settings such as @babel/preset-env)</li>
<li>Use the sideEffects property in package.json</li>
<li>Use webpack production mode</li>
</ul>
<h2 id="react-tree-shaking"><strong>React Tree Shaking</strong><a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#react-tree-shaking"><span class="icon icon-link"></span></a></h2>
<h3 id="export-the-modules-you-want-to-expose"><strong>Export the modules you want to expose</strong><a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#export-the-modules-you-want-to-expose"><span class="icon icon-link"></span></a></h3>
<ul>
<li>If you export each module you want to expose individually and import it into the components that need it, tree shaking becomes possible.
<ul>
<li>A natural question: does tree shaking still work when things are configured using re-export syntax?</li>
<li>The conclusion is yes, it does. Why? Because starting from webpack 4, the <code>providedExports</code> optimization setting defaults to <code>true</code> during production builds, so webpack analyzes the syntax at build time and applies optimizations.</li>
</ul>
</li>
</ul>

<h3 id="configuring-the-babelrc-file"><strong>Configuring the Babelrc file</strong><a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#configuring-the-babelrc-file"><span class="icon icon-link"></span></a></h3>
<p>Babel is a <strong>library that transpiles JavaScript syntax into ES5 syntax</strong> so that it remains <strong>compatible even with older browsers</strong>, and it is an essential tool for web applications. However, when the <strong><a href="https://babeljs.io/docs/plugins/preset-env/">babel-preset-env</a></strong> package is used during transpilation, it automatically converts ES6 syntax to CommonJS, which makes tree shaking impossible.</p>
<p>To prevent this, you need to add a setting in <code>.babelrc</code> that stops the conversion to <code>commonjs</code>.</p>

<h3 id="configuring-sideeffects"><strong>Configuring sideEffects</strong><a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#configuring-sideeffects"><span class="icon icon-link"></span></a></h3>
<p>For <strong>code that may cause side effects</strong>, Webpack <strong>excludes it from tree shaking even if it is unused</strong>.</p>
<p>Setting <code>sideEffects</code> in the <code>package.json</code> file tells Webpack that no side effects will occur across the entire application, so it is safe to perform tree shaking.</p>
<p>If you would rather not add it to <code>package.json</code>, you can configure it using <code>module.rules</code>.]</p>
<p><a href="https://github.com/webpack/webpack/issues/6065#issuecomment-351060570">Allow app authors to force libraries into sideEffects: false` · Issue #6065 · webpack/webpack</a></p>
<p>However, when using css-loader or importing files directly in JS, necessary information can sometimes be dropped, so be sure to add such files to the sideEffects array.</p>

<h3 id="using-modules-that-use-es6-syntax"><strong>Using modules that use ES6 syntax</strong><a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#using-modules-that-use-es6-syntax"><span class="icon icon-link"></span></a></h3>
<p>Since Webpack only supports tree shaking for modules that manage dependencies as ES Modules, tree shaking is not supported when using libraries that follow the ES5/CommonJS spec.</p>
<p>Let me compare lodash and lodash-es, which always come up when optimizing performance.</p>
<ul>
<li>lodash-es: <a href="https://github.com/lodash/lodash/blob/master/pick.js">pick.js</a>
<ul>
<li>Uses ES Modules (uses export, import), sideEffects: false</li>
</ul>
</li>
<li>lodash: <a href="https://github.com/lodash/lodash/blob/4.17.11-npm/pick.js">pick.js</a>, <a href="https://github.com/lodash/lodash/blob/4.17.11-npm/package.json">package.json</a>
<ul>
<li>Uses CommonJS</li>
</ul>
</li>
</ul>
