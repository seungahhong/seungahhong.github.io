<h2 id="explaining-jotais-concepts-and-strengths">Explaining Jotai's Concepts and Strengths<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#explaining-jotais-concepts-and-strengths"><span class="icon icon-link"></span></a></h2>
<ul>
<li>State management overview
Recent approaches to state management can be broadly divided into three categories.
<ul>
<li>Flux (Redux, Zustand)
<ul>
<li>The commonly used Flux approach, which updates state through a store, action functions, reducers, and so on.</li>
</ul>
</li>
<li>Proxy (Mobx, Valtio)
<ul>
<li>An approach that automatically detects and updates the portions of state used by a component.</li>
</ul>
</li>
<li>Atomic (Jotai, Recoil)
<ul>
<li>An approach that stores and manages state within the React tree, similar to React's built-in state.</li>
</ul>
</li>
</ul>
</li>
<li>Jotai concepts
<ul>
<li>Key concepts
<ul>
<li>Minimal API</li>
<li>Built-in TypeScript support</li>
<li>Small bundle size (3kb)</li>
<li>Many additional utilities and official integrations</li>
<li>Next.js and React Native support</li>
<li>Usable only with React</li>
</ul>
</li>
<li>Introduction
<ul>
<li>"Jotai" means "state" in Japanese. The same development group, <a href="https://pmnd.rs/">Pmndrs</a>, also created a state management library called <a href="https://github.com/pmndrs/zustand">Zustand</a>, which means "state" in German.</li>
<li>A React-specific state management library built to solve Context's re-rendering problem.</li>
<li>In React, to improve on the top-down approach of useContext and useState, it is organized as an atomic state management style similar to Recoil (a bottom-up approach).
<img src="/blog-assets/2022/06/images/14/Untitled.png" alt="Untitled"></li>
</ul>
</li>
</ul>
</li>
<li>Jotai's strengths
<ul>
<li>By default, it reduces re-rendering problems, and it also provides utilities such as selectAtom and splitAtom to further reduce re-rendering.</li>
<li>It significantly reduces boilerplate code compared to Redux.</li>
<li>It is designed to work well with Suspense (Concurrent mode), a major React feature.</li>
<li>Two characteristics that Jotai emphasizes
<ul>
<li>Primitive: An interface similar to useState, React's built-in state function.</li>
<li>Flexible: Atoms can combine with one another and participate in each other's state, and it supports smooth integration with other libraries (in particular, it can be linked with Redux for state management).</li>
</ul>
</li>
</ul>
</li>
</ul>
<h2 id="key-features-of-jotai">Key Features of Jotai<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#key-features-of-jotai"><span class="icon icon-link"></span></a></h2>
<ul>
<li>
<p>atom</p>
<ul>
<li>The basic unit for holding data; state is created using an atom.</li>
<li>Provides an interface similar to useState (useAtom).</li>
</ul>

<p>Provider
An atom's value is not stored in a global atom; instead, it is stored on the component tree, similar to Context. Using a <a href="https://jotai.org/docs/api/core#provider">Provider</a>, you can supply the Context in which atoms are stored. (In other words, if the referenced Provider differs, the same atom will have different values even when used.) If you do not specify a Provider, the default store is used.</p>

<h2 id="personal-opinion">Personal Opinion<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#personal-opinion"><span class="icon icon-link"></span></a></h2>
<ul>
<li>If you need state management support through multiple stores, this seems like a library well worth using.</li>
<li>Since Jotai supports many libraries out of the box, it looks easy to use. (That said, check whether each library is fully supported.)</li>
<li>The syntax itself looks easier than Recoil's state management.
<ul>
<li>Everything is unified into atoms.</li>
<li>Not having a unique key also feels convenient.</li>
</ul>
</li>
<li>Given that several companies have adopted it, it seems to have secured a certain level of stability. (Kakaostyle, Hwahae, and others.)</li>
<li>It seems like a state management tool worth trying on small-scale, React-tree-based projects.</li>
</ul>
