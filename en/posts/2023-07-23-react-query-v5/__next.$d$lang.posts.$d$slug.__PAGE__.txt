<li>
<p>Limited, Infinite Queries with new maxPages option</p>
<ul>
<li>The more pages an Infinite Query fetches, the more memory it consumes, and since every page has to be refetched sequentially, the query refetch process becomes slower.</li>
<li>By providing <code>maxPages</code>, you can cap the maximum number of pages so that only the pages you actually need are fetched.</li>
</ul>
</li>

<li>Prefetching was also added for Infinite Queries.</li>

<ul>

<li>
<p>Callback on useQuery(and QueryObserver) have been removed
The onSuccess, onError, and onSettled callback functions were removed from options. (This does not apply to mutations.)</p>
<ul>
<li>Use global cache-level callbacks, which fire only once per query.
<ul>
<li>When you need to show a different message per query, use the <code>meta</code> field.</li>
</ul>
</li>
<li>Additional rendering cycles
<ul>
<li>When you manage the value with useState, a state can be rendered in the intermediate layer while the value is being synchronized.</li>
<li>Return the desired state value as an object instead.</li>
</ul>
</li>
<li>Instead of using a callback function that runs only when a fetch occurs, hook the actual data change into your deps.
<a href="https://tkdodo.eu/blog/breaking-react-querys-api-on-purpose">https://tkdodo.eu/blog/breaking-react-querys-api-on-purpose</a></li>
</ul>
