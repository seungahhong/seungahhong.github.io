23:T6f93,<h2 id="typescript-70-release-a-native-compiler-rewritten-in-go">TypeScript 7.0 Release: A Native Compiler Rewritten in Go<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#typescript-70-release-a-native-compiler-rewritten-in-go"><span class="icon icon-link"></span></a></h2>
<p>TypeScript 7.0 has been officially released. The heart of this major version is a <strong>complete native port of the compiler to Go</strong>. By moving <code>tsc</code> — written in JavaScript for over a decade — to native code, it achieves <strong>8–12x faster builds</strong> and <strong>up to 26% lower memory usage</strong> on large projects, while keeping type-checking fully compatible with prior versions.</p>

<h3 id="background-why-rewrite-in-go">Background: Why Rewrite in Go<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#background-why-rewrite-in-go"><span class="icon icon-link"></span></a></h3>
<p>TypeScript has always been implemented in JavaScript. That choice paid off in portability and ecosystem integration, but on large codebases, type-checking and build times increasingly became a bottleneck. The team decided to natively port the compiler to Go, targeting an <strong>order-of-magnitude performance increase</strong> rather than a small incremental gain.</p>
<p>The port was done "as faithfully as possible" — preserving the structure and logic of the original compiler while gaining the advantages of a native language:</p>
<ul>
<li><strong>Native code speed</strong> — a compiled Go binary runs faster than interpreted JavaScript.</li>
<li><strong>Shared-memory multithreading</strong> — type-checking and file processing can run in parallel, free of JavaScript's single-threaded event loop.</li>
<li><strong>Cross-platform optimization</strong> — Parcel's C++ file watcher was ported to idiomatic Go for better per-platform file watching.</li>
</ul>
<p>Despite being a new codebase, results remain consistent and compatible between the Go and original implementations.</p>

<h3 id="parallelization-flags">Parallelization Flags<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#parallelization-flags"><span class="icon icon-link"></span></a></h3>
<p>One of the biggest wins of the Go port is true multithreading, controlled by new flags.</p>
<h4 id="--checkers--type-checker-parallelization"><code>--checkers</code> — Type-Checker Parallelization<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#--checkers--type-checker-parallelization"><span class="icon icon-link"></span></a></h4>
<figure data-rehype-pretty-code-figure=""><pre tabindex="0" data-language="bash" data-theme="github-light-high-contrast github-dark-high-contrast"><code data-language="bash" data-theme="github-light-high-contrast github-dark-high-contrast" style="display: grid;"><span data-line=""><span style="--shiki-light:#66707B;--shiki-dark:#BDC4CC"># Default is 4 type-checking workers</span></span>
<span data-line=""><span style="--shiki-light:#702C00;--shiki-dark:#FFB757">tsc</span><span style="--shiki-light:#023B95;--shiki-dark:#91CBFF"> --checkers</span><span style="--shiki-light:#023B95;--shiki-dark:#91CBFF"> 8</span></span></code></pre></figure>
<ul>
<li>Default: 4 workers</li>
<li>Configurable from 1 to N (higher values increase memory usage)</li>
<li>Substantial speedups on multicore systems</li>
</ul>
<h4 id="--builders--project-reference-parallelization"><code>--builders</code> — Project Reference Parallelization<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#--builders--project-reference-parallelization"><span class="icon icon-link"></span></a></h4>
<figure data-rehype-pretty-code-figure=""><pre tabindex="0" data-language="bash" data-theme="github-light-high-contrast github-dark-high-contrast"><code data-language="bash" data-theme="github-light-high-contrast github-dark-high-contrast" style="display: grid;"><span data-line=""><span style="--shiki-light:#66707B;--shiki-dark:#BDC4CC"># Parallelize project-reference builds in a monorepo</span></span>

<ul>
<li>Works with <code>--build</code> (project references)</li>
<li>Multiplicative with <code>--checkers</code> — the example above allows up to 16 concurrent type-checkers.</li>
</ul>
<h4 id="--singlethreaded--single-threaded-mode"><code>--singleThreaded</code> — Single-Threaded Mode<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#--singlethreaded--single-threaded-mode"><span class="icon icon-link"></span></a></h4>
<figure data-rehype-pretty-code-figure=""><pre tabindex="0" data-language="bash" data-theme="github-light-high-contrast github-dark-high-contrast"><code data-language="bash" data-theme="github-light-high-contrast github-dark-high-contrast" style="display: grid;"><span data-line=""><span style="--shiki-light:#702C00;--shiki-dark:#FFB757">tsc</span><span style="--shiki-light:#023B95;--shiki-dark:#91CBFF"> --singleThreaded</span></span></code></pre></figure>
<p>Disables all parallelization for debugging, comparing against TypeScript 6, or resource-constrained environments.</p>
<h4 id="rebuilt-watch-mode">Rebuilt Watch Mode<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#rebuilt-watch-mode"><span class="icon icon-link"></span></a></h4>
<p><code>--watch</code> mode was rebuilt on a Go port of Parcel's file watcher. It addresses the limits of cross-platform file watching in Go's standard library and the overhead of pure polling, significantly reducing resource consumption during development cycles.</p>

<h4 id="javascript-support-reworked">JavaScript Support Reworked<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#javascript-support-reworked"><span class="icon icon-link"></span></a></h4>
<p><code>.js</code> analysis was streamlined for consistency with <code>.ts</code> handling. Key changes:</p>
<ul>
<li>Values can no longer stand in for types → use <code>typeof</code></li>
<li><code>@enum</code> is no longer auto-recognized</li>
<li>Standalone <code>?</code> is no longer a type → use <code>any</code></li>
<li><code>@class</code> no longer creates a constructor</li>
<li>Postfix <code>!</code> (non-null assertion) unsupported</li>
<li>Type names require <code>@typedef</code> tags (adjacent placement removed)</li>
<li>Closure-style function syntax and prototype reassignment special-handling removed</li>
</ul>

<p>TypeScript 7.0 adopts the new defaults introduced in TypeScript 6.0:</p>

<h4 id="removed-features-now-hard-errors">Removed Features (Now Hard Errors)<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#removed-features-now-hard-errors"><span class="icon icon-link"></span></a></h4>
<ul>
<li><code>target: es5</code> unsupported</li>
<li><code>downlevelIteration</code> removed</li>
<li><code>moduleResolution: node / node10</code> removed → use <code>nodenext</code> or <code>bundler</code></li>

<li>Namespace <code>module</code> keyword prohibited</li>

<li><code>skipDefaultLibCheck</code> no longer respects <code>/// &#x3C;reference no-default-lib /></code></li>
</ul>

<h3 id="editor--tooling">Editor &#x26; Tooling<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#editor--tooling"><span class="icon icon-link"></span></a></h3>
<h4 id="vs-code">VS Code<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#vs-code"><span class="icon icon-link"></span></a></h4>
<p>A dedicated <strong>TypeScript 7 extension</strong> is available in the Visual Studio Marketplace. It becomes the default on install and can be toggled via the command palette ("Disable/Enable TypeScript 7 Language Server").</p>
<h4 id="visual-studio">Visual Studio<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#visual-studio"><span class="icon icon-link"></span></a></h4>
<p>Recent versions automatically enable TypeScript 7 for workspaces based on configuration, with no manual step.</p>
<h4 id="lsp-based-language-server">LSP-Based Language Server<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#lsp-based-language-server"><span class="icon icon-link"></span></a></h4>
<p>The new language server is built on <strong>LSP (Language Server Protocol)</strong>, enabling multi-threaded request handling across editors. Features include auto-imports, expandable hovers, inlay hints, code lenses, go-to-source-definition, JSX linked editing and tag completions, semantic highlighting, sort imports, and remove-unused-imports.</p>
<h4 id="embedded-language-limitations">Embedded Language Limitations<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#embedded-language-limitations"><span class="icon icon-link"></span></a></h4>
<p>Vue, MDX, Astro, Svelte, and Angular templates can't yet leverage TypeScript 7 because it lacks a stable programmatic API; tools like Volar still depend on TypeScript 6.0. The recommended setup is <strong>TS 7 for the CLI, TS 6.0 for the editor</strong>. This limitation will be resolved by the 7.1 API support.</p>

<h3 id="wrap-up">Wrap-Up<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#wrap-up"><span class="icon icon-link"></span></a></h3>
<p>TypeScript 7.0 isn't just a feature bump — it's a <strong>foundational shift of the compiler's execution engine from JavaScript to Go</strong>. It delivers 8–12x faster builds and lower memory usage while keeping type-checking compatible.</p>
<p><strong>Key checklist:</strong></p>
<ul>
<li>✅ Install with <code>npm install -D typescript</code>, verify via <code>npx tsc --version</code></li>

<li>✅ Clean up removed options (<code>es5</code>, <code>baseUrl</code>, <code>node/node10</code>, <code>classic</code>, ...)</li>
<li>✅ Install <code>@typescript/typescript6</code> side-by-side for editors and embedded-language tooling</li>
<li>✅ Tune <code>--checkers</code> / <code>--builders</code> for parallelization on multicore machines</li>
