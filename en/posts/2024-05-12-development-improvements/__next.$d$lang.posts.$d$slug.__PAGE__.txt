<li>
<p><strong>Module fundamentals before explaining Tree Shaking</strong></p>
<ul>
<li>
<p>Problems that occurred back when JavaScript had no module management spec</p>
<pre><code>  - Hard to manage - to **load files with script tags**, you had to add each one manually,
  - Among countless code modules, cases where **global variables get overridden** also occurred
</code></pre>
<ul>
<li>
<p>The approaches to solve these problems were also all over the place - so certain libraries <strong>created their own module objects to use $</strong>, _</p>
</li>
<li>
<p><strong>Wrapping files in an IIFE</strong> to create them was also awkward to look at…</p>
</li>

<p>CommonJS - 2009</p>
<ul>
<li>
<p>From 2005 to 2009, with the birth of J-Query/AJAX, <strong>server-side operation</strong> beyond just the client</p>
</li>
<li>
<p>The <strong>module loader operates synchronously</strong> in order to be used as a way to load local files</p>
</li>
<li>
<p><strong>Directly accessing the file system, it can quickly load necessary modules or data locally</strong></p>
<ul>
<li><strong>Too much of a burden to use in a browser environment that operates asynchronously</strong></li>
</ul>

<li>Summary of the Loaders and Plugins measured for performance
<ul>
<li><strong>babel-loader</strong>
<ul>
<li>Converting ES6+ syntax into ES5 or lower code is called <strong>transpiling</strong>, and it's babel that does this. babel-loader is what integrates babel with webpack.</li>
</ul>
</li>
<li><strong>optimize-css-assets-webpack-plugin</strong>
<ul>
<li>If HtmlWebpackPlugin is the plugin that compresses html, optimize-css-assets-webpack-plugin is the plugin that compresses css.</li>

</li>

<ul>
<li>The series of tasks that convert the code we wrote into a lightweight version that provides the same functionality — such as mangling or compressing the code — is called minify or minification (code lightening), and the tool that performs code lightening is what we call a minifier. terser-webpack-plugin is a plugin that helps our JavaScript code be served in a more lightweight state in production.</li>
</ul>
</li>
<li><strong>css-loader, postcss-loader, sass-loader</strong>
<ul>
<li><strong>postcss-loader</strong>: A tool that transforms styles through js plugins.</li>

<li><strong>css-loader</strong>: Converts css files into js code.</li>
</ul>
</li>
<li><strong>IgnorePlugin</strong>
<ul>
<li>Sets the files to ignore during bundling with a regular expression or a filter function.</li>
</ul>
</li>
<li><strong>file-loader</strong>: Handles making files usable as modules. It moves the files actually used to the output directory.</li>
<li><strong>url-loader</strong>: Handles converting files into base64 urls. Rather than moving files, it converts and stores them in the output directory.</li>
</ul>
</li>

<h3 id="an-explanation-of-bundlers-before-explaining-esbuild-loader">An explanation of bundlers before explaining esbuild-loader<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#an-explanation-of-bundlers-before-explaining-esbuild-loader"><span class="icon icon-link"></span></a></h3>
<p>Bundler definition
A tool that gathers and combines the modules and resources (HTML, CSS, Javascript, Image, etc.) that make up a web application to create a single output.
Expected roles</p>
<ul>
<li>Modular</li>
<li>Transpiler</li>
<li>Obfuscation/compression</li>
<li>Other optimization features (module splitting, tree shaking)
Types of bundlers
<img src="/blog-assets/2024/05/assets/12/Untitled14.png" alt="Untitled"></li>
<li><strong>Webapck - 2014</strong>
<ul>
<li><strong>A static module bundler that provides development convenience features</strong></li>
<li><strong>Focused on managing large and complex applications</strong></li>
<li>Provides Tree-Shaking, code-splitting, and HMR features</li>
<li>v4 &#x3C;= supports only the cjs (commonjs) format, v5 (supports the esmodule format)</li>
</ul>
</li>
<li><strong>Rollup - 2015</strong>
<ul>
<li><strong>An esm-supporting module bundler focused on lightweighting and bundle optimization</strong></li>
<li><strong>Clear understanding of dependencies between modules through esmodule support → provides powerful Tree-shaking</strong></li>
<li>Provides Tree-Shaking, code-splitting, and HMR (rollup-plugin-hot) features</li>
</ul>
</li>
<li><strong>Parcel, zero-configuration - 2016</strong>
<ul>
<li>A bundler that can be used right away without complex configuration like webpack and Rollup</li>
<li>Limitations in fine-grained optimization and customization</li>
<li><strong>A bundler suitable for small and medium projects</strong></li>
</ul>
</li>
<li><strong>esbuild, the arrival of a 100x faster bundler - 2020</strong>
<ul>
<li><strong>Implemented in Go, a compiled language</strong></li>
<li><strong>Parallel processing tasks</strong></li>
<li><strong>Aggressive use of the CPU cache</strong></li>
<li><strong>However, many unsupported features exist</strong></li>
</ul>
</li>
<li><strong>Snowpack - 2019</strong>
<ul>
<li>Focused on the dev server, Unbundled Development that doesn't bundle all files → uses esbuild</li>
<li><strong>Rebuilds changed files, and does NOT bundle all files</strong></li>
<li><strong>Production build → choose webpack or rollup bundler</strong></li>
<li>However, in January 2021 it declared end of support → recommends using vite
<img src="/blog-assets/2024/05/assets/12/Untitled15.png" alt="Untitled"></li>
</ul>
</li>
<li><strong>Vite - 2020</strong>
<ul>
<li><strong>A frontend build tool that provides a dev server using ESM and a Rollup-optimized build command</strong>
<ul>
<li>dev environment: esbuild</li>
<li>production environment: rollup</li>
</ul>
</li>
<li><strong>Rebuilds changed files, and does NOT bundle all files</strong></li>

<img src="/blog-assets/2024/05/assets/12/Untitled16.png" alt="Untitled"></li>

<li>Improved compatibility with the web platform</li>

<ul>
<li>A feature that can load modules deployed across multiple servers

<h2 id="improving-package-installation-size-and-speed">Improving Package Installation, Size, and Speed<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#improving-package-installation-size-and-speed"><span class="icon icon-link"></span></a></h2>
<p>To improve package performance over the npm and yarn classic package managers, I selected the pnpm package manager and proceeded with improvements.</p>
<h3 id="an-explanation-of-package-managers-before-explaining-pnpm">An explanation of package managers before explaining pnpm<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#an-explanation-of-package-managers-before-explaining-pnpm"><span class="icon icon-link"></span></a></h3>
<p><strong>npm (January 2010)</strong></p>
<ul>
<li>Abbreviation of pkgmakeinst + node version → npm</li>
<li>package.json, dependencies → installs into node_modules</li>
<li>Provides custom scripts and the concept of public &#x26; private package registries
<strong>yarn classic (yarn 1.x, 2016)</strong></li>
<li>A package manager added to solve npm's consistency, security, and performance issues (abbreviation of Yet Another Resource Negotiator)</li>
<li>Native monorepo support, cache-aware installation</li>
<li>Offline caching, lock files</li>
<li>Entered maintenance mode in 2020 → yarn berry developed and improved
<strong>npm, yarn classic → duplicate storage of dependencies, phantom dependencies arising through hoisting</strong>
<img src="/blog-assets/2024/05/assets/12/Untitled18.png" alt="Untitled">
<strong>yarn berry, plug n play (January 2020)</strong></li>
<li>Zero Install → PnP approach
<ul>
<li>Organizes packages flatly (no phantom dependencies)</li>
<li>Manages packages as a Zip Archive File without installing node_modules packages</li>
<li>The advantage of being able to reduce size by managing as a Zip file rather than installing
<img src="/blog-assets/2024/05/assets/12/Untitled19.png" alt="Untitled"></li>
</ul>
</li>
<li>Apparently there are also about 3 downsides ㅜㅜ
<ul>
<li>Performance issues → since it re-runs the pnp approach on top of the yarn classic environment, performance doesn't miraculously get faster</li>
<li>Not all Dependencies can be managed as zip files
<ul>
<li>Dependencies that must operate with binary information about the current environment → packages like <em>swc, esbuild, sentry-cli</em> are tied to the shell, so they're managed in unplugged
<img src="/blog-assets/2024/05/assets/12/Untitled20.png" alt="Untitled"></li>
</ul>
</li>
<li>It's too heavy to carry all the zip files around under version control. - Even though they're compressed files, the dependency sizes are large, making management difficult. - When updating a Dependency, the number of changed files increases
<strong>pnpm (2017)</strong></li>
</ul>
</li>
<li>Fast and efficient disk management
<ul>
<li>Global store installation → connected via symbol link, hard link</li>
<li>Organizes packages flatly (no phantom dependencies)
<img src="/blog-assets/2024/05/assets/12/Untitled21.png" alt="Untitled"></li>
</ul>
</li>
</ul>
<h3 id="pnpm-explanation"><a href="https://seungahhong.github.io/blog/2024/03/2024-03-18-pnpm/">pnpm explanation</a><a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#pnpm-explanation"><span class="icon icon-link"></span></a></h3>
<h3 id="reasons-for-choosing-pnpm">Reasons for choosing pnpm<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#reasons-for-choosing-pnpm"><span class="icon icon-link"></span></a></h3>
<ul>
<li>Besides the npm and yarn classic package managers, the better options are yarn berry and pnpm.</li>
<li>Reasons for choosing pnpm
<ul>
<li>If you place packages in a global store and connect them via symbolic and hard links, the installation speed can become faster after the initial build.</li>
<li>Since it manages packages flatly in node_modules and does not pull packages up through hoisting, packages not added to package.json are not installed at the 1st depth of node_modules, so phantom dependencies can be resolved.</li>
</ul>
</li>
<li>Reasons for not choosing yarn berry
<ul>
<li>Even if managed as zip files, if there were packages tied to the binary environment, zero install is impossible.</li>
<li>When managing packages under version control, it's hard to grasp too many changes when installing/removing/modifying packages.</li>
</ul>
</li>
</ul>
