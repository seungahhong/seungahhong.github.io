10:Tcbac,<h2 id="the-background-behind-the-emergence-of-global-state-management-libraries">The Background Behind the Emergence of Global State Management Libraries<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#the-background-behind-the-emergence-of-global-state-management-libraries"><span class="icon icon-link"></span></a></h2>
<p>When React was first released, it was announced as a library responsible only for the View portion of Model-View-Controller. As a result, a way to compose and manage state became necessary. In the early days, development proceeded by cramming state and business logic into a Container/Presenter and simply passing View logic down as props to render it.</p>
<p>However, as applications grew in scale, the number of states to manage and the number of components handling those states increased within the bidirectional MVC/MVP structure, making the architecture more complex. In addition, because logic was processed in a parent and passed down to children via props, the props drilling problem arose. To solve these issues, global state management libraries emerged.</p>
<p><img src="/blog-assets/2023/09/assets/10/Untitled.png" alt="Untitled"></p>
<h3 id="the-problems-global-state-management-libraries-aim-to-solve">The Problems Global State Management Libraries Aim to Solve<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#the-problems-global-state-management-libraries-aim-to-solve"><span class="icon icon-link"></span></a></h3>
<p><strong>The ability to read stored state from anywhere in the component tree</strong></p>
<ul>
<li>Inside the React runtime
<ul>
<li>To propagate shared values, it combines with React context and leverages features such as <code>useState</code>, <code>useRef</code>, or <code>useReducer</code> → the main challenge here is that you have to carefully consider how to handle re-render optimization.</li>
</ul>
</li>
<li>Leveraging module state outside of React
<ul>
<li>Using module state stores state in a manner similar to a singleton.</li>
<li>It is easy to optimize so that re-rendering occurs only when the state changes, via subscription.</li>
<li>However, because it is a single value in memory, it cannot hold a different state that is used only in a different subtree.</li>
</ul>
</li>
</ul>
<p><img src="/blog-assets/2023/09/assets/10/Untitled1.png" alt="Untitled"></p>
<p><strong>The ability to modify stored state</strong></p>
<ul>
<li>The React UI model supports reference equality and immutable updates, but JavaScript is a mutable language.</li>
<li>In the case of Redux, this was solved by adopting an approach where all state updates are immutable, but this introduced the drawback of a lot of boilerplate code.
<ul>
<li>However, if you use immer, which helps you write mutable-style code, you can improve the code.</li>
</ul>
</li>
<li>These days, libraries such as valtio (js proxy) have also emerged, allowing developers to use a mutable style.</li>
</ul>
<p><img src="/blog-assets/2023/09/assets/10/Untitled2.png" alt="Untitled"></p>
<p><strong>A mechanism to optimize rendering</strong></p>
<ul>
<li><strong>Manual optimization:</strong> This often means creating selector functions that subscribe to a specific piece of state. The advantage here is that the user can finely control the subscription method and optimize how components subscribing to that state re-render. The downside is that one could argue this is a manual process that is error-prone and requires unnecessary overhead that should not be part of the API.
<ul>
<li>redux: useSelector, recoil: useRecoilState, jotai: useAtom</li>
</ul>
</li>
<li><strong>Automatic optimization:</strong> This is where the library automatically optimizes the process so that only what the user needs is re-rendered. The advantage here, of course, is that it is easy to use and lets the user focus on feature development without having to worry about manual optimization. The downside of this is that, as a consumer, the optimization process is a black box, and if there is no way to manually optimize a part of it, it can feel too magical.
<ul>
<li>Valtio internally uses <code>Proxy</code> to automatically track when updates occur and automatically manage when components need to re-render.</li>
</ul>
</li>
</ul>
<p><img src="/blog-assets/2023/09/assets/10/Untitled3.png" alt="Untitled"></p>
<p><strong>Provides a mechanism to optimize memory usage</strong></p>
<ul>
<li>State management that stores state outside the React runtime as module state
<ul>
<li>This means it is not tied to a specific component and may have to be managed manually (redux).</li>
</ul>
</li>
<li>State management that stores state inside the React runtime
<ul>
<li>Tying it to the React lifecycle makes it easier to leverage automatic garbage collection when a component is unmounted.
<ul>
<li>context api, recoil, jotai</li>
</ul>
</li>
</ul>
</li>
</ul>
<p><img src="/blog-assets/2023/09/assets/10/Untitled4.png" alt="Untitled"></p>
<p><strong>New trends in global state management libraries and patterns (the emergence of the bottom-up approach)</strong></p>
<ul>
<li>Top-down approach: state management solutions up to and including Redux
<ul>
<li>An approach where the Store at the top of the component tree holds all the necessary state, and lower components pull the state they need from it.</li>
</ul>
</li>
<li>Bottom-up approach
<ul>
<li>With the arrival of React hooks, it became known that composing hooks with small pieces of state or logic to manage even complex state could be useful. As the bottom-up approach was discussed, stores came to be held at the granularity of atoms.</li>
<li>An approach where, when an atom changes, the components subscribing to that atom re-render.</li>
<li>recoil, jotai</li>
</ul>
</li>
</ul>
<p><img src="/blog-assets/2023/09/assets/10/Untitled5.png" alt="Untitled"></p>
<p><strong>Component-centric applications vs. data-centric applications</strong></p>
<p><img src="/blog-assets/2023/09/assets/10/Untitled6.png" alt="Untitled"></p>
<p><strong>Libraries built specifically to solve the problem of remote state management</strong></p>
<ul>
<li>For most web applications, which are CRUD-style applications, a dedicated remote state management library</li>
<li>Handling things such as request deduplication, retries, polling, and mutations
<ul>
<li>Includes <a href="https://react-query.tanstack.com/overview">React query</a>, <a href="https://github.com/vercel/swr">SWR</a>, <a href="https://www.apollographql.com/">Apollo</a>, <a href="https://relay.dev/">Relay</a>,  <a href="https://redux-toolkit.js.org/introduction/getting-started#rtk-query">RTK Query</a></li>
</ul>
</li>
</ul>
<h2 id="summary-of-state-management-libraries">Summary of State Management Libraries<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#summary-of-state-management-libraries"><span class="icon icon-link"></span></a></h2>
<p><img src="/blog-assets/2023/09/assets/10/Untitled7.png" alt="Untitled"></p>
<p><strong>State management trends</strong></p>
<p><img src="/blog-assets/2023/09/assets/10/Untitled8.png" alt="Untitled"></p>
<p><a href="https://npmtrends.com/jotai-vs-mobx-vs-recoil-vs-redux-vs-valtio-vs-xstate-vs-zustand">https://npmtrends.com/jotai-vs-mobx-vs-recoil-vs-redux-vs-valtio-vs-xstate-vs-zustand</a></p>
<h3 id="contextapi">ContextAPI<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#contextapi"><span class="icon icon-link"></span></a></h3>
<p>Suitable for use when handling mostly static data or when updates do not occur frequently.</p>
<p>It is inefficient when handling complex updates, and the reason is that <strong>re-rendering occurs even for state that has not been updated within the portion wrapped by the Provider.</strong></p>
<h3 id="flux-redux-zustand">Flux (Redux, Zustand)<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#flux-redux-zustand"><span class="icon icon-link"></span></a></h3>
<p><img src="/blog-assets/2023/09/assets/10/Untitled9.png" alt="Untitled"></p>
<p>Based on a state store called the <strong>Store</strong>, when you <strong>pass an Action type to a Reducer</strong>, the state value is updated according to the operation matching that type, and components use a <strong>Selector</strong> to <strong>subscribe</strong> to <strong>the state value they need</strong> from the Store.</p>
<p><strong>When used with the purpose of separating business logic from React components</strong></p>
<ul>
<li><a href="https://seungahhong.github.io/blog/2021/12/2021-12-30-redux/">Redux</a>, <a href="https://seungahhong.github.io/blog/2022/03/2022-03-26-redux-toolkit/">Redux-Toolkit</a>
<ul>
<li>Redux has only one store and a single object tree, which makes debugging easy.</li>
<li>The internal state of the store can only be changed via action objects. Because all state changes are concentrated in a single store and occur in one direction, the results are predictable.</li>
<li>Because a reducer is a pure function, it returns a new state rather than mutating the state.</li>
<li>It has the drawback of a lot of boilerplate code, but redux-toolkit was created to address that issue.</li>
</ul>
</li>
<li><a href="https://seungahhong.github.io/blog/2023/07/2023-07-22-zustand/">Zustand</a>
<ul>
<li>The way stores are implemented and modified is simple (less boilerplate code compared to redux).</li>
<li>There is no need to wrap it with a Provider.</li>
<li>It provides various middleware libraries (redux, immer, selector (automatically invoked on state change), redux-devtools).</li>
</ul>
</li>
</ul>
<h3 id="atomic-recoil-jotai">Atomic (Recoil, Jotai)<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#atomic-recoil-jotai"><span class="icon icon-link"></span></a></h3>
<p><img src="/blog-assets/2023/09/assets/10/recoil.jpeg" alt="Untitled"></p>
<p><img src="/blog-assets/2023/09/assets/10/Untitled10.png" alt="Untitled"></p>
<ul>
<li><a href="https://seungahhong.github.io/blog/2022/06/2022-06-14-jotai/">jotai</a>
<ul>
<li>Version updates happen about once a month, with fast new features and bug fixes (to the point where there are no open PRs).</li>
<li>Very small in size compared to Recoil.</li>
<li>Based on TypeScript.</li>
<li>You don't need to generate a unique key value (internally it uses a weakMap).</li>
<li>Supports suspense.</li>
<li>Powerful devtool.</li>
</ul>
</li>
<li><a href="https://seungahhong.github.io/blog/2022/03/2022-03-22-recoil/">recoil</a>
<ul>
<li>Developed by Facebook.</li>
<li>Because it uses internal React state rather than state as an "external factor" to React, it can access the scheduler.</li>
<li>It provides a snapshot feature, allowing you to revert to a previous state value.</li>
<li>persist: recoil-persist
<ul>
<li>The reason for including a key when creating an atom (a unique key enables debugging and persistence).</li>
</ul>
</li>
<li>The update cycle is long. 🥶</li>
</ul>
</li>
</ul>
<h3 id="proxy-mobx-valtio-overmind">Proxy (MobX, Valtio, overmind)<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#proxy-mobx-valtio-overmind"><span class="icon icon-link"></span></a></h3>

<p>A pattern that gathers the entire state (Proxy) and provides access, automatically detecting some of the state used in a component and recognizing updates.</p>
<ul>
<li>Valtio
<ul>
<li>Uses Hooks for its rendering optimization approach.</li>

</ul>
</li>
</ul>

<h3 id="xstate">XState<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#xstate"><span class="icon icon-link"></span></a></h3>
<ul>
<li>A library that uses a technical pattern to organize complex, tangled code with the limited structure and a few constraints of an FSM (Finite State Machine). It is used when behavior must differ depending on specific states, since complexity increases dramatically as the number of states grows.</li>
<li>In particular, since complex state changes and flows can be diagrammed as a flowchart, it enables efficient communication when collaborating with development stakeholders.</li>
</ul>
<p><img src="/blog-assets/2023/09/assets/10/Untitled13.png" alt="Untitled"></p>
<ul>
<li>
<p>In general, an FSM consists of five parts. (<a href="https://xstate.js.org/docs/about/concepts.html#finite-state-machines">documentation</a>)</p>
<ul>
<li>
<p>An <strong>initial state</strong></p>
</li>
<li>
<p>A finite number of <strong>states</strong></p>
</li>
<li>
<p>A finite number of <strong>events</strong></p>
</li>
<li>
<p>A <strong>transition function</strong> that determines the next state given the current state and event</p>
</li>
<li>
<p>A (possibly empty) set of <strong>final states</strong></p>
</li>
<li>

<h2 id="so-when-should-you-use-state-management">So... when should you use state management??<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#so-when-should-you-use-state-management"><span class="icon icon-link"></span></a></h2>
<h3 id="npm-state-management-trends---redux--react-query-">npm state management trends -> redux 👍, react-query 👍<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#npm-state-management-trends---redux--react-query-"><span class="icon icon-link"></span></a></h3>
<ul>
<li>
<p>client state: redux > zustand > XState > mobx > jotai > recoil > valtio</p>
</li>
<li>
<p>server state: react-query > swr</p>
</li>
</ul>
<h3 id="handling-mostly-static-data-when-updates-do-not-occur-frequently--context-api-">Handling mostly static data, when updates do not occur frequently → context API 👍<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#handling-mostly-static-data-when-updates-do-not-occur-frequently--context-api-"><span class="icon icon-link"></span></a></h3>
<h3 id="bottom-up-approach-optimizing-memory-usage-when-using-only-the-react-ecosystem--jotai-">Bottom-up approach, optimizing memory usage, when using only the React ecosystem → jotai 👍<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#bottom-up-approach-optimizing-memory-usage-when-using-only-the-react-ecosystem--jotai-"><span class="icon icon-link"></span></a></h3>
<ul>
<li>recoil: because it uses internal React state rather than state as an "external factor" to React, it can access the scheduler (Facebook's own library).</li>
<li>jotai: TypeScript-based, very small in size compared to Recoil, no unique key required.</li>
</ul>
<h3 id="top-down-approach-when-data-must-be-shared-across-many-modules--redux-">Top-down approach, when data must be shared across many modules → redux 👍<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#top-down-approach-when-data-must-be-shared-across-many-modules--redux-"><span class="icon icon-link"></span></a></h3>
<ul>
<li>Redux: provides various middleware libraries; the most widely used library.</li>
<li>zustand: no Provider wrapping required, smaller in size/amount of code than redux.</li>
</ul>
<h3 id="when-you-want-to-use-automatic-optimization-proxy--valtio--mobx">When you want to use automatic optimization (proxy) → valtio 👍, mobx<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#when-you-want-to-use-automatic-optimization-proxy--valtio--mobx"><span class="icon icon-link"></span></a></h3>
<ul>
<li>valtio: supports React hooks.</li>
<li>mobx uses object-oriented components and hoc-style functions, and supports decorators.</li>
</ul>
<h3 id="when-communication-through-flowchart-diagrams-is-important--xstate-">When communication through flowchart diagrams is important → XState 👍<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#when-communication-through-flowchart-diagrams-is-important--xstate-"><span class="icon icon-link"></span></a></h3>
<h3 id="when-you-need-to-use-server-state-management--react-query--swr">When you need to use server state management → react-query 👍, swr<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#when-you-need-to-use-server-state-management--react-query--swr"><span class="icon icon-link"></span></a></h3>
<ul>
<li>react-query: makes it easy to fetch, cache, synchronize, and update server state in a React application. It additionally provides graphql support.</li>
<li>swr: a strategy that first returns data from the cache, then sends a request to fetch data from the server, and finally provides the up-to-date data. It is easy to set up in a Next.js environment.</li>
</ul>
<h3 id="when-you-are-in-a-graphql-development-environment--apollo-client-">When you are in a GraphQL development environment → Apollo Client 👍<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#when-you-are-in-a-graphql-development-environment--apollo-client-"><span class="icon icon-link"></span></a></h3>
