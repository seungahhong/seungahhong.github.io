<p><a href="https://nextjs.org/blog/next-14#forms-and-mutations"><strong>Server Actions (Stable)</strong></a></p>
<ul>
<li>Next.js has been upgraded to the latest React, which includes Server Actions from React's Canary release.</li>
<li>For performance-heavy actions such as mutating data, re-rendering a page, or redirecting, you can present the client user with a screen that reflects the corresponding state.</li>
<li><a href="https://nextjs.org/blog/next-14#caching-revalidating-redirecting-and-more"><strong>Caching, Revalidating, Redirecting, and more</strong></a>
<ul>
<li>As Server Actions are integrated with the app router, the following APIs are available.</li>
<li>Revalidate cached data with <code>revalidatePath()</code> or <code>revalidateTag()</code></li>
<li>Redirect to different routes through <code>redirect()</code></li>
<li>Set and read cookies through <code>cookies()</code></li>
<li>Handle optimistic UI updates with <code>useOptimistic()</code></li>
<li>Catch and display errors from the server with <code>useFormState()</code></li>
<li>Display loading states on the client with <code>useFormStatus()</code></li>
</ul>
</li>
</ul>

<li>
<p>Metadata Improvements
The viewport, colorScheme, and themeColor information that affects the user experience has been separated from the existing Metadata type and must now be defined separately.
Sending viewport data together with the page content lets you avoid layout shifts or flickering caused by theme color changes or viewport changes.</p>
<ul>
<li><strong>viewport</strong> : Sets the initial zoom and other properties of the viewport.</li>
<li><strong>colorScheme</strong> : Sets the supported modes (light/dark) of the viewport.</li>
<li><strong>themeColor</strong> : Sets the color that the chrome surrounding the viewport will render.
The properties that used to be defined in the existing meta can be added using <a href="https://nextjs.org/docs/app/api-reference/functions/generate-viewport"><code>viewport</code> and <code>generateViewport</code></a>. (Use the static field: viewport; use the runtime dynamic field: generateViewport.)</li>
</ul>
