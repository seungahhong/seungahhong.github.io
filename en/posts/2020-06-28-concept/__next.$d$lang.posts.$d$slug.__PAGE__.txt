f:T2165f,<h2 id="client-side-storage">Client-Side Storage<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#client-side-storage"><span class="icon icon-link"></span></a></h2>
<h3 id="cookies">Cookies<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#cookies"><span class="icon icon-link"></span></a></h3>
<ul>
<li>Once a cookie is set, every subsequent web request is sent to the server including the cookie information</li>
<li>Stores strings only, with a 4KB size limit</li>
<li>Typically used to record visited pages or to store a user's login information</li>
<li>Session cookies: cookies without an expiration date (they last only while the browser tab is open)</li>
<li>Persistent cookies: cookies that have an expiration date (used, for example, to track a user's activity on a website)</li>
</ul>

<h3 id="localstorage">localstorage<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#localstorage"><span class="icon icon-link"></span></a></h3>
<ul>
<li>Can store strings only</li>
<li>You can work around the string-only limitation by converting JSON data into a string and storing it</li>
<li>Data persists even after the browser is closed</li>
<li>Local storage cannot be accessed across different domains</li>
<li>Size limits vary by browser and device (browser: 5MB–10MB, mobile: 2.5MB)</li>
</ul>

<h3 id="sessionstorage">sessionstorage<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#sessionstorage"><span class="icon icon-link"></span></a></h3>
<ul>
<li>Can store strings only</li>
<li>You can work around the string-only limitation by converting JSON data into a string and storing it</li>
<li>Stored separately for each session (e.g., stored per tab, released individually when the session ends)</li>
<li>Cannot be accessed from a different session even within the same domain</li>
<li>Size limits vary by browser and device (browser: 5MB–10MB, mobile: 2.5MB)</li>
<li>Its usage is identical to localstorage.</li>
</ul>

<p>In this way, you create a new function that has received only some of the arguments, and later complete it by passing the remaining arguments to the new function.</p>
<h3 id="partial-application">Partial application<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#partial-application"><span class="icon icon-link"></span></a></h3>
<p>It's a technique for creating a function with some of its arguments fixed when you have a function that takes multiple arguments.</p>
<h3 id="the-concept-of-currying">The concept of currying<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#the-concept-of-currying"><span class="icon icon-link"></span></a></h3>
<p>Currying is named after the mathematician Haskell Curry, and it refers to the process of transforming a function.
It's a way of creating a simpler function by pre-filling some of the function's arguments.
Like partial application, currying lets you fix arguments in advance, but its distinguishing feature is that it fixes them only one at a time. In addition, it keeps generating functions until all arguments have been received.
You can also view it as a series of partial applications that each fix one argument at a time.</p>
<h3 id="when-to-use-currying">When to use currying<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#when-to-use-currying"><span class="icon icon-link"></span></a></h3>
<p>If most of the arguments are almost always similar whenever you call a certain function, it's a good candidate for currying.
When you dynamically create a new function by applying some of the arguments, that dynamically created function internally stores the repeatedly used arguments, so that without passing those arguments every time, it fulfills the functionality the original function expects.</p>

<h2 id="web-worker">web worker<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#web-worker"><span class="icon icon-link"></span></a></h2>
<p>Web Worker
In JavaScript, using a web worker enables multithreading (for reference). A web worker lets you run script execution on a separate background thread rather than on the main thread.</p>
<p>When you create a worker object on the main thread, you can communicate with the worker thread through messages. If you request the execution of a time-consuming task from the worker thread via postMessage, the worker thread runs it. This prevents the main thread from being blocked. When the worker thread finishes the task, it likewise sends a completion result message via postMessage, which allows the main thread to move on to another task.</p>

<h3 id="callbindapply">call/bind/apply<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#callbindapply"><span class="icon icon-link"></span></a></h3>
<h4 id="differences-between-call-apply-and-bind">Differences between call, apply, and bind<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#differences-between-call-apply-and-bind"><span class="icon icon-link"></span></a></h4>
<p>call() and apply() were added in ECMA 3, while bind() was added in ECMA 5.
call() and apply() are invocations. They call the function immediately.
bind() is used when the function will be executed later. It's useful when you need to call a function on a specific event.</p>
<h4 id="call">call<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#call"><span class="icon icon-link"></span></a></h4>

<li>Explanation
When you create a Person object, Person.prototype is created. And Person.prototype.constructor points to Person. Then, if you make Employee.prototype reference Person.prototype, its constructor would also point to Person, so you change it back to Employee so that it can point to itself. And the newly created kim object points to Employee.prototype. Therefore, kim.proto points to Employee.prototype.</li>

When you use the <code>new</code> keyword before a function object, it becomes a constructor, and the object created with it is called an instance. In the image above, kim is an instance of the Person object.</p>
<h4 id="the-difference-between-proto-and-prototype">The difference between <strong>proto</strong> and prototype<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#the-difference-between-proto-and-prototype"><span class="icon icon-link"></span></a></h4>
<ul>
<li>
<p><strong>proto</strong></p>
<ul>
<li>The <strong>proto</strong> property is a property that every object has.</li>
<li>When an object is created, it points to the prototype of the object that created it.</li>
</ul>
</li>
<li>
<p>prototype</p>
<ul>
<li>A prototype that only function objects have</li>
<li>It refers to the prototype that a created instance points to.</li>
</ul>
</li>
</ul>
<h4 id="prototype-chain">Prototype Chain<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#prototype-chain"><span class="icon icon-link"></span></a></h4>
<p>The end of every prototype chain is always Object.prototype. That's why Object.prototype has no <strong>proto</strong> property.</p>

<h4 id="pure-functions-immutability-first-class-objects">Pure functions, immutability, first-class objects<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#pure-functions-immutability-first-class-objects"><span class="icon icon-link"></span></a></h4>
<p>First-Class Object (or first-class citizen)</p>
<ul>
<li>A first-class object is an object that satisfies the following conditions
<ul>
<li>It can be held in a variable or data structure.</li>
<li>It can be passed as a parameter.</li>
<li>It can be used as a return value.</li>
<li>Properties can be assigned to it dynamically.</li>
</ul>
</li>
</ul>
<p>Higher-Order Function</p>
<ul>
<li>A term originating from lambda calculus, referring to a function that satisfies the conditions below
<ul>
<li>A function can be passed to it as a parameter.</li>
<li>A function can be used as its return value.</li>
</ul>
</li>
</ul>
<p>Immutability</p>
<ul>
<li>In functional programming, data cannot change, and this is called immutable data. (JavaScript allows mutation, but there are languages where it's not possible.)</li>
<li>When data needs to change, instead of altering the original data structure, you make a copy of that data, change part of it, and proceed with your work using the modified copy.</li>
</ul>

<p>Pure Function</p>
<ul>
<li>A pure function is a concept needed for functional programming, referring to a function that satisfies the conditions below.
<ul>
<li>The function's return value is determined solely by its input argument values</li>
<li>A function with no side effects</li>
<li></li>
</ul>
