b:T35bb2,<h2 id="overview">Overview<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#overview"><span class="icon icon-link"></span></a></h2>
<p>React 19 introduces a number of new features and improvements that enhance the developer experience, simplify common patterns, and boost performance. Below is a summary along with the key changes and code examples.</p>
<h2 id="whats-new-in-react-19">What’s new in React 19<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#whats-new-in-react-19"><span class="icon icon-link"></span></a></h2>
<h3 id="actions">Actions<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#actions"><span class="icon icon-link"></span></a></h3>
<p>A common use case in React apps is to perform a data mutation and then update the state based on the response.</p>
<p>In the past, pending, state, and optimistic updates had to be managed sequentially as separate pieces of state, but with the introduction of Actions this can now be handled automatically.</p>

<h3 id="react-server-components-and-server-actions">React Server Components and Server Actions<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#react-server-components-and-server-actions"><span class="icon icon-link"></span></a></h3>
<ul>
<li>Server Components
An option that lets you pre-render components in an environment separate from the client application or the SSR server.
One common misconception, though: the use server directive is only used in server actions, not in server components.</li>
<li>Server Actions
They let client components call asynchronous functions that execute on the server.</li>

<h3 id="support-for-document-metadata">Support for Document Metadata<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#support-for-document-metadata"><span class="icon icon-link"></span></a></h3>
<ul>
<li>Overview
Built-in support was added for rendering <a href="https://react.dev/reference/react-dom/components/title"><strong><code>&#x3C;title></code></strong></a>, <a href="https://react.dev/reference/react-dom/components/meta"><strong><code>&#x3C;meta></code></strong></a>, and <strong>metadata</strong> <a href="https://react.dev/reference/react-dom/components/link"><strong><code>&#x3C;link></code></strong></a> tags anywhere in the component tree.
It works in both server and client components, meaning that functionality pioneered by libraries such as <strong>React Helmet</strong>, which were already in use, has been brought in-house.
However, if you need to override generic metadata with route-specific metadata based on the current path, you will still need to use a library such as React Helmet.</li>

<h3 id="errors-in-render-are-not-re-thrown">Errors in render are not re-thrown<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#errors-in-render-are-not-re-thrown"><span class="icon icon-link"></span></a></h3>
<p>React 19 introduces new capabilities for fine-grained control over error handling.</p>
<p>You can now adjust how errors are handled using the onCaughtError and onUncaughtError options on the createRoot and hydrateRoot methods.</p>
<p>The existing problem</p>
<p>Previously, even when you caught errors using an Error Boundary, the errors were still printed to the console via console.error.</p>
<p>As a result, developers saw unnecessary error messages even though the errors had been handled properly, which could cause confusion during development.</p>
<p>Improvements in React 19</p>
<p>React 19 provides a way to control error handling more granularly.</p>
<p>Using the onCaughtError and onUncaughtError options of createRoot and hydrateRoot, you can override the default behavior of printing error messages to the console.</p>
<p>onCaughtError is used to handle errors caught by an Error Boundary.</p>
