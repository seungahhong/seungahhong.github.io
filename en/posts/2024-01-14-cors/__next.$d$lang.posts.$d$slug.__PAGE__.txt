10:T1539d,<h2 id="overview">Overview<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#overview"><span class="icon icon-link"></span></a></h2>
<p>CORS (Cross-Origin Resource Sharing) is a mechanism that tells the browser whether it is allowed to access resources from a different origin (origin: protocol, host, port).</p>
<p>When you load a resource from a different origin, access is restricted unless the correct CORS headers are included.</p>
<p><img src="/blog-assets/2024/01/assets/14/Untitled.png" alt="Untitled"></p>
<p><img src="/blog-assets/2024/01/assets/14/Untitled1.png" alt="Untitled"></p>
<h2 id="cors-use-cases">CORS Use Cases<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#cors-use-cases"><span class="icon icon-link"></span></a></h2>
<ul>
<li><a href="https://developer.mozilla.org/ko/docs/Web/API/XMLHttpRequest">XMLHttpRequest</a> and <a href="https://developer.mozilla.org/ko/docs/Web/API/Fetch_API">Fetch API</a> calls.</li>
<li>Web fonts (when using cross-domain fonts via @font-face in CSS), <a href="https://www.w3.org/TR/css-fonts-3/#font-fetching-requirements">so that servers can deploy TrueType fonts that can only be cross-site loaded and used by web sites that are permitted to do so.</a></li>
<li><a href="https://developer.mozilla.org/ko/docs/Web/API/WebGL_API/Tutorial/Using_textures_in_WebGL">WebGL textures</a>.</li>
<li>Images/video frames drawn onto a canvas using <a href="https://developer.mozilla.org/en-US/docs/Web/API/CanvasRenderingContext2D/drawImage">drawImage() (en-US)</a>.</li>
<li><a href="https://developer.mozilla.org/en-US/docs/Web/CSS/CSS_shapes/Shapes_from_images">CSS Shapes extracted from images. (en-US)</a></li>
</ul>
<h2 id="lets-reproduce-it-simply-cross-origin-get-method">Let's Reproduce It Simply (Cross-Origin GET Method)<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#lets-reproduce-it-simply-cross-origin-get-method"><span class="icon icon-link"></span></a></h2>
<ul>
<li>If you run two servers on ports 4000 and 4001, and then call <a href="http://localhost:3000/cors">http://localhost:3000/cors</a>, the HTML file calls <a href="http://localhost:4001/response.json">http://localhost:4001/response.json</a>. Because these are not the same origin, a CORS error occurs as shown in the image below.</li>
<li>To determine whether a cross-origin resource is allowed, the browser checks the Access-Control-Allow-Origin attribute value in the server's response. Since the response headers below do not include any allowed origin, a CORS error occurs.</li>
</ul>

<h2 id="simple-requests">Simple requests<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#simple-requests"><span class="icon icon-link"></span></a></h2>
<p><img src="/blog-assets/2024/01/assets/14/Untitled4.png" alt="Untitled"></p>
<p>As in the example above, a request for which the browser only checks the cross-origin attribute is called a simple request, and some requests do not trigger a <a href="https://developer.mozilla.org/ko/docs/Glossary/Preflight_request">CORS preflight</a>. A simple request is one that satisfies all of the conditions below.</p>
<ul>
<li>One of the following methods
<ul>
<li><a href="https://developer.mozilla.org/ko/docs/Web/HTTP/Methods/GET">GET</a></li>
<li><a href="https://developer.mozilla.org/ko/docs/Web/HTTP/Methods/HEAD">HEAD</a></li>
<li><a href="https://developer.mozilla.org/ko/docs/Web/HTTP/Methods/POST">POST</a></li>
</ul>
</li>
<li>Apart from the headers automatically set by the user agent (for example, <a href="https://developer.mozilla.org/ko/docs/Web/HTTP/Headers/Connection">Connection</a>, <a href="https://developer.mozilla.org/en-US/docs/Web/HTTP/Headers/User-Agent">User-Agent (en-US)</a>, and <a href="https://fetch.spec.whatwg.org/#forbidden-header-name">the headers defined as "forbidden header name" in the Fetch spec</a>), the only headers that may be set manually are <a href="https://fetch.spec.whatwg.org/#cors-safelisted-request-header">those defined as "CORS-safelisted request-header" in the Fetch spec</a>.
<ul>
<li><a href="https://developer.mozilla.org/ko/docs/Web/HTTP/Headers/Accept">Accept</a></li>
<li><a href="https://developer.mozilla.org/ko/docs/Web/HTTP/Headers/Accept-Language">Accept-Language</a></li>
<li><a href="https://developer.mozilla.org/ko/docs/Web/HTTP/Headers/Content-Language">Content-Language</a></li>
<li><a href="https://developer.mozilla.org/ko/docs/Web/HTTP/Headers/Content-Type">Content-Type</a> (note the additional requirements below.)</li>
</ul>
</li>
<li>The <a href="https://developer.mozilla.org/ko/docs/Web/HTTP/Headers/Content-Type">Content-Type</a> header allows only the following values.
<ul>
<li>application/x-www-form-urlencoded</li>
<li>multipart/form-data</li>
<li>text/plain</li>
</ul>
</li>
</ul>
<p><strong>Solution</strong></p>
<p>The server sends the origin that is allowed to use the resource back to the client via Access-Control-Allow-Origin, and the browser checks the allowed origin address so that it can use the server's resource.</p>

<h2 id="preflight-request">Preflight request<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#preflight-request"><span class="icon icon-link"></span></a></h2>
<p><strong>Unsafe requests</strong></p>
<p>In the past, browsers were not expected to send API requests using anything other than GET and POST. So when later-introduced methods such as PATCH, DELETE, and PUT are called, the browser assumes the request may not have originated from itself and checks the access permission. The mechanism used to check that access permission is called a preflight request.</p>
<p><img src="/blog-assets/2024/01/assets/14/Untitled6.png" alt="Untitled"></p>
<p>When there is a preflight request, it uses the OPTIONS method, includes two headers, and has an empty body.</p>
<p>A preflight request uses the OPTIONS method, includes two headers, and has an empty body.</p>
<ul>
<li>Access-Control-Request-Method header – contains the method information used in the unsafe request.</li>
<li>Access-Control-Request-Headers header – contains the list of headers used in the unsafe request. Each header is separated by a comma.</li>
</ul>
<p>If the server agrees to allow the unsafe request, it sends a response with an empty body and status code 200 to the browser, together with headers such as the following.</p>
<ul>
<li>Access-Control-Allow-Origin – must be the origin that sent the request.</li>
<li>Access-Control-Allow-Methods – contains the allowed method information.</li>
<li>Access-Control-Allow-Headers – contains the list of allowed headers.</li>
<li>Access-Control-Max-Age – specifies how many seconds the permission check result should be cached. Once the permission information is cached, the browser can skip the preflight request for a certain period and send the unsafe request directly.</li>
</ul>

<h2 id="accessing-unsafe-headers-expose-headers">Accessing Unsafe Headers (Expose-Headers)<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#accessing-unsafe-headers-expose-headers"><span class="icon icon-link"></span></a></h2>
<p>To access unsafe response headers using JavaScript, the server must add and send a header called Access-Control-Expose-Headers.</p>
<p>Once it is added to the headers, the client can access it through the response headers.</p>
<p>So, which headers are safe?</p>
<ul>
<li>Cache-Control, Content-Language, Content-Length, Content-Type, Expires, Last-Modified, Pragma</li>
</ul>
<p>For access to headers other than those above, the server must add the header before the client can access it.</p>

<h2 id="credentials">Credentials<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#credentials"><span class="icon icon-link"></span></a></h2>
<p>When you send a cross-origin request with JavaScript, credentials such as cookies or HTTP authentication are not sent along by default. So to send credential information via cookies, you need to add the credential setting to the header when sending the request.</p>
<p>For credentials, you can add the corresponding attribute to the options, such as fetch (credentials: "include") or axios (withCredentials: true).</p>
<p>To handle CORS for this attribute, the server must set the Access-Control-Allow-Credentials attribute to true.</p>
<p>Note that when there is a request that carries credentials, you cannot use a wildcard (*) as the value of the Access-Control-Allow-Origin attribute.</p>
