4:T15818,<h2 id="개요">개요<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#개요"><span class="icon icon-link"></span></a></h2>
<p>CORS(교차 출처 리소스 공유)는 다른 출처(origin:프로토콜, 호스트, 포트)출처의 자원을 접근할 수 있도록 알려주는 것을 것을 뜻한다.</p>
<p>다른 출처의 리소스를 불러올 때 올바를 CORS 헤더를 포함하지 않는다면 접근이 제한됨을 뜻합니다.</p>
<p><img src="/blog-assets/2024/01/assets/14/Untitled.png" alt="Untitled"></p>
<p><img src="/blog-assets/2024/01/assets/14/Untitled1.png" alt="Untitled"></p>
<h2 id="cors-사용-사례">CORS 사용 사례<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#cors-사용-사례"><span class="icon icon-link"></span></a></h2>
<ul>
<li><a href="https://developer.mozilla.org/ko/docs/Web/API/XMLHttpRequest">XMLHttpRequest</a>와 <a href="https://developer.mozilla.org/ko/docs/Web/API/Fetch_API">Fetch API</a> 호출.</li>
<li>웹 폰트(CSS 내 @font-face에서 교차 도메인 폰트 사용 시), <a href="https://www.w3.org/TR/css-fonts-3/#font-fetching-requirements">so that servers can deploy TrueType fonts that can only be cross-site loaded and used by web sites that are permitted to do so.</a></li>
<li><a href="https://developer.mozilla.org/ko/docs/Web/API/WebGL_API/Tutorial/Using_textures_in_WebGL">WebGL 텍스쳐</a>.</li>
<li><a href="https://developer.mozilla.org/en-US/docs/Web/API/CanvasRenderingContext2D/drawImage">drawImage() (en-US)</a>를 사용해 캔버스에 그린 이미지/비디오 프레임.</li>
<li><a href="https://developer.mozilla.org/en-US/docs/Web/CSS/CSS_shapes/Shapes_from_images">이미지로부터 추출하는 CSS Shapes. (en-US)</a></li>
</ul>
<h2 id="간단하게-재현해보자다른-출처-get-메서드">간단하게 재현해보자(다른 출처 GET 메서드)<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#간단하게-재현해보자다른-출처-get-메서드"><span class="icon icon-link"></span></a></h2>
<ul>
<li>서버를 4000, 4001 포트로 해서 2개를 띄운 이후에 <a href="http://localhost:3000/cors">http://localhost:3000/cors</a> 호출한다면 html 파일에서 <a href="http://localhost:4001/response.json">http://localhost:4001/response.json</a> 호출하게 되고 동일 출처가 아니라서 아래 이미지와 같이 CORS에러가 발생합니다.</li>
<li>브라우저는 교차 출처에 리소스 자원 허용을 확인하기 위해서는 서버 응답에 Access-Control-Allow-Origin 속성값을 확인하게 되는데, 아래 응답 헤더에서는 따로 허용 출처가 없기 때문에 CORS가 발생하게 됩니다.</li>
</ul>

<h2 id="simple-requests단순요청">Simple requests(단순요청)<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#simple-requests단순요청"><span class="icon icon-link"></span></a></h2>
<p><img src="/blog-assets/2024/01/assets/14/Untitled4.png" alt="Untitled"></p>
<p>위에 예제처럼 교차 출처(origin) 속성만 브라우저가 확인하는 요청을 단순요청이라고 하며, 일부 요청은 <a href="https://developer.mozilla.org/ko/docs/Glossary/Preflight_request">CORS preflight</a> 트리거를 하지 않습니다. 해당 단순 요청은 아래 조건을 모두 충족하는 요청입니다.</p>
<ul>
<li>다음 중 하나의 메서드
<ul>
<li><a href="https://developer.mozilla.org/ko/docs/Web/HTTP/Methods/GET">GET</a></li>
<li><a href="https://developer.mozilla.org/ko/docs/Web/HTTP/Methods/HEAD">HEAD</a></li>
<li><a href="https://developer.mozilla.org/ko/docs/Web/HTTP/Methods/POST">POST</a></li>
</ul>
</li>
<li>유저 에이전트가 자동으로 설정 한 헤더 (예를들어, <a href="https://developer.mozilla.org/ko/docs/Web/HTTP/Headers/Connection">Connection</a>, <a href="https://developer.mozilla.org/en-US/docs/Web/HTTP/Headers/User-Agent">User-Agent (en-US)</a>, <a href="https://fetch.spec.whatwg.org/#forbidden-header-name">Fetch 명세에서 "forbidden header name"으로 정의한 헤더</a>)외에, 수동으로 설정할 수 있는 헤더는 오직 <a href="https://fetch.spec.whatwg.org/#cors-safelisted-request-header">Fetch 명세에서 "CORS-safelisted request-header"로 정의한 헤더</a> 뿐입니다.
<ul>
<li><a href="https://developer.mozilla.org/ko/docs/Web/HTTP/Headers/Accept">Accept</a></li>
<li><a href="https://developer.mozilla.org/ko/docs/Web/HTTP/Headers/Accept-Language">Accept-Language</a></li>
<li><a href="https://developer.mozilla.org/ko/docs/Web/HTTP/Headers/Content-Language">Content-Language</a></li>
<li><a href="https://developer.mozilla.org/ko/docs/Web/HTTP/Headers/Content-Type">Content-Type</a> (아래의 추가 요구 사항에 유의하세요.)</li>
</ul>
</li>
<li><a href="https://developer.mozilla.org/ko/docs/Web/HTTP/Headers/Content-Type">Content-Type</a> 헤더는 다음의 값들만 허용됩니다.
<ul>
<li>application/x-www-form-urlencoded</li>
<li>multipart/form-data</li>
<li>text/plain</li>
</ul>
</li>
</ul>
<p><strong>해결방안</strong></p>
<p>서버는 자원을 제공하는 출처를 Access-Control-Allow-Origin 설정해서 클라이언트에 응답으로 보내주게 되며, 브라우저가 허용 출처 주소를 확인해서 서버 자원 사용이 가능하게 됩니다.</p>

<h2 id="사전-전달-요청preflight-request">사전 전달 요청(Preflight request)<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#사전-전달-요청preflight-request"><span class="icon icon-link"></span></a></h2>
<p><strong>안전하지 않은 요청</strong></p>
<p>과거에는 GET, POST 외에는 브라우저에서 API 요청을 보낼 거라고 생각을 못했었기 때문에, 추후에 등장한 PATCH, DELETE, PUT 같은 메서드 호출 시 브라우저가 보낸 것이 아니라고 판단해서 접근 권한을 확인하게 됩니다. 해당 접근 권한을 확인할 때 사용하는 것이 사전 전달 요청이라고 합니다.</p>
<p><img src="/blog-assets/2024/01/assets/14/Untitled6.png" alt="Untitled"></p>
<p>사전 전달 요청이 있는 경우에는 options 메서드를 사용하고 두 헤더가 함께 들어가며, 본문은 비어 있습니다.</p>
<p>preflight 요청은 OPTIONS 메서드를 사용하고 두 헤더가 함께 들어가며, 본문은 비어있습니다.</p>
<ul>
<li>Access-Control-Request-Method 헤더 – 안전하지 않은 요청에서 사용하는 메서드 정보가 담겨있습니다.</li>
<li>Access-Control-Request-Headers 헤더 – 안전하지 않은 요청에서 사용하는 헤더 목록이 담겨있습니다. 각 헤더는 쉼표로 구분됩니다.</li>
</ul>
<p>안전하지 않은 요청을 허용하기로 협의하였다면 서버는 본문이 비어있고 상태 코드가 200인 응답을 다음과 같은 헤더와 함께 브라우저로 보냅니다.</p>
<ul>
<li>Access-Control-Allow-Origin – 요청을 보낸 오리진 이어야 합니다</li>
<li>Access-Control-Allow-Methods – 허용된 메서드 정보가 담겨있습니다.</li>
<li>Access-Control-Allow-Headers – 허용된 헤더 목록이 담겨있습니다.</li>
<li>Access-Control-Max-Age – 퍼미션 체크 여부를 몇 초간 캐싱해 놓을지를 명시합니다. 이렇게 퍼미션 정보를 캐싱해 놓으면 브라우저는 일정 기간 동안 preflight 요청을 생략하고 안전하지 않은 요청을 보낼 수 있습니다.</li>
</ul>

<h2 id="안전하지-않는-헤더-접근expose-headers">안전하지 않는 헤더 접근(Expose-Headers)<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#안전하지-않는-헤더-접근expose-headers"><span class="icon icon-link"></span></a></h2>
<p>자바스크립트를 사용해 안전하지 않은 응답 헤더에 접근하려면 서버에서 Access-Control-Expose-Headers라는 헤더를 추가해서 보내줘야합니다.</p>

<p>그렇다면 안전한 헤더는 어떤게 있을까요??</p>
<ul>
<li>Cache-Control, Content-Language, Content-Length, Content-Type, Expires, Last-Modified, Pragma</li>
</ul>

<h2 id="자격-증명credential">자격 증명(Credential)<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#자격-증명credential"><span class="icon icon-link"></span></a></h2>
<p>자바스크립트로 크로스 오리진 요청을 보내는 경우, 기본적으로 쿠키나 HTTP 인증 같은 자격 증명(credential)이 함께 전송되지 않기 때문에, 자격 증명 정보를 쿠키에 보내기 위해서는 자격 증명 설정을 header에 추가해서 보내줘야합니다.</p>
<p>자격 증명도 options에 속성으로 fetch(creidentials: “include”), axios(withCredentials: true) 추가해서 보내주면 됩니다.</p>
<p>해당 속성에 대한 CORS 대응을 위해서는 서버에서는 Access-Control-Allow-Credentials 속성을 true로 설정해줘야 합니다.</p>
<p>단, 자격 증명이 함께 전송된는 요청이 있는 경우에는 Access-Control-Allow-Origin 속성값에 와일드 카드(*)를 사용할 수 없습니다.</p>
