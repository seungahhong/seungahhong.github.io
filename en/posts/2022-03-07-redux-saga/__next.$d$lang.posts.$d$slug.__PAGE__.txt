10:T1c22a,<h3 id="what-is-redux-saga">What is redux-saga?<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#what-is-redux-saga"><span class="icon icon-link"></span></a></h3>
<p>A middleware library whose purpose is to make handling side effects in React/Redux applications easier and cleaner.</p>
<h3 id="installation">Installation<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#installation"><span class="icon icon-link"></span></a></h3>
<pre><code>npm install redux-saga typesafe-actions
</code></pre>
<h5 id="installing-typesafe-actions-v5--optional">Installing typesafe-actions (v5) → optional<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#installing-typesafe-actions-v5--optional"><span class="icon icon-link"></span></a></h5>
<p>This is a TypeScript library similar to redux-actions. It lets you write and use action creators and reducers more conveniently.</p>
<p><strong>Sample code</strong></p>
<p><a href="https://github.com/seungahhong/states-todos">GitHub - seungahhong/states-todos</a></p>

<h4 id="side-effect">Side Effect<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#side-effect"><span class="icon icon-link"></span></a></h4>
<p>When you use Redux in real-world projects, actions are dispatched simultaneously and in quick succession. In the middle of these actions, plain logic that isn't an actual Redux action gets executed, or server requests such as Ajax calls occur. When you use thunk, this logic can become complicated.</p>
<p><strong>Ajax calls</strong></p>
<p><strong>Async timers</strong></p>
<p><strong>Callbacks after animations</strong></p>
<p><strong>Cancellation during a request</strong></p>
<p><strong>Throttling</strong></p>
<p><strong>Debouncing</strong></p>
<p><strong>Page navigation</strong></p>
<p>These are a bit difficult to express with the ordinary Redux action flow, and for asynchronous work you have to keep a reference to the dispatch function somewhere and call it when needed.</p>
<p>If you use Redux-Saga, these side effects can be solved fairly simply and intuitively.</p>

<p>Saga follows a structure of a Watcher that subscribes to actions and a Worker that performs the actual work.</p>
<ul>
<li><strong>Watcher</strong>
<ul>
<li><strong>watcher function</strong></li>
</ul>
</li>
<li><strong>Worker</strong>
<ul>
<li><strong>loadUser</strong></li>
<li><strong>loadFollowers</strong></li>
<li><strong>loadPoint</strong></li>
</ul>
</li>
</ul>
<p>First, define all the worker functions that will handle the actions. There are three: loadUser, loadFollowers, and loadPoint. Then define the watcher function that acts as the manager, and once you define the execution inside that function, you're done.</p>
<p>I'll explain more later, but the takeXXX family of functions watch for specific action(s), and put is the function that actually dispatches an action. It is the same as Redux's dispatch function. (In Saga, these are called Saga-Effects. I'll explain them later.)</p>

<h3 id="take">take<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#take"><span class="icon icon-link"></span></a></h3>
<p>Blocks and waits until the action passed as an argument arrives.</p>
<ul>
