<h3 id="changes-by-package">Changes by Package<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#changes-by-package"><span class="icon icon-link"></span></a></h3>
<h4 id="nodejs-v26120-current--v24220-lts">Node.js v26.12.0 (Current) · v24.22.0 (LTS)<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#nodejs-v26120-current--v24220-lts"><span class="icon icon-link"></span></a></h4>
<p>The JavaScript runtime for servers.</p>
<p><strong>What changed</strong> — The Current line's v26.12.0 adds <code>websocketMask()</code>/<code>websocketUnmask()</code> to HTTP, loads most ES modules synchronously, moves <code>process.finalization</code> to RC stage and the config file feature to stable. SQLite now throws an exception instead of crashing on oversized strings, and bugs in <code>AbortSignal.any()</code> leaks and querystring decoding are fixed. The LTS v24.22.0 adds <code>crypto.parsePKCS12()</code>, a general MAC API, SIV/GCM-SIV cipher modes, <code>util.throttle</code>/<code>util.debounce</code> and SQLite <code>StatementSync.close()</code>, and fixes an HTTP/2 write deadlock and a Windows <code>rmSync</code> issue. npm is bumped to 11.19.1. Neither release note lists a CVE.</p>
<p><strong>What to check when upgrading</strong> — v26.12.0 now throws an exception in environments without WebAssembly or RX support (a semver-minor item), so check any service running in such an environment. In v24.22.0, non-FIPS WebCrypto paths are disabled in FIPS mode (the US government cryptography certification standard), and <code>Server.prototype._listen2</code> in <code>net</code> and the HTTP/2 <code>aborted</code> property are marked deprecated (scheduled for removal).</p>
<p>Release notes: <a href="https://github.com/nodejs/node/releases/tag/v26.12.0">v26.12.0</a> · <a href="https://github.com/nodejs/node/releases/tag/v24.22.0">v24.22.0</a></p>
<h4 id="zed-v1242--v1233">Zed v1.24.2 · v1.23.3<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#zed-v1242--v1233"><span class="icon icon-link"></span></a></h4>
<p>A fast code editor written in Rust.</p>
<p><strong>What changed</strong> — v1.24.2 adds a Git tag creation command, dragging terminal tabs into the Agent Panel, <code>file_finder.prefill_query_from_selection</code> to prefill the file finder from selected text, a Go test button, Markdown/Mermaid font settings, Gerrit/Gitiles permalinks and custom Amazon Bedrock model configuration. The Linux x86_64 binary is about 23% smaller and starts faster, and a crash while editing inlay hints, broken Linux emoji fonts and a hang in remote project search are fixed. v1.23.3 is a patch for the previous stable line that fixes the Markdown preview font, worktree handling in edit predictions and the Threads Sidebar transparent background, updates Node.js to the latest v24 LTS, and adds opt-in telemetry for the agent checkpoint feature that runs only with consent.</p>
<p><strong>What to check when upgrading</strong> — No breaking changes are listed. This release is fine to upgrade to as is.</p>
<p>Release notes: <a href="https://github.com/zed-industries/zed/releases/tag/v1.24.2">v1.24.2</a> · <a href="https://github.com/zed-industries/zed/releases/tag/v1.23.3">v1.23.3</a></p>
<h4 id="pnpm-v12140--v11286--v10347">pnpm v12.14.0 · v11.28.6 · v10.34.7<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#pnpm-v12140--v11286--v10347"><span class="icon icon-link"></span></a></h4>
<p>A Node.js package manager.</p>
<p><strong>What changed</strong> — The 12.x line had four minor releases this week. v12.14.0 adds a <code>sideEffectsCache.exclude</code> setting to drop packages from the build cache when their cache key can't be built because they depend on system libraries, and <code>pnpm install</code> skips the daily update check if it finishes first. v12.13.0 adds the <code>pnpm profile</code> and <code>pnpm token</code> commands and a <code>storeIndexFormat: files</code> setting for network file systems, and v12.12.x adds a remote cache for task results and dependency builds, an <code>addMissingPeerTypes</code> setting, <code>pnpm dist-tag</code> with OIDC authentication and a <code>tool:</code> protocol for download tools. v11.28.6 is a security fix: <code>pnpm publish</code> now uses a CI identity token only when its audience (the target the token is meant for) matches the destination registry. v10.34.7 is a patch that makes switching to the pnpm version named in <code>packageManager</code> work even when a mirror strips or re-signs npm signatures.</p>
<p><strong>What to check when upgrading</strong> — The notes mark no breaking change, but since 12.12.x <code>pnpm publish</code> checks the token audience against the registry, so if you publish from CI with a token, confirm publishing still works after upgrading.</p>
<p>Release notes: <a href="https://github.com/pnpm/pnpm/releases/tag/v12.14.0">v12.14.0</a> · <a href="https://github.com/pnpm/pnpm/releases/tag/v11.28.6">v11.28.6</a> · <a href="https://github.com/pnpm/pnpm/releases/tag/v10.34.7">v10.34.7</a></p>
<h4 id="electron-v4490--v4480--v4380--v421115">Electron v44.9.0 · v44.8.0 · v43.8.0 · v42.11.15<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#electron-v4490--v4480--v4380--v421115"><span class="icon icon-link"></span></a></h4>
<p>A platform for building desktop apps with web technology.</p>
<p><strong>What changed</strong> — v44.9.0 adds an app shim on macOS to show a window under another app's Dock icon, makes windows opened via a link use the opener's session and <code>webPreferences</code>, and makes <code>setCertificateVerifyProc</code> apply to requests sent at the same time as the first one. v44.8.0 adds Linux notification action buttons and fixes <code>net.fetch</code> failing after a Network Service restart, lost <code>utilityProcess</code> messages and <code>win.isFullScreen()</code> returning a stale value on Windows, and updates to Chromium 152.0.7977.167 and Node.js v24.22.0. v43.8.0 and v42.11.15 are backport patches fixing Linux GTK crashes, missed background clicks on macOS, <code>net.fetch</code> failures and lost <code>utilityProcess</code> messages.</p>
<p><strong>What to check when upgrading</strong> — There are no breaking changes. Apps that use certificate verification (<code>setCertificateVerifyProc</code>) should check its behavior once.</p>
<p>Release notes: <a href="https://github.com/electron/electron/releases/tag/v44.9.0">v44.9.0</a> · <a href="https://github.com/electron/electron/releases/tag/v44.8.0">v44.8.0</a> · <a href="https://github.com/electron/electron/releases/tag/v43.8.0">v43.8.0</a> · <a href="https://github.com/electron/electron/releases/tag/v42.11.15">v42.11.15</a></p>
<h4 id="oxfmt-v0730">Oxfmt v0.73.0<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#oxfmt-v0730"><span class="icon icon-link"></span></a></h4>
<p>A JavaScript/TypeScript formatter.</p>
<p><strong>What changed</strong> — The <code>associations</code> setting lets you specify a language per file path, and Astro support (LSP, <code>prettier-plugin-astro</code>, <code>--migrate prettier</code>) and display of LSP root config errors are added. A new TOML formatter crate is included, and symlinked config file discovery, CSS-in-JS placeholder handling and <code>export default</code> line breaks are fixed.</p>
<p><strong>What to check when upgrading</strong> — The behavior of <code>--migrate prettier</code> (the feature that moves your Prettier config over) changed and is marked breaking, so recheck the result if you have already migrated a config.</p>
<p>Release notes: <a href="https://github.com/oxc-project/oxc/releases/tag/oxfmt_v0.73.0">oxfmt_v0.73.0</a></p>
<h4 id="oxlint-v1880">Oxlint v1.88.0<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#oxlint-v1880"><span class="icon icon-link"></span></a></h4>
<p>A JavaScript/TypeScript linter.</p>
<p><strong>What changed</strong> — The LSP now shows config errors to the client, and the <code>prefer-query-selector</code> rule gains an <code>allowWithVariables</code> option. <code>sort-keys</code> now uses the same natural sort as ESLint, and <code>prefer-bigint-literals</code> no longer auto-fixes when precision would be lost. Fixes also make it follow symlinked configs and set stderr to blocking.</p>
<p><strong>What to check when upgrading</strong> — Two changes to how comment positions are stored (the AST) are marked breaking, but they affect users who use the parser API directly. If you only use the linter, just check whether <code>sort-keys</code> results change.</p>

<h4 id="ubuntu-2610-stonking-stingray">Ubuntu 26.10 Stonking Stingray<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#ubuntu-2610-stonking-stingray"><span class="icon icon-link"></span></a></h4>
<p>A Linux distribution (an interim release, not LTS).</p>
<p><strong>What changed</strong> — It brings GNOME 51, a redesigned App Center, dbus-broker (the default D-Bus implementation), Linux kernel 7.3 (Intel Xe3P, AMD Zen 6 and NVIDIA 615 support), the optional offline on-device speech recognition agent Myna, and Microsoft Entra ID integration. The toolchain is updated to ROCm 10.0, LLVM 22.1.6, GCC 15.2.0, Python 3.14.7, Rust 1.97.1 and Go 1.27. On security it adds Sequoia PGP-based APT repository signature verification (preparing for post-quantum signatures), openCryptoki integration with ML-DSA and ML-KEM, and TPM-based full-disk encryption (with an optional PIN/passphrase) usable on devices without a hardware root of trust.</p>
<p><strong>What to check when upgrading</strong> — The post lists no breaking changes or deprecations. However, existing components are being replaced, such as GnuPG by Sequoia PGP and the completed move to Rust-based coreutils, so check the impact of those.</p>
