The conference was held on Thursday, October 24 → Next.js Conf
<a href="https://nextjs.org/conf">Next.js Conf by Vercel</a></p>

<h2 id="summary">Summary<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#summary"><span class="icon icon-link"></span></a></h2>
<ul>
<li>Internet Explorer has been dropped from the list of supported browsers, and support has shifted to <a href="https://nextjs.org/docs/basic-features/supported-browsers-features">modern browsers</a>.
<ul>
<li>Chrome 64+</li>
<li>Edge 79+</li>
<li>Firefox 67+</li>
<li>Opera 51+</li>
<li>Safari 12+</li>
</ul>
</li>
<li>The minimum Node version has been raised to 18.18.x and above.</li>
<li>The minimum React version has been raised to react and react-dom 19.
<ul>
<li>useFormState → renamed to useActionState</li>
<li><a href="https://react.dev/blog/2024/04/25/react-19-upgrade-guide">https://react.dev/blog/2024/04/25/react-19-upgrade-guide</a></li>
</ul>
</li>
</ul>
<h2 id="key-features">Key Features<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#key-features"><span class="icon icon-link"></span></a></h2>
<ul>
<li>
<p><a href="https://nextjs.org/blog/next-15#smooth-upgrades-with-nextcodemod-cli">Smooth upgrades with @next/codemod CLI</a>
Provides a codemod that automatically upgrades Next.js major versions.</p>
<figure data-rehype-pretty-code-figure=""><pre tabindex="0" data-language="bash" data-theme="github-light-high-contrast github-dark-high-contrast"><code data-language="bash" data-theme="github-light-high-contrast github-dark-high-contrast" style="display: grid;"><span data-line=""><span style="--shiki-light:#702C00;--shiki-dark:#FFB757">npx</span><span style="--shiki-light:#032563;--shiki-dark:#ADDCFF"> @next/codemod@canary</span><span style="--shiki-light:#032563;--shiki-dark:#ADDCFF"> upgrade</span><span style="--shiki-light:#032563;--shiki-dark:#ADDCFF"> latest</span></span></code></pre></figure>
</li>
<li>
<p><a href="https://nextjs.org/blog/next-15#async-request-apis-breaking-change">Async Request APIs (Breaking Change)</a>
Previously, SSR waited for all data before rendering the content. Because it was determined that not every component needs to wait for all of the server data, the existing synchronous APIs have been converted to asynchronous APIs.
With this shift to asynchronous APIs, you now need to await the async API response when requesting data.</p>

</li>
<li>
<p><a href="https://nextjs.org/blog/next-15#caching-semantics">Caching Semantics</a>
The default caching policy (<a href="https://x.com/feedthejim/status/1785242054773145636">caching heuristics</a>) that had previously been introduced by default to improve performance has been changed, so the caching defaults for Route Handlers and the Client Router Cache are now set to not cache.
GET Route Handlers and the Client Router Cache are no longer cached by default.</p>

<li>
<p><a href="https://nextjs.org/blog/next-15#react-19">React 19</a>
With confidence in the stability of the React 19 RC after extensive testing, the decision was made to adopt it in Next.js v15.
A <a href="https://nextjs.org/blog/next-15#smooth-upgrades-with-codemod-cli">codemod</a> is provided to make the transition seamless.
Pages Router on React 18</p>
<ul>
<li>In the Pages Router (as opposed to the App Router), React 18 can still be used as-is to maintain backward compatibility.
React Compiler (Experimental)</li>
<li>This is a React compiler created by Meta's React team, and support for it has been added in Next.js 15.
It reduces the amount of manual memoization code (useMemo, useCallback) that developers previously had to write, making the code simpler and easier to maintain.</li>
<li></li>
</ul>
</li>
<li>
<p><a href="https://nextjs.org/blog/next-15#turbopack-dev">Turbopack Dev</a>
The <code>next dev --turbo</code> command approach has now stabilized and become faster.</p>
<ul>
<li>Local server startup is up to <strong>76.7% faster.</strong></li>
<li>Code updates via Fast Refresh are up to <strong>96.3% faster.</strong></li>
<li>Initial route compilation without caching is up to <strong>45.8% faster.</strong></li>
</ul>
</li>
<li>
<p><a href="https://nextjs.org/blog/next-15#static-route-indicator">Static Route Indicator</a>
Next.js now displays a static route indicator during development, helping you identify which routes are static or dynamic.
<img src="/blog-assets/2024/11/assets/23/image.png" alt="image.png"></p>
</li>

next.config.ts is supported to provide type safety and autocompletion.</p>

<li>
<p><a href="https://nextjs.org/blog/next-15#eslint-9-support">ESLint 9 Support</a>
As an alternative to ESLint 8, whose support ends on October 5, 2024, Next.js 15 now supports ESLint 9. (The <code>-ext</code> option is not supported → apparently ESLint 10 is heading in a direction that no longer allows the legacy configuration.)
However, ESLint 8 is also still supported to maintain backward compatibility.</p>
</li>
<li>
<p><a href="https://nextjs.org/blog/next-15#development-and-build-improvements">Development and Build Improvements</a>
Server Components HMR</p>
<ul>
<li>As part of improving HMR performance, previous rendering responses are reused, improving fetch development performance to reduce the cost of API calls.
Faster Static Generation for the App Router</li>
<li>The logic that previously rendered twice for static optimization has been reduced to a single render.</li>
<li>The fetch cache is shared across static pages.</li>
</ul>
