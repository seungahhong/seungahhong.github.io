1d:T6c78,<h3 id="why-webassembly-emerged">Why WebAssembly Emerged<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#why-webassembly-emerged"><span class="icon icon-link"></span></a></h3>
<p>Various attempts to bring native machine code to the web and to execute it quickly—such as Google's <a href="https://developer.chrome.com/native-client">NaCI</a>(Native Client) and Mozilla's <a href="http://asmjs.org/">asm.js</a>(a subset of JavaScript)—eventually converged into WebAssembly (hereafter referred to as 'wasm'), which is where its development began.</p>
<p>In December 2019, the W3C officially recommended wasm—currently at <a href="https://webassembly.github.io/spec/core/">version 1.1</a>—as the fourth language of the web, following HTML, CSS, and JavaScript.</p>
<h3 id="how-webassembly-runs">How WebAssembly Runs<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#how-webassembly-runs"><span class="icon icon-link"></span></a></h3>
<p>The execution process of JavaScript code and wasm within a JavaScript engine</p>
<ul>
<li>The compiled binary-format wasm module does not replace JavaScript or run inside JavaScript; instead, it runs side by side with JavaScript within the JavaScript engine.</li>
</ul>
<p><img src="/blog-assets/2022/01/assets/08/Untitled.png" alt="Untitled"></p>
<p>Emscripten takes C/C++ code, passes it through LLVM, and converts the LLVM-generated bytecode into JavaScript (specifically Asm.js, a subset of JavaScript).</p>
<p>WASM generation process</p>
<ul>
<li>C, C++ → [Clang tool (LLVM) → LLVM bytecode generation → Asm.js conversion]: Emscripten</li>
</ul>
<p><img src="http://i.imgur.com/1yoy1Fal.png" alt="http://i.imgur.com/1yoy1Fal.png"></p>
<p>The evolution of Emscripten</p>
<ol>
<li>wasm compilation was handled on the backend by <a href="https://github.com/emscripten-core/emscripten-fastcomp/">fastcomp</a>(LLVM plus Emscripten's asm.js backend)</li>
<li>C/C++ is compiled into an intermediate representation (IR)</li>
<li>It is then compiled into asm.js via fastcomp</li>
<li>A compilation pipeline that leads to wasm using <a href="https://github.com/WebAssembly/binaryen/blob/master/src/asm2wasm.h">asm2wasm</a></li>
</ol>
<p><img src="/blog-assets/2022/01/assets/08/Untitled3.png" alt="Untitled3"></p>
<p>The V8 team announced that they achieved performance improvements across many areas by making the native LLVM wasm backend the default pipeline in Emscripten, bypassing the unnecessary asm.js compilation step.</p>
<p><a href="https://twitter.com/v8js/status/1145704863377981445">https://twitter.com/v8js/status/1145704863377981445</a></p>
<h3 id="why-use-wasm">Why Use wasm?<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#why-use-wasm"><span class="icon icon-link"></span></a></h3>
<p>The step-by-step workflow of the JavaScript engine</p>
<p><img src="/blog-assets/2022/01/assets/08/Untitled1.png" alt="Untitled"></p>
<h4 id="fetching">Fetching<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#fetching"><span class="icon icon-link"></span></a></h4>
<p>The process of loading the module/code to be executed</p>
<p>⇒ Since wasm is a binary file, its loading speed is improved even when JavaScript is minified and mangled.</p>
<h4 id="parse">Parse<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#parse"><span class="icon icon-link"></span></a></h4>
<p>The process of parsing the downloaded source code so that the interpreter can understand it</p>
<p>JavaScript: JS → AST → generates bytecode the JavaScript engine can understand → execution</p>
<p>WSAM: intermediate representation via LLVM (asm.js) → decoding, error checking → execution</p>
<h4 id="compile--optimize">Compile + Optimize<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#compile--optimize"><span class="icon icon-link"></span></a></h4>
<ul>
<li>The process of compilation through the baseline and optimizing compilers</li>
</ul>
<p>JavaScript: compilation happens simultaneously during execution via the <a href="https://en.wikipedia.org/wiki/Just-in-time_compilation">JIT</a>(Just-In-Time) compiler</p>
<p><img src="/blog-assets/2022/01/assets/08/Untitled2.png" alt="Untitled"></p>
<p>WSAM</p>
<ol>
<li>wasm itself is close to machine code and uses explicit types (the <a href="https://webassembly.github.io/spec/core/syntax/types.html">four primitive types</a> composed of 32-bit and 64-bit Float and Integer - f32, f64, i32, i64)</li>
<li>No type checking is performed during JS engine compilation</li>
<li>Since many optimizations have already been applied through LLVM, there is little need to do heavy work during compilation and optimization.</li>
</ol>
<h4 id="re-optimize">Re-optimize<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#re-optimize"><span class="icon icon-link"></span></a></h4>
<p>The readjustment process of re-optimizing when the JIT compiler's prediction turns out to be wrong, or of discarding the optimized code and falling back to the baseline code</p>
<ul>
<li>When a variable's type differs from the previous iteration, requiring re-optimization</li>
<li>WSAM: since it is already optimized and requires no type checking, the re-optimization cycle is unnecessary</li>
</ul>
<h4 id="execute">Execute<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#execute"><span class="icon icon-link"></span></a></h4>
<p>Execution of the code</p>
<p>WSAM: designed to target the compiler, so it outputs compiler-optimized results</p>
<p>JavaScript: whether optimized code is used depends on the developer's skill</p>
<h4 id="gc">GC<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#gc"><span class="icon icon-link"></span></a></h4>
<p>The process of freeing memory regions that were allocated but are no longer used</p>
<p>WSAM: since memory allocation and deallocation are handled explicitly, GC is unnecessary.</p>
<p>Other improvements</p>
<p>Expanded memory usage (2GB -> 4GB)</p>
<p>Data sharing (data sharing between web workers → ShareArrayBuffer),</p>
<p>→ IPC communication is possible using C++ pthread</p>

<h4 id="additional-notes">Additional Notes<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#additional-notes"><span class="icon icon-link"></span></a></h4>
<p>Yew:</p>
<p>A modern <a href="https://www.rust-lang.org/">Rust</a> framework for building multi-threaded front-end web apps using <a href="https://webassembly.org/">WebAssembly</a></p>
<p>Minimizes DOM API calls</p>
<p>wasm_bindgen</p>
<p>js engine ↔ WebAssembly can only support numeric types (added to support other types beyond that)</p>
<p>The JavaScript file serves as the interface used when calling Rust</p>
<figure data-rehype-pretty-code-figure=""><pre tabindex="0" data-language="rust" data-theme="github-light-high-contrast github-dark-high-contrast"><code data-language="rust" data-theme="github-light-high-contrast github-dark-high-contrast" style="display: grid;"><span data-line=""><span style="--shiki-light:#0E1116;--shiki-dark:#F0F3F6">export function </span><span style="--shiki-light:#622CBC;--shiki-dark:#DBB7FF">greet</span><span style="--shiki-light:#0E1116;--shiki-dark:#F0F3F6">(s</span><span style="--shiki-light:#A0111F;--shiki-dark:#FF9492">:</span><span style="--shiki-light:#0E1116;--shiki-dark:#F0F3F6"> string); </span><span style="--shiki-light:#66707B;--shiki-dark:#BDC4CC">// rust -> js</span></span>
<span data-line=""> </span>
<span data-line=""><span style="--shiki-light:#A0111F;--shiki-dark:#FF9492">const</span><span style="--shiki-light:#0E1116;--shiki-dark:#F0F3F6"> rust </span><span style="--shiki-light:#A0111F;--shiki-dark:#FF9492">=</span><span style="--shiki-light:#622CBC;--shiki-dark:#DBB7FF"> import</span><span style="--shiki-light:#0E1116;--shiki-dark:#F0F3F6">(</span><span style="--shiki-light:#032563;--shiki-dark:#ADDCFF">"./wasm_greet"</span><span style="--shiki-light:#0E1116;--shiki-dark:#F0F3F6">); </span><span style="--shiki-light:#66707B;--shiki-dark:#BDC4CC">// js -> rust</span></span>
<span data-line=""><span style="--shiki-light:#0E1116;--shiki-dark:#F0F3F6">rust</span><span style="--shiki-light:#A0111F;--shiki-dark:#FF9492">.</span><span style="--shiki-light:#622CBC;--shiki-dark:#DBB7FF">then</span><span style="--shiki-light:#0E1116;--shiki-dark:#F0F3F6">(m </span><span style="--shiki-light:#A0111F;--shiki-dark:#FF9492">=></span><span style="--shiki-light:#0E1116;--shiki-dark:#F0F3F6"> m</span><span style="--shiki-light:#A0111F;--shiki-dark:#FF9492">.</span><span style="--shiki-light:#622CBC;--shiki-dark:#DBB7FF">greet</span><span style="--shiki-light:#0E1116;--shiki-dark:#F0F3F6">(</span><span style="--shiki-light:#032563;--shiki-dark:#ADDCFF">"World!"</span><span style="--shiki-light:#0E1116;--shiki-dark:#F0F3F6">));</span></span></code></pre></figure>
<p>lib.rs → in Rust, the executable is main.rs; when created as a library, lib.rs is generated (cargo new --lib [프로젝트명])</p>
<p>mod.rs → javascript index.js</p>
<p>Syntax</p>
<p>mod → javascript import</p>
<p>pub → typescript publish</p>
<p>use → equivalent to import { Home } from 'home'</p>
<p>type → typescript type</p>
<p>→ during the build, it is changed into _bg.wasm optimized code</p>
