f:T17d2,<h2 id="c">C<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#c"><span class="icon icon-link"></span></a></h2>
<h3 id="global-variables">Global Variables<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#global-variables"><span class="icon icon-link"></span></a></h3>
<ol>
<li>Characteristics</li>
</ol>
<ul>
<li>Declared outside of functions</li>
<li>Occupies a specific region of memory (heap) and is accessible from all functions</li>
<li>Created and allocated when the program starts, and its memory space is released when the program terminates</li>
</ul>
<ol start="2">
<li>Advantages</li>
</ol>
<ul>
<li>Convenient to use, accessible from every function, and returns values via call-by-reference</li>
</ul>
<ol start="3">
<li>Disadvantages</li>
</ol>
<ul>
<li>Because its value can be changed by any function, it can be altered from anywhere. The memory space is not released</li>
</ul>
<h3 id="local-variables">Local Variables<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#local-variables"><span class="icon icon-link"></span></a></h3>
<ol>
<li>Characteristics</li>
</ol>
<ul>
<li>Declared inside a function or within a {...} scope</li>
<li>Memory is created and allocated when the function is called, and released when the function ends</li>
<li>Accessed within its scope; a call-by-reference pointer is required to access it</li>
</ul>
<ol start="2">
<li>Advantages</li>
</ol>
<ul>
<li>No waste of memory occurs.</li>
</ul>
<ol start="3">
<li>Disadvantages</li>
</ol>
<ul>
<li>It is cumbersome to access a specific function's variable from another function.</li>
</ul>
<h3 id="static-variables-static-variable">Static Variables (static variable)<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#static-variables-static-variable"><span class="icon icon-link"></span></a></h3>
<ol>
<li>Characteristics</li>
</ol>
<ul>
<li>When declared using the static keyword, it is automatically initialized to 0</li>
<li>Since a static variable is allocated in the heap region, it retains its value even after termination.</li>
</ul>
<h2 id="c-1">C++<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#c-1"><span class="icon icon-link"></span></a></h2>
<h3 id="virtual-functions">Virtual Functions<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#virtual-functions"><span class="icon icon-link"></span></a></h3>
<ul>
<li>Determining the call target not based on the pointer's data type, but by referring to the object that the pointer variable actually points to</li>
</ul>
<h3 id="why-use-virtual-functions">Why Use Virtual Functions<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#why-use-virtual-functions"><span class="icon icon-link"></span></a></h3>
<ul>
<li>The C++ compiler decides whether a pointer operation is possible based on the pointer's data type, not the data type of the object it actually points to. Therefore, a virtual function is needed in order to call the object that is actually being pointed to.</li>
</ul>
