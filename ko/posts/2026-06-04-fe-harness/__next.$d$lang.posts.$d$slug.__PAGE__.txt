f:T5f12,<h2 id="1-하네스-엔지니어링이란">1. 하네스 엔지니어링이란?<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#1-하네스-엔지니어링이란"><span class="icon icon-link"></span></a></h2>
<p>AI 모델을 둘러싼 <strong>실행 환경 전체</strong>(도구, 피드백 루프, 안전장치, 승인 게이트)를 설계하여, <strong>신뢰할 수 있는 소프트웨어</strong>로 만들어 가는 기술이다.</p>
<h3 id="ai-엔지니어링의-진화-프롬프트-vs-컨텍스트-vs-하네스">AI 엔지니어링의 진화 (프롬프트 vs 컨텍스트 vs 하네스)<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#ai-엔지니어링의-진화-프롬프트-vs-컨텍스트-vs-하네스"><span class="icon icon-link"></span></a></h3>
<p>AI를 다루는 방식은 프롬프트 엔지니어링 → 컨텍스트 엔지니어링 → 하네스 엔지니어링으로 진화해 왔다. 단순히 "무엇을 물어볼지"를 넘어, "어떤 컨텍스트를 주입할지", 나아가 "AI가 동작하는 실행 환경 전체를 어떻게 설계할지"로 관심사가 확장되고 있다.</p>
<h3 id="anthropic-사례--generator-evaluator-패턴">Anthropic 사례 — Generator-Evaluator 패턴<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#anthropic-사례--generator-evaluator-패턴"><span class="icon icon-link"></span></a></h3>
<p>Anthropic은 장기 실행 애플리케이션 개발에 하네스를 적용하고, 그 결과를 공개했다.</p>
<p><strong>핵심 발견</strong></p>
<ul>
<li>
<p><strong>자기 평가 실패 문제</strong></p>
<p>모델에게 자신의 출력을 평가하게 하면, 평범한 결과를 자신있게 칭찬한다.</p>
<blockquote>
<p>"생성자와 평가자를 분리하는 것이 훨씬 다루기 쉬운 문제였다." — Anthropic</p>
</blockquote>
</li>
<li>
<p><strong>컨텍스트 윈도우(Context Window) 한계</strong></p>
<p>세션 안에서 기억할 수 있는 최대 글자 수(토큰 용량)가 정해져 있다. 메인 컨텍스트 오염을 막기 위해 서브 에이전트를 실행한다.</p>
</li>
</ul>
<p><strong>정량적 결과</strong></p>

<h3 id="설계-원칙">설계 원칙<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#설계-원칙"><span class="icon icon-link"></span></a></h3>
<ol>
<li><strong>"한 번에 하나씩"</strong>
<ul>
<li>grill-me가 질문을 1개씩만 하여 답변 깊이 확보</li>
<li>여러 질문 동시 → 피상적 답변 문제 해결</li>
</ul>
</li>
<li><strong>"순차가 아닌 병렬"</strong>
<ul>
<li>독립적인 스킬/검증 항목은 항상 동시 병렬 처리</li>
<li>각 서브에이전트가 깨끗한 컨텍스트로 동작 → 품질 저하 없음</li>
</ul>
</li>
<li><strong>"정적 분석 먼저, 비싼 E2E 나중"</strong>
<ul>
<li>Review(정적)가 Verify(E2E)보다 먼저 → 불필요한 E2E 비용 방지</li>
</ul>
</li>
<li><strong>"AI는 실행, 사람은 결정"</strong>
<ul>
<li>모든 Phase 전환, 스킬 선택, 수정 여부에 사용자 승인 필수</li>
<li>AI의 자율 실행 범위를 명확히 제한</li>
</ul>
</li>
</ol>
<p><strong>한 줄 설명</strong>: Research → PRD → Develop → Review → Verify 5단계를 순차 실행하고, 각 단계 전환 시 사용자 승인을 받는 전체 개발 워크플로우 지휘자.</p>

<span data-line=""><span style="--shiki-light:#0E1116;--shiki-dark:#F0F3F6">□ tdd (테스트 주도)</span></span>
<span data-line=""><span style="--shiki-light:#0E1116;--shiki-dark:#F0F3F6">           ↓</span></span>
<span data-line=""><span style="--shiki-light:#0E1116;--shiki-dark:#F0F3F6">    선택 스킬 전부 동시 병렬 실행</span></span></code></pre></figure>
<ul>
<li><strong>통합 우선순위</strong>: TDD > semantic-html > a11y > seo-geo</li>
</ul>

<span data-line=""><span style="--shiki-light:#0E1116;--shiki-dark:#F0F3F6">┌──────────┬──────────┬──────────┬───────────┬────────────┐</span></span>
<span data-line=""><span style="--shiki-light:#0E1116;--shiki-dark:#F0F3F6">│/simplify │ /review  │ security │lighthouse │qa-inspector│</span></span>
<span data-line=""><span style="--shiki-light:#0E1116;--shiki-dark:#F0F3F6">│ 코드간소    │ 품질리뷰   │ 보안감사   │ 성능측정    │ 경계면검증    │</span></span>
<span data-line=""><span style="--shiki-light:#0E1116;--shiki-dark:#F0F3F6">└──────────┴──────────┴──────────┴───────────┴────────────┘</span></span>

<span data-line=""><span style="--shiki-light:#0E1116;--shiki-dark:#F0F3F6">         수정 필요 → 재리뷰 루프 (최대 3회)</span></span>

<h2 id="3-향후-개선">3. 향후 개선<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#3-향후-개선"><span class="icon icon-link"></span></a></h2>
<h3 id="다양한-개발-환경별-하네스-구축">다양한 개발 환경별 하네스 구축<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#다양한-개발-환경별-하네스-구축"><span class="icon icon-link"></span></a></h3>
<p>현재 FE 개발에 특화된 하네스를 <strong>다양한 환경</strong>으로 확장한다.</p>
<figure data-rehype-pretty-code-figure=""><pre tabindex="0" data-language="markdown" data-theme="github-light-high-contrast github-dark-high-contrast"><code data-language="markdown" data-theme="github-light-high-contrast github-dark-high-contrast" style="display: grid;"><span data-line=""><span style="--shiki-light:#0E1116;--shiki-dark:#F0F3F6">┌─────────────────────────────────────────────────────┐</span></span>
<span data-line=""><span style="--shiki-light:#0E1116;--shiki-dark:#F0F3F6">│          Orchestrator (환경 무관 범용 엔진)             │</span></span>
<span data-line=""><span style="--shiki-light:#0E1116;--shiki-dark:#F0F3F6">│    Research → PRD → Develop(선택) → Review(선택) → Verify(선택)│</span></span>
<span data-line=""><span style="--shiki-light:#0E1116;--shiki-dark:#F0F3F6">├─────────────┬──────────────┬────────────────────────┤</span></span>
<span data-line=""><span style="--shiki-light:#0E1116;--shiki-dark:#F0F3F6">│  FE 스킬 팩   │ 문서 스킬 팩    │   PRD 생성 스킬          │</span></span>
<span data-line=""><span style="--shiki-light:#0E1116;--shiki-dark:#F0F3F6">│  a11y       │ 기술 보고서 작성  │   요구사항 정의          │</span></span>
<span data-line=""><span style="--shiki-light:#0E1116;--shiki-dark:#F0F3F6">│  semantic   │ Wiki 자동 업로드 │   아키텍처 설계          │</span></span>
<span data-line=""><span style="--shiki-light:#0E1116;--shiki-dark:#F0F3F6">│  lighthouse │ 발표 자료 생성    │   리스크 분석           │</span></span>
<span data-line=""><span style="--shiki-light:#0E1116;--shiki-dark:#F0F3F6">└─────────────┴──────────────┴────────────────────────┘</span></span></code></pre></figure>
<p><strong>핵심</strong>: Orchestrator 5단계 흐름은 환경 무관. <strong>스킬만 교체</strong>하면 된다.</p>
<h3 id="에이전트-엔지니어링-구축">에이전트 엔지니어링 구축<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#에이전트-엔지니어링-구축"><span class="icon icon-link"></span></a></h3>
<p>하네스 → 에이전트 엔지니어링으로의 진화:</p>
<figure data-rehype-pretty-code-figure=""><pre tabindex="0" data-language="markdown" data-theme="github-light-high-contrast github-dark-high-contrast"><code data-language="markdown" data-theme="github-light-high-contrast github-dark-high-contrast" style="display: grid;"><span data-line=""><span style="--shiki-light:#0E1116;--shiki-dark:#F0F3F6">현재                              미래</span></span>
<span data-line=""><span style="--shiki-light:#0E1116;--shiki-dark:#F0F3F6">──────                            ──────</span></span>
<span data-line=""><span style="--shiki-light:#0E1116;--shiki-dark:#F0F3F6">인간이 하네스를 설계         →    AI가 하네스를 자기 개선</span></span>
<span data-line=""><span style="--shiki-light:#0E1116;--shiki-dark:#F0F3F6">AI가 실행, 인간이 승인       →    인간은 목표와 경계만 설정</span></span>
<span data-line=""><span style="--shiki-light:#0E1116;--shiki-dark:#F0F3F6">스킬이 정적 (SKILL.md 고정)  →    스킬 자동 튜닝 (A/B 테스트)</span></span>
<span data-line=""><span style="--shiki-light:#0E1116;--shiki-dark:#F0F3F6">실패 패턴을 인간이 분석      →    메트릭 기반 자동 진단</span></span></code></pre></figure>
