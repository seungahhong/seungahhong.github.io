1a:T17bd,<h2 id="c">C<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#c"><span class="icon icon-link"></span></a></h2>
<h3 id="전역변수">전역변수<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#전역변수"><span class="icon icon-link"></span></a></h3>
<ol>
<li>특징</li>
</ol>
<ul>
<li>함수외부에서 선언</li>
<li>메모리의 어느 특정공간(heap)에 자리를 차지하고 모든 함수 access 가능</li>
<li>프로그램 시작 시 생성 및 할당, 프로그램 종료가 되면 그 메모리 공간을 반환</li>
</ul>
<ol start="2">
<li>장점</li>
</ol>
<ul>
<li>사용하기 편리하다, 모든 함수에서 access 가능, call-by-reference로 값을 반환</li>
</ul>
<ol start="3">
<li>단점</li>
</ol>
<ul>
<li>모든 함수에서 그 값을 변경할 수 있기 때문에 이더서든지 변한다. 메모리 공간을 반환하지 않음</li>
</ul>
<h3 id="지역변수">지역변수<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#지역변수"><span class="icon icon-link"></span></a></h3>
<ol>
<li>특징</li>
</ol>
<ul>
<li>함수 혹은 {...} 범위 내부에서 선언</li>
<li>함수가 호출되면 메모리의 생성, 할당이 되며 함수가 끝나면 메모리 반환</li>
<li>범위 안에서 접근, 접근하려면 call-by-reference 포인터가 필요</li>
</ul>
<ol start="2">
<li>장점</li>
</ol>
<ul>
<li>메모리의 낭비가 일어나지 않는다.</li>
</ul>
<ol start="3">
<li>단점</li>
</ol>
<ul>
<li>다른 함수에서 특정 함수의 변수로 접근할 때 까다롭다.</li>
</ul>
<h3 id="정적변수static-valuable">정적변수(static valuable)<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#정적변수static-valuable"><span class="icon icon-link"></span></a></h3>
<ol>
<li>특징</li>
</ol>
<ul>
<li>static 키둬드를 사용하여 선언할 때 자동으로 0으로 초기화 됨</li>
<li>static 변수는 heap 영역에 할당되므로 종료해도 그 값을 유지하게 된다.</li>
</ul>

<h3 id="가상함수">가상함수<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#가상함수"><span class="icon icon-link"></span></a></h3>
<ul>
<li>포인터의 자료형을 기반으로 호출대상을 결정하지 않고, 포인터 변수가 실제로 가리키는 객체를 참조하여 호출의 대상을 결정하는 것</li>
</ul>
<h3 id="가상함수-하는-이유">가상함수 하는 이유<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#가상함수-하는-이유"><span class="icon icon-link"></span></a></h3>
<ul>
<li>C++ 컴파일러는 포인터의 연산의 가능성 여부를 판단할 때, 포인터의 자료형을 기준으로 판단하지, 실제 가리키는 객체의 자료형을 기준으로 판단 하지 않으므로, 실제 가리키는 객체를 호출하기 위해서 가상함수가 필요함.</li>
</ul>
