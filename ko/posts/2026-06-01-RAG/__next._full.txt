23:T175ae,<h2 id="0-배경">0. 배경<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#0-배경"><span class="icon icon-link"></span></a></h2>
<p>특정 비즈니스 로직(결제, 인증, 캠페인 등)이 프론트엔드·백엔드 서비스 등 여러 레포에 걸쳐 구현되어 있어, 관련 코드를 찾기 위해 각 레포를 개별적으로 검색해야 하는 비효율이 발생하고 있다.</p>
<p>기존 GitHub 검색은 키워드 기반으로만 동작하여 "결제 처리 로직", "캠페인 생성 흐름"과 같은 의미 기반 검색이 불가능하다. 또한 Claude AI를 활용한 코드 분석 시, AI가 사내 코드베이스에 직접 접근할 수 없어 컨텍스트 제공에 수작업이 필요하다.</p>
<p>이러한 문제를 해결하기 위해 다중 레포 코드를 통합 인덱싱하고, 시맨틱 검색 + Claude AI 연동을 제공하는 RAG 시스템을 구축하게 되었다.</p>
<hr>
<h2 id="1-개요">1. 개요<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#1-개요"><span class="icon icon-link"></span></a></h2>
<p><strong>code-retrieval</strong>은 사내 다중 GitHub 레포지토리의 코드를 대상으로 <strong>시맨틱(의미 기반) + 키워드 하이브리드 검색</strong>을 제공하는 RAG(Retrieval-Augmented Generation) 시스템이다.</p>
<p>개발자가 자연어 질의로 여러 레포에 흩어진 관련 코드를 한 번에 찾을 수 있으며, Claude AI와 직접 연동하여 코드 이해·분석 작업을 지원한다.</p>
<p>2가지 접근 경로를 제공한다.</p>
<ul>
<li><strong>REST API</strong> (FastAPI): 웹 UI, 외부 서비스 연동용</li>
<li><strong>MCP 서버</strong> (FastMCP): Claude Desktop / Claude Code에서 직접 코드 검색용</li>
</ul>
<hr>
<h2 id="2-목표">2. 목표<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#2-목표"><span class="icon icon-link"></span></a></h2>
<p><strong>핵심 목표</strong></p>
<ul>
<li>다중 레포 코드를 하나의 검색 엔진으로 통합하여 개발자의 코드 탐색 시간을 단축한다</li>
<li>"결제 처리 함수", "캠페인 생성 API" 같은 자연어 질의로 의미 기반 코드 검색을 가능하게 한다</li>
<li>Claude AI가 사내 코드베이스에 직접 접근하여 코드 분석·리뷰·질의응답을 수행할 수 있게 한다</li>
</ul>
<p><strong>기술 목표</strong></p>
<ul>
<li>AST 기반 구조적 코드 청킹으로 함수·클래스 단위의 의미 있는 검색 결과를 제공한다</li>
<li>Dense(시맨틱) + Sparse(키워드) 하이브리드 검색 + 리랭킹으로 검색 품질을 극대화한다</li>
<li>git diff 기반 증분 동기화로 코드 변경 시 전체 재인덱싱 없이 효율적으로 업데이트한다</li>
</ul>
<hr>
<h2 id="3-설치-및-실행-installation--execution">3. 설치 및 실행 (Installation &#x26; Execution)<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#3-설치-및-실행-installation--execution"><span class="icon icon-link"></span></a></h2>
<h3 id="31-사전-요구사항">3.1 사전 요구사항<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#31-사전-요구사항"><span class="icon icon-link"></span></a></h3>
<ul>
<li>Python 3.12</li>
<li>Docker 또는 Colima (Qdrant 실행용, Docker Desktop 불필요)</li>

<h3 id="62-인덱싱-흐름">6.2 인덱싱 흐름<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#62-인덱싱-흐름"><span class="icon icon-link"></span></a></h3>
<ol>
<li><strong>레포 등록</strong>: GitHub URL 또는 로컬 경로를 CLI로 등록, data/registry.json에 메타데이터 저장</li>
<li><strong>코드 수집</strong>: git clone (또는 기존 로컬 레포 참조)</li>
<li><strong>파일 필터링</strong>: 확장자 기반 인덱싱 대상 판별 (.py, .ts, .kt 등), node_modules/, .git/ 등 제외</li>
<li><strong>AST 청킹</strong>: Python은 ast 모듈, JS/TS/Java/Kotlin/Go/Rust는 Tree-sitter로 함수·클래스·모듈 단위 분할</li>
<li><strong>임베딩 생성</strong>: FastEmbed으로 Dense(1024d) + Sparse(BM25) 벡터 동시 생성</li>
<li><strong>Qdrant 저장</strong>: Insert-then-Delete 패턴으로 안전하게 upsert</li>
</ol>
<h3 id="63-검색-흐름">6.3 검색 흐름<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#63-검색-흐름"><span class="icon icon-link"></span></a></h3>
<ol>
<li><strong>쿼리 전처리</strong>: 유니코드 NFC 정규화 → camelCase/snake_case 코드 키워드 자동 추출</li>
<li><strong>임베딩 생성</strong>: 쿼리를 Dense + Sparse 벡터로 변환</li>
<li><strong>하이브리드 검색</strong>: Qdrant에서 Dense 검색과 Sparse 검색을 각각 수행 (prefetch_limit=100)</li>
<li><strong>RRF 융합</strong>: Reciprocal Rank Fusion으로 두 검색 결과를 하나로 병합</li>
<li><strong>리랭킹</strong>: BGE-Reranker-v2-M3로 상위 후보를 크로스인코더 재순위 매김</li>
<li><strong>결과 반환</strong>: top_k개의 코드 청크를 관련도 순으로 반환 (GitHub 링크 포함)</li>
</ol>
<h3 id="64-증분-동기화-흐름">6.4 증분 동기화 흐름<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#64-증분-동기화-흐름"><span class="icon icon-link"></span></a></h3>
<ol>
<li>git fetch → git reset --hard origin/branch</li>
<li>git diff --name-only old_sha..new_sha로 변경/삭제 파일 감지</li>
<li>삭제된 파일: Qdrant에서 해당 파일의 청크 삭제</li>
<li>변경된 파일만 재청킹 → 재임베딩 → Qdrant sync_file (insert-then-delete)</li>
</ol>

<h3 id="71-ast-기반-구조적-코드-청킹">7.1 AST 기반 구조적 코드 청킹<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#71-ast-기반-구조적-코드-청킹"><span class="icon icon-link"></span></a></h3>
<p>단순 텍스트 분할이 아닌 코드의 구문 구조(AST)를 분석하여 의미 있는 단위로 분할한다.</p>













































<table><thead><tr><th>언어</th><th>파서</th><th>청킹 단위</th></tr></thead><tbody><tr><td>Python</td><td>ast 모듈</td><td>함수, 클래스, 모듈 레벨 코드</td></tr><tr><td>JS/TS</td><td>Tree-sitter</td><td>함수, 클래스, 인터페이스, arrow function</td></tr><tr><td>Java</td><td>Tree-sitter</td><td>메서드, 클래스, 인터페이스</td></tr><tr><td>Kotlin</td><td>Tree-sitter</td><td>함수, 클래스, object 선언</td></tr><tr><td>Go</td><td>Tree-sitter</td><td>함수, 메서드, 타입 선언</td></tr><tr><td>Rust</td><td>Tree-sitter</td><td>함수, impl, struct, trait, enum</td></tr><tr><td>기타 (YAML, JSON 등)</td><td>고정 크기</td><td>~512 토큰 단위, 50 토큰 오버랩</td></tr></tbody></table>
<p><strong>큰 클래스 처리</strong>: 100줄 초과 클래스는 메서드별 개별 청크 + 클래스 헤더 청크로 분할</p>
<h3 id="72-하이브리드-검색-dense--sparse--rrf">7.2 하이브리드 검색 (Dense + Sparse + RRF)<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#72-하이브리드-검색-dense--sparse--rrf"><span class="icon icon-link"></span></a></h3>
<ul>
<li><strong>Dense 검색</strong>: multilingual-e5-large로 의미 기반 유사도 검색 (한국어/영어 모두 지원)</li>
<li><strong>Sparse 검색</strong>: BM25로 정확한 키워드 매칭 (함수명, 변수명 등 코드 식별자에 강점)</li>
<li><strong>RRF 융합</strong>: 두 검색 결과를 Reciprocal Rank Fusion으로 통합하여 상호 보완</li>
</ul>
<h3 id="73-bge-reranker-리랭킹">7.3 BGE-Reranker 리랭킹<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#73-bge-reranker-리랭킹"><span class="icon icon-link"></span></a></h3>
<p>1차 검색 결과(top_k x 3개 후보)를 크로스인코더 모델로 정밀 재순위 매김한다.</p>
<ul>
<li><strong>FP16 추론</strong>: 메모리 절감 및 속도 향상</li>

<li><strong>메타데이터 부스트</strong> (선택): 함수명·파일경로·언어 매칭 시 가산점 부여</li>
</ul>

<p><strong>호출자 탐지 로직</strong> (_find_callers)</p>
<ul>
<li>같은 파일 내에서 def/function/const/let/var/fun/func 선언을 추적하여 현재 함수 스코프를 판별</li>

<li>길이 3 미만이거나 &#x3C;module>, &#x3C;anonymous> 같은 제네릭 이름은 건너뜀</li>
</ul>
<p><strong>docstring 추출 로직</strong> (extract_docstring)</p>
<ul>
<li>Python: ast.get_docstring()으로 첫 번째 함수/클래스의 docstring 첫 줄 추출</li>
<li>JS/TS/Java/Kotlin: 선행 // 주석 또는 JSDoc /** ... */ 블록의 텍스트 추출 (최대 120자)</li>
</ul>

<p>3가지 기능은 독립적으로 또는 조합하여 사용할 수 있다. 아래는 가능한 조합과 효과를 정리한 것이다.</p>















































<table><thead><tr><th>Contextual Chunking</th><th>Ollama 보강</th><th>메타데이터 부스트</th><th>효과</th></tr></thead><tbody><tr><td>OFF</td><td>OFF</td><td>OFF</td><td>기본 모드. 코드 텍스트만으로 검색. 가장 빠르고 가벼움</td></tr><tr><td>ON</td><td>OFF</td><td>OFF</td><td>휴리스틱 문맥(파일경로, import, docstring, 호출자)이 임베딩에 반영되어 검색 정확도 향상</td></tr><tr><td>ON</td><td>ON</td><td>OFF</td><td>휴리스틱 + LLM 요약으로 시맨틱 임베딩 품질 극대화. 인덱싱 시간 증가 (청크당 ~2-5초)</td></tr><tr><td>OFF</td><td>OFF</td><td>ON</td><td>검색 시 함수명/파일명 매칭에 가산점. 정확한 이름을 알고 있을 때 효과적</td></tr><tr><td>ON</td><td>OFF</td><td>ON</td><td>인덱싱 시 문맥 보강 + 검색 시 메타데이터 부스트. 균형 잡힌 권장 조합</td></tr><tr><td>ON</td><td>ON</td><td>ON</td><td>모든 기능 활성화. 최고 품질이지만 인덱싱 시간 가장 길음</td></tr></tbody></table>
<p><strong>권장 구성</strong></p>
<ul>
<li><strong>빠른 시작</strong>: 모두 OFF (기본값) — 환경 구성 없이 즉시 사용</li>
<li><strong>품질 개선</strong>: ENABLE_CONTEXTUAL_CHUNKING=true + ENABLE_RERANKER_METADATA_BOOST=true — Ollama 없이도 유의미한 품질 향상</li>
<li><strong>최대 품질</strong>: 3가지 모두 ON — Ollama 서버 필요, 인덱싱 시간 증가 감수</li>
</ul>
