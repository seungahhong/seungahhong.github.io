f:T76f6,<h2 id="typescript-70-출시-go로-다시-쓴-네이티브-컴파일러">TypeScript 7.0 출시: Go로 다시 쓴 네이티브 컴파일러<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#typescript-70-출시-go로-다시-쓴-네이티브-컴파일러"><span class="icon icon-link"></span></a></h2>
<p>TypeScript 7.0이 공식 출시되었습니다. 이번 메이저 버전의 핵심은 <strong>컴파일러를 Go 언어로 완전히 다시 이식(native port)</strong> 한 것입니다. 10년 넘게 JavaScript로 작성되어 온 <code>tsc</code>를 네이티브 코드로 옮기면서, 대규모 프로젝트에서 <strong>8~12배 빠른 빌드</strong>와 <strong>최대 26% 낮은 메모리 사용량</strong>을 달성했습니다. 기존 구현과의 타입 검사 호환성은 그대로 유지됩니다.</p>

<h3 id="배경-왜-go로-다시-썼나">배경: 왜 Go로 다시 썼나<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#배경-왜-go로-다시-썼나"><span class="icon icon-link"></span></a></h3>
<p>TypeScript는 그동안 JavaScript로 구현되어 왔습니다. 이 방식은 이식성과 생태계 통합 측면에서 장점이 컸지만, 대규모 코드베이스에서는 타입 검사와 빌드 속도가 점점 병목이 되었습니다. 팀은 <strong>한 자릿수 배수가 아닌 order-of-magnitude(자릿수 단위) 성능 향상</strong>을 목표로 컴파일러를 Go로 다시 이식하기로 결정했습니다.</p>
<p>이식은 "가능한 한 원본에 충실하게(as faithfully as possible)" 진행되었습니다. 즉, 기존 컴파일러의 구조와 로직을 그대로 보존하면서 다음과 같은 네이티브 언어의 이점을 얻는 방향입니다.</p>
<ul>
<li><strong>네이티브 코드 속도</strong> — 컴파일된 Go 바이너리는 인터프리터 방식의 JavaScript보다 빠르게 실행됩니다.</li>
<li><strong>공유 메모리 기반 멀티스레딩</strong> — JavaScript의 단일 스레드 이벤트 루프 제약 없이 타입 검사와 파일 처리를 병렬화할 수 있습니다.</li>
<li><strong>크로스 플랫폼 최적화</strong> — Parcel의 C++ 파일 워처를 Go로 이식하여 플랫폼별 파일 감시 성능을 개선했습니다.</li>
</ul>
<p>새로운 코드베이스임에도 Go 구현과 원본 구현 간의 결과는 일관되고 호환됩니다.</p>

<p>VSCode 코드베이스에서 에러가 있는 파일을 여는 시간이 약 <strong>17.5초 → 1.3초 미만</strong>으로, 13배 이상 빨라졌습니다. 언어 서버 안정성도 개선되어 <strong>실패 명령 80% 감소</strong>, <strong>크래시 60% 감소</strong>를 기록했습니다.</p>
<h3 id="실제-도입-사례">실제 도입 사례<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#실제-도입-사례"><span class="icon icon-link"></span></a></h3>
<p>TypeScript 7.0은 10년 이상 축적된 수만 개의 기존 테스트와 GitHub 상위 프로젝트에 대한 자동 회귀 검사를 거쳤고, 여러 대기업에서 실사용 검증을 마쳤습니다.</p>
<ul>
<li><strong>Slack</strong> — 머지 큐 대기 시간 40% 단축, CI 타입 검사가 7.5분 → 1.25분으로 감소. 이전에는 언어 서버 부하로 로컬 타입 검사가 "거의 사용 불가능" 수준이었다고 합니다.</li>
<li><strong>Vanta</strong> — 주요 프로젝트에서 최대 9배 빠른 빌드.</li>
<li><strong>Microsoft News Services</strong> — CI 빌드 대기 시간이 월 약 400시간 절감.</li>
<li><strong>Canva</strong> — 언어 서비스 에러 감지가 약 58초 → 4.8초로 단축.</li>
<li><strong>PowerBI</strong> — 엔지니어들이 에디터 경험을 "생명을 구하는(life-saving)" 수준이라고 평가.</li>
</ul>

<p><code>--watch</code> 모드는 Parcel의 파일 워처를 Go로 이식하여 새로 구현되었습니다. Go 표준 라이브러리의 크로스 플랫폼 파일 감시 한계와 순수 폴링 방식의 오버헤드를 해소하여, 개발 사이클 중 리소스 소비를 크게 줄였습니다.</p>
<h3 id="언어-및-동작-변경사항">언어 및 동작 변경사항<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#언어-및-동작-변경사항"><span class="icon icon-link"></span></a></h3>

<h4 id="javascript-지원-재정비">JavaScript 지원 재정비<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#javascript-지원-재정비"><span class="icon icon-link"></span></a></h4>
<p><code>.js</code> 파일 분석 방식이 <code>.ts</code> 파일과 일관되도록 정리되었습니다. 주요 변경점은 다음과 같습니다.</p>
<ul>
<li>값(value)을 타입 자리에 사용할 수 없음 → <code>typeof</code>를 사용</li>
<li><code>@enum</code> 자동 인식 제거</li>
<li>단독 <code>?</code>를 타입으로 쓸 수 없음 → <code>any</code> 사용</li>
<li><code>@class</code>가 생성자를 만들지 않음</li>
<li>후위 <code>!</code>(non-null assertion) 미지원</li>
<li>타입 이름에 <code>@typedef</code> 태그 필요 (인접 배치 방식 폐지)</li>
<li>클로저 스타일 함수 구문 및 프로토타입 재할당 특수 처리 폐지</li>
</ul>

<p>새 언어 서버는 <strong>LSP(Language Server Protocol)</strong> 위에 구축되어 에디터 전반에서 멀티스레드 요청 처리가 가능합니다. 자동 import, 확장형 hover, inlay hint, code lens, go-to-source-definition, JSX 링크드 에디팅/태그 완성, 시맨틱 하이라이팅, import 정렬, 미사용 import 제거 등이 지원됩니다.</p>
<h4 id="임베디드-언어의-한계">임베디드 언어의 한계<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#임베디드-언어의-한계"><span class="icon icon-link"></span></a></h4>
<p>Vue, MDX, Astro, Svelte, Angular 템플릿은 아직 안정적인 프로그래밍 방식 API가 없어 TypeScript 7을 활용할 수 없습니다. Volar 등은 여전히 TypeScript 6.0에 의존하므로, <strong>CLI는 TS 7 / 에디터는 TS 6.0</strong> 조합을 권장합니다. 이 제약은 7.1의 API 지원으로 해소될 예정입니다.</p>
<h3 id="향후-로드맵">향후 로드맵<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#향후-로드맵"><span class="icon icon-link"></span></a></h3>
<p>7.0 출시로 팀은 다시 기능 개발에 집중합니다.</p>
<ul>
<li><strong>TypeScript 7.1</strong> — 생태계를 위한 프로그래밍 방식 API 제공</li>
<li>3~4개월 주기의 정기 릴리스</li>
<li>성능 최적화 및 개발 편의성(ergonomics) 개선 지속</li>
</ul>
<h3 id="마무리">마무리<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#마무리"><span class="icon icon-link"></span></a></h3>
<p>TypeScript 7.0은 단순한 기능 추가가 아니라, <strong>컴파일러 실행 기반을 JavaScript에서 Go로 옮긴 근본적 전환</strong>입니다. 8~12배 빠른 빌드와 낮은 메모리 사용량을 제공하면서도 타입 검사 호환성은 유지합니다.</p>
<p><strong>주요 체크리스트:</strong></p>
<ul>
<li>✅ <code>npm install -D typescript</code>로 설치, <code>npx tsc --version</code> 확인</li>

<li>✅ 제거된 옵션 정리 (<code>es5</code>, <code>baseUrl</code>, <code>node/node10</code>, <code>classic</code> 등)</li>
<li>✅ 에디터·임베디드 언어 도구용으로 <code>@typescript/typescript6</code> 병행 설치</li>
<li>✅ 멀티코어 환경에서 <code>--checkers</code> / <code>--builders</code>로 병렬화 튜닝</li>
</ul>
