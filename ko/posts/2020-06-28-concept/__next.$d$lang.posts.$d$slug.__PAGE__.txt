<h3 id="쿠키">쿠키<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#쿠키"><span class="icon icon-link"></span></a></h3>
<ul>
<li>쿠키를 설정하면 이후 모든 웹 요청은 쿠키정보를 포함하여 서버로 전송</li>
<li>문자열만 저장, 4KB용량 제한</li>
<li>대개, 방문한 페이지를 저장하거나 유저의 로그인 정보를 저장</li>
<li>Seesion cookies : 만료일이 포함되지 않는 쿠키(브라우저 탭이 열려 있는 동안만)</li>
<li>Persistent cookies : 만료일을 가지는 쿠키(유저의 웹사이트의 행동기록등에 사용)</li>
</ul>

<h3 id="localstorage">localstorage<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#localstorage"><span class="icon icon-link"></span></a></h3>
<ul>
<li>오직 문자열만 저장가능</li>
<li>JSON 데이터를 문자열로 변환하여서 문자열 저장하는 부분을 보완가능</li>
<li>브라우저가 종료해도 데이터가 유지</li>
<li>도메인이 다를 경우 로컬스토리지 접근 불가능</li>
<li>브라우저, 기기별 용량 제한(브라우저: 5MB~10MB, 모바일: 2.5MB)</li>
</ul>

<h3 id="sessionstorage">sessionstorage<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#sessionstorage"><span class="icon icon-link"></span></a></h3>
<ul>
<li>오직 문자열만 저장가능</li>
<li>JSON 데이터를 문자열로 변환하여서 문자열 저장하는 부분을 보완가능</li>
<li>각 세션마다 개별적으로 저장(예: 탭실행, 세션종료시 개별실행)</li>
<li>같은 도메인이라도 세션이 다르면 접근불가능</li>
<li>브라우저, 기기별 용량 제한(브라우저: 5MB~10MB, 모바일: 2.5MB)</li>
<li>사용법은 localstorage와 동일하다.</li>
</ul>

<p>이렇게 일부 인자만 받은 새로운 함수를 만들고, 나중에 새로운 함수에 인자를 넣어 완성합니다.</p>
<h3 id="partial-application">Partial application<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#partial-application"><span class="icon icon-link"></span></a></h3>
<p>여러 개의 인자를 받는 함수가 있을 때 일부의 인자를 고정한 함수를 만드는 기법입니다</p>
<h3 id="커링함수-개념">커링함수 개념<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#커링함수-개념"><span class="icon icon-link"></span></a></h3>
<p>커링은 수학자 하스켈 커리로 부터 유래된 이름이고 함수를 변형하는 과정을 말한다.
함수의 전달인자 몇 개를 미리 채움으로써 더 간단한 함수를 만드는 방법입니다.
커링도 partial application처럼 인자를 미리 고정할 수 있지만 하나씩만 고정한다는 것이 특징입니다. 또한, 모든 인자를 받을 때까지 계속 함수를 생성합니다.
매 번 인자를 1개씩 고정하는 연속적인 partial application으로 볼 수도 있습니다.</p>
<h3 id="커링을-사용하는-경우">커링을 사용하는 경우<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#커링을-사용하는-경우"><span class="icon icon-link"></span></a></h3>
<p>어떤 함수를 호출할 때 대부분의 매개 변수가 항상 비슷하다면 커링을 사용할 만한 후보라고 할 수 있다.
매개변수 일부를 적용하여 새로운 함수를 동적으로 생성하면 이 동적 생성된 함수는 반복적으로 사용되는 매개변수를 내부적으로 저장하여, 매번 인자를 전달하지 않아도 원본함수가 기대하는 기능을 채워 놓게 될 것이다.</p>

<h2 id="web-worker">web worker<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#web-worker"><span class="icon icon-link"></span></a></h2>
<p>웹 워커
JavaScript에서 웹 워커(web worker)를 활용하면 멀티 스레딩이 가능합니다(참고). 웹 워커는 스크립트 수행을 메인 스레드가 아닌 별도 백그라운드 스레드에서 수행할 수 있게 해줍니다.</p>
<p>메인 스레드에서 워커 객체를 생성하면 워커 스레드와 메시지 기반으로 통신이 가능합니다. 워커 스레드에게 postMessage를 통해 처리하는 데 오래 걸리는 작업의 실행을 요청하면 워커 스레드는 이를 실행합니다. 이를 통해 메인 스레드가 블록되는 것을 막을 수 있습니다. 워커 스레드는 작업이 완료되면 역시 postmessage를 통해 결과 완료 메시지를 전송하고, 메인 스레드에선 이를 통해 또 다른 작업을 할 수 있게 됩니다.</p>

<h2 id="프로그레시브-웹앱progressive-web-apps">프로그레시브 웹앱(Progressive Web Apps)<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#프로그레시브-웹앱progressive-web-apps"><span class="icon icon-link"></span></a></h2>
<p>프로그레시브 웹앱(Progressive Web Apps)은 Google I/O 2016에서 소개된 미래의 웹기술이며, PWA라고 줄여서 부르기도 합니다.</p>
<p>먼저 구글에서 소개하는 PWA는 이러합니다.</p>
<blockquote>
<p>PWA는 최고의 웹과 최고의 앱을 결합한 경험이다. 브라우저를 통해 처음 방문한 사용자에게 유용하며, 설치가 필요하지 않다.
사용자가 PWA와 관계를 점진적으로 형성할수록 성능이 더욱 강력해 질 것이다. 느린 네트워크에서도 빠르게 로드되고, 관련된 푸시 알림을 전송한다.
모바일 앱처럼 전체 화면으로 로드되고, 홈 화면에 아이콘이 있다.</p>
</blockquote>
<p>네이티브 앱은 느린 네트워크에서도 작동하며, 백그라운드에서 푸시 알람을 보내줍니다. 또한, 카메라, 마이크 등에도 쉽게 접근하여 다양한 기능을 수행할 수 있습니다. 즉, Capability(능력)가 뛰어나다라고 할 수 있죠.
웹은 URL을 통한 접근이 간단하고, 설치 과정이 없습니다. 즉, Reach(범위)가 넓다라고 할 수 있습니다.
이는 다음 그림처럼 시각화 할 수 있습니다.</p>
<p><img src="/blog-assets/2020/06/images/28/pwa1.png" alt="pwa1"></p>
<p>그리고 네이티브 앱과 웹의 장점을 결합한 PWA는 이쯤에 위치시킬 수 있겠네요.</p>
<p><img src="/blog-assets/2020/06/images/28/pwa2.png" alt="pwa2"></p>

<h3 id="callbindapply">call/bind/apply<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#callbindapply"><span class="icon icon-link"></span></a></h3>
<h4 id="call-apply-bind-차이">call, apply, bind 차이<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#call-apply-bind-차이"><span class="icon icon-link"></span></a></h4>
<p>call(), apply() 는 ECMA 3에서 추가 되었으며, bind()는 ECMA 5에서 추가 되었습니다.
call(), apply()는 invoke입니다. 함수 호출을 즉시 합니다.
bind()는 나중에 실행될때 사용 됩니다. 특정 이벤트를 함수를 호출해야 할때 유용합니다.</p>

<h3 id="스코프">스코프<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#스코프"><span class="icon icon-link"></span></a></h3>

<ul>
<li>설명
Person객체를 생성시 Person.prototype이 생성된다. 그리고 Person.prototype.constructor는 Person을 가리킨다. 그리고 Employee.prototype이 Person.prototype을 참조하게 한다면, 그의 constructor 또한 Person을 지칭하므로 자신을 지칭할 수 있도록 다시 Employee로 변경해준다. 그리고 새롭게 생성된 kim객체는 Employee.prototype를 가리킨다. 따라서 kim.proto 는 Employee.prototype를 가리킨다</li>
</ul>
<p><img src="/blog-assets/2020/06/images/28/prototype.png" alt="prototype">
함수 객체 앞에 new키워드를 사용하면 생성자가 되고, 이것으로 생성한 객체를 인스턴스라고 한다. 위 이미지에서는 kim이 Person객체의 인스턴스이다.</p>
<h4 id="proto-vs-prototype의-차이"><strong>proto</strong> vs prototype의 차이<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#proto-vs-prototype의-차이"><span class="icon icon-link"></span></a></h4>
<ul>
<li>
<p><strong>proto</strong></p>
<ul>
<li><strong>proto</strong> 속성은 모든 객체가 가지고 있는 속성.</li>
<li>객체가 생성될 때 자신의 생성한 객체에 프로토타입을 가리킽다.</li>
</ul>
</li>
<li>
<p>prototype</p>
<ul>
<li>함수 객체만이 가지는 프로토타입</li>
<li>생성한 인스턴스가 가리키는 프로토타입을 의미한다.</li>
</ul>
</li>
</ul>
<h4 id="prototype-chain">Prototype Chain<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#prototype-chain"><span class="icon icon-link"></span></a></h4>
<p>모든 프로토타입 체인의 끝은 항상 Object.prototype이다. 그래서 Object.prototype은 <strong>proto</strong>속성이 없다.</p>

<h4 id="함수형-프로그래밍에-대해-설명">함수형 프로그래밍에 대해 설명<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#함수형-프로그래밍에-대해-설명"><span class="icon icon-link"></span></a></h4>
<h4 id="순수함수-불변성-일급객체">순수함수, 불변성, 일급객체<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#순수함수-불변성-일급객체"><span class="icon icon-link"></span></a></h4>
<p>1급 객체 (First Object, 또는 1급 시민)</p>
<ul>
<li>1급 객체(First class object)란 다음과 같은 조건을 만족하는 객체
<ul>
<li>변수나 데이터 구조안에 담을 수 있다.</li>
<li>파라미터로 전달 할 수 있다.</li>
<li>반환값(return value)으로 사용할 수 있다.</li>
<li>동적으로 프로퍼티 할당이 가능하다.</li>
</ul>
</li>
</ul>
<p>고차 함수 (High-Order Function)</p>
<ul>
<li>람다 계산법에서 만들어진 용어로 아래 조건을 만족하는 함수
<ul>
<li>함수에 함수를 파라미터로 전달할 수 있다.</li>
<li>함수의 반환값으로 함수를 사용할 수 있다.</li>
</ul>
</li>
</ul>
<p>불변성 (Immutablility)</p>
<ul>
<li>함수형 프로그래밍에서는 데이터가 변할 수 없는데, 이를 불변성 데이터라고 한다. (자바스크립트는 가능하지만 불가능한 언어들이 있다)</li>
<li>데이터 변경이 필요한 경우, 원본 데이터 구조를 변경하지 않고 그 데이터를 복사본을 만들어 그 일부를 변경하고, 변경한 복사본을 사용해 작업을 진행한다.</li>
</ul>
