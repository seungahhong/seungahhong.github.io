1b:T110d1,<h2 id="react-router-v8-출시-지루한-메이저와-v7--v8-업그레이드-가이드">React Router v8 출시: "지루한 메이저"와 v7 → v8 업그레이드 가이드<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#react-router-v8-출시-지루한-메이저와-v7--v8-업그레이드-가이드"><span class="icon icon-link"></span></a></h2>
<h3 id="️-한-줄-요약">✍️ 한 줄 요약<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#️-한-줄-요약"><span class="icon icon-link"></span></a></h3>
<blockquote>
<p><strong>React Router v8은 새 기능을 싣고 온 릴리스가 아니라, v7에서 future flag로 미리 풀어둔 변경을 기본값으로 굳히고 최소 버전을 올린 릴리스입니다.</strong> v7에서 플래그를 모두 켜두었다면 업그레이드는 사실상 <code>pnpm i react-router@latest</code> 한 줄입니다.</p>
</blockquote>
<h4 id="요약">요약<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#요약"><span class="icon icon-link"></span></a></h4>
<ul>
<li><strong>출시</strong>: 2026년 6월 17일, Remix 블로그 공지. 팀 스스로 "가장 지루한(boring) 메이저"라고 부릅니다.</li>
<li><strong>최소 버전</strong>: Node <strong>22.22.0+</strong> · React <strong>19.2.7+</strong> · Vite <strong>7+</strong>(Framework 모드). 패키지는 <strong>ESM 전용</strong>이 되었고 tsconfig target/lib는 ES2022로 올라갔습니다.</li>
<li><strong>기본값이 된 future flag 5개</strong>: <code>v8_middleware</code> · <code>v8_splitRouteModules</code>(최상위 <code>splitRouteModules</code>로 이동) · <code>v8_viteEnvironmentApi</code> · <code>v8_passThroughRequests</code> · <code>v8_trailingSlashAwareDataRequests</code></li>
<li><strong>제거된 것 4가지</strong>: <code>react-router-dom</code> 패키지 · <code>meta</code>/<code>matches</code>의 <code>data</code>(→ <code>loaderData</code>) · Cloudflare dev proxy(→ <code>@cloudflare/vite-plugin</code>) · <code>@react-router/architect</code>의 <code>useRequestContextDomainName</code> 옵션</li>
<li><strong>업그레이드 순서</strong>: v7 최신 → future flag 하나씩 켜고 커밋 → 제거된 API 정리 → v8 설치. 모든 변경을 <strong>v7에서 미리 적용</strong>할 수 있다는 게 핵심입니다.</li>
<li><strong>조용히 깨질 수 있는 곳</strong>: <code>.data</code> 요청 URL을 직접 다루는 서버·CDN·캐시 규칙(<code>/_root.data</code> → <code>/_.data</code>), <code>request.url</code>로 경로를 비교하던 loader, <code>isSsrBuild</code>에 기대던 Vite 설정.</li>
<li><strong>앞으로</strong>: <strong>매년 메이저</strong>를 내는 일정으로 전환. v6와 Remix v2는 <strong>EOL</strong>(보안 업데이트 종료), v7은 보안 업데이트 계속. v9(2027년 중반 예상)는 <strong>Node 24+</strong> 를 요구할 예정이고, RSC 지원은 아직 unstable입니다.</li>
</ul>

<h3 id="왜-지루한-메이저인가">왜 "지루한 메이저"인가<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#왜-지루한-메이저인가"><span class="icon icon-link"></span></a></h3>
<p>React Router는 12년 동안 여러 번 모양을 바꿨고, 오래 쓴 사람일수록 "메이저 = 대공사"라는 기억이 있습니다. <a href="/ko/posts/2022-03-12-react-router-v6/">v6 때</a>만 해도 <code>Switch</code>가 <code>Routes</code>로, <code>useHistory</code>가 <code>useNavigate</code>로 바뀌는 식이었죠.</p>
<p>v7부터 팀의 전략은 <strong>future flag</strong> 입니다. 다음 메이저에서 바뀔 동작을 현재 메이저에서 플래그로 먼저 제공하고, 사용자는 원하는 시점에 하나씩 켜서 적응합니다. 메이저가 나오는 날에는 그 플래그들이 기본값이 될 뿐이라, <strong>업그레이드 당일에 새로 고칠 게 거의 없습니다.</strong></p>
<p>공지문 작성자(Brooks Lybrand)의 표현을 빌리면, 이 방식의 유일한 단점은 "블로그 글로 띄우기 어렵다"는 것입니다. 그리고 팀은 이 지루함을 제도화하기로 했습니다 — <strong>앞으로 메이저는 매년 한 번</strong> 나옵니다.</p>
<h3 id="v7-이후-쌓인-것들">v7 이후 쌓인 것들<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#v7-이후-쌓인-것들"><span class="icon icon-link"></span></a></h3>
<p>v7의 헤드라인은 <strong>Framework 모드</strong>였습니다. Vite 플러그인 하나로 타입 안전한 Route Module API, 코드 분할, SPA/SSR/정적 렌더링, 데이터 로딩·뮤테이션을 얹는 구조입니다. 동시에 단순한 클라이언트 라우터(Declarative 모드), 직접 프레임워크를 만드는 Data 모드도 계속 지원합니다. 이 <strong>세 가지 모드를 모두 유지</strong>한다는 방침은 v8에서도 그대로입니다.</p>
<p>v7 이후 40번이 넘는 릴리스에서 추가된 것들은 다음과 같습니다(공지 기준, 전체 목록은 아님).</p>





























<table><thead><tr><th>분류</th><th>추가된 것</th></tr></thead><tbody><tr><td><strong>데이터/서버</strong></td><td>미들웨어·개선된 context · Pass-through Requests · Call-site revalidation · <code>fetcher.reset</code></td></tr><tr><td><strong>번들/빌드</strong></td><td>Split Route Modules · Vite Environment API 지원 · Object 기반 <code>route.lazy</code> · 설정 가능한 Lazy Route Discovery</td></tr><tr><td><strong>렌더링</strong></td><td>SPA 모드 개선 · 프리렌더링 개선 · (unstable) RSC 지원</td></tr><tr><td><strong>API</strong></td><td>타입 안전 <code>href</code> · <code>useRoute</code>/<code>useRouterState</code>(unstable) · <code>useTransitions</code> 라우터 prop · RouterProvider <code>onError</code> · Link masking</td></tr><tr><td><strong>운영</strong></td><td>Instrumentation API · Subresource integrity · 다수의 성능 개선 · Agent Skills</td></tr></tbody></table>
<p>v8에서 "새로 생긴" 기능이 적어 보이는 이유가 여기 있습니다. 새 기능은 이미 v7 마이너 릴리스로 다 나와 있었고, v8은 그중 일부를 <strong>기본값으로 확정</strong>하는 자리입니다.</p>
<h3 id="무엇이-바뀌나">무엇이 바뀌나<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#무엇이-바뀌나"><span class="icon icon-link"></span></a></h3>
<h4 id="1-최소-지원-버전">1. 최소 지원 버전<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#1-최소-지원-버전"><span class="icon icon-link"></span></a></h4>

























<table><thead><tr><th>대상</th><th>최소 버전</th><th>비고</th></tr></thead><tbody><tr><td><strong>Node</strong></td><td>22.22.0+</td><td>Maintenance LTS는 최신 마이너 라인만 지원</td></tr><tr><td><strong>React</strong></td><td>19.2.7+</td><td><code>react</code>, <code>react-dom</code> 모두</td></tr><tr><td><strong>Vite</strong></td><td>7+</td><td>Framework 모드만 해당. 커스텀 Vite 플러그인도 Vite 7 호환인지 확인</td></tr></tbody></table>
<p>여기에 두 가지가 더 붙습니다.</p>
<ul>
<li><strong>ESM 전용 배포</strong> — CommonJS 빌드가 빠졌습니다.</li>
<li><strong>tsconfig target/lib를 ES2022로</strong> 일괄 상향했습니다.</li>
</ul>
<p>Node 지원 정책도 명문화됐습니다. <strong>Active LTS는 모든 버전</strong>, <strong>Maintenance LTS는 최신 마이너 라인만</strong> 공식 지원합니다. 공지 시점 기준으로:</p>
<ul>
<li>Node 24는 Active LTS → 24.x 전부 지원</li>
<li>Node 22는 Maintenance LTS → <strong>22.22.x만</strong> 지원</li>
<li>Node 22.23.x가 나오면 React Router의 <strong>마이너 릴리스</strong>에서 최소 버전을 22.23.x로 올림</li>
<li>Node 22가 EOL이 되면 <strong>메이저 릴리스</strong>에서 지원 중단</li>
</ul>
<p>보안 패치가 들어간 Node 버전을 빠르게 최소 기준으로 삼기 위한 정책입니다. 뒤집어 말하면, Node 22를 쓰는 팀은 <strong>마이너 업데이트만으로도 Node 버전을 올려야 할 수 있다</strong>는 뜻이니, CI와 배포 이미지의 Node 버전을 느슨하게 두지 않는 편이 안전합니다.</p>
<h4 id="2-기본값이-된-future-flag">2. 기본값이 된 future flag<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#2-기본값이-된-future-flag"><span class="icon icon-link"></span></a></h4>
<p>v7의 v8 future flag 다섯 개가 삭제되고, 그 동작이 기본값이 되었습니다.</p>

<h3 id="앞으로의-react-router-그리고-remix">앞으로의 React Router, 그리고 Remix<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#앞으로의-react-router-그리고-remix"><span class="icon icon-link"></span></a></h3>
<ul>
<li><strong>연 1회 메이저</strong> — 메이저 버전을 정기적이고 예측 가능하게, 그래서 지루하게 만들겠다는 방침입니다.</li>
<li><strong>지원 종료</strong> — v8 출시와 함께 <strong>React Router v6와 Remix v2가 EOL</strong>이 되어 보안 업데이트도 끊깁니다. v7은 계속 보안 업데이트를 받습니다. 아직 v6에 머물러 있다면 지금이 v7로 올라갈 시점입니다.</li>
<li><strong>Server Components / Server Actions</strong> — 작업은 진행 중이지만 API를 확정하기 전이라 unstable로 남아 있습니다. opt-in 아키텍처이며, <strong>마이너 버전에서 안정화</strong>할 계획입니다.</li>
<li><strong>Open Governance</strong> — 커뮤니티 제안(Proposals) 기반으로 개발 우선순위를 정하는 모델을 유지합니다.</li>
<li><strong>설계 원칙</strong> — Less is More · Routing and Data Focused · Simple Migration Paths · Lowest Common Mode</li>
</ul>
<p>Remix와의 관계도 정리됐습니다. Remix v0~v2는 사실상 React Router의 <strong>feature branch</strong>였고, 성숙한 아이디어와 API는 React Router로 다시 합쳐졌습니다. 덕분에 Remix는 React Router와 별개로 <strong>"진정한 풀스택, 의존성 없는 JavaScript 웹 프레임워크"</strong>(Remix 3 베타) 방향으로 갑니다.</p>
<p>어느 쪽을 써야 하느냐는 질문에 대한 팀의 답은 간단합니다. <strong>검증된 것이 필요하면 React Router, 새로운 시도에 끌린다면 Remix 3.</strong></p>
<h3 id="마무리">마무리<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#마무리"><span class="icon icon-link"></span></a></h3>
<p>v8을 한 문장으로 정리하면 <strong>"v7에서 이미 할 수 있던 일을, 이제 해야 하는 일로 바꾼 릴리스"</strong> 입니다. 기능 목록은 v7 마이너 릴리스들에서 다 나왔고, v8은 그 기본값과 바닥(최소 버전)을 올렸을 뿐입니다.</p>
<p>그래서 업그레이드 난이도는 <strong>v7에서 플래그를 얼마나 켜두었느냐</strong>에 달려 있습니다. 다 켜두었다면 한 줄이고, 하나도 안 켰다면 이 글의 2~3단계를 v7 위에서 차례로 밟으면 됩니다. 어느 쪽이든 v8 설치는 마지막 단계여야 합니다.</p>
<p><strong>업그레이드 체크리스트:</strong></p>
<ul>
<li>✅ Node 22.22+ · React/React DOM 19.2.7+ · (Framework) Vite 7+ — <code>.nvmrc</code>·CI·배포 이미지까지</li>
<li>✅ v7 최신으로 올리기</li>
<li>✅ <code>v8_middleware</code> — 커스텀 서버면 <code>getLoadContext</code>, Data 모드면 <code>Future</code> 타입 augmentation</li>
<li>✅ <code>v8_splitRouteModules</code> — v8에선 최상위 <code>splitRouteModules</code></li>
<li>✅ <code>v8_viteEnvironmentApi</code> — <code>isSsrBuild</code> 분기를 <code>environments.ssr</code>로</li>
<li>✅ <code>v8_passThroughRequests</code> — <code>new URL(request.url)</code> 경로 비교를 <code>url</code> 인자로</li>
<li>✅ <code>v8_trailingSlashAwareDataRequests</code> — CDN·캐시·리라이트의 <code>/_root.data</code> → <code>/_.data</code></li>
<li>✅ <code>meta</code>/<code>matches</code>/<code>useMatches()</code>의 <code>data</code> → <code>loaderData</code></li>
<li>✅ <code>react-router-dom</code> 제거, import를 <code>react-router</code> / <code>react-router/dom</code>으로</li>
<li>✅ Cloudflare dev proxy → <code>@cloudflare/vite-plugin</code>, architect 옵션 정리</li>
<li>✅ 마지막에 <code>react-router@latest</code> 설치</li>
<li>✅ (선택) v9 대비 Node 24 검토</li>
</ul>
