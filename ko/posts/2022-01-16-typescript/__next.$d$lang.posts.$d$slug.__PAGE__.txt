f:T14445,<h2 id="타입스크립트는-왜-사용해야하는-걸까">타입스크립트는 왜 사용해야하는 걸까??<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#타입스크립트는-왜-사용해야하는-걸까"><span class="icon icon-link"></span></a></h2>
<p><strong>Typescript는 코드를 보다 읽기 쉽게 만든다.</strong></p>
<ul>
<li>변수,리턴,인터페이스 등등 타입을 명시함으로써 코드에 대한 이해가 쉬워진다.
<strong>Typescript는 개발자의 실수를 줄여준다.</strong></li>
<li>코드 작성 중/컴파일 단계에서 에러 발견이 쉽다.</li>
<li>에러에 대한 대응을 빠르게 가능하며, 사이드 이펙트를 최소화 가능하다.
<strong>IDE 를 더욱 더 적극적으로 활용 (자동완성, 타입확인)</strong></li>
<li>TypeScript 를 사용하면 자동완성이 굉장히 잘됩니다.</li>
<li>함수를 사용 할 때 해당 함수가 어떤 파라미터를 필요로 하는지, 그리고 어떤 값을 반환하는지 코드를 따로 열어보지 않아도 알 수 있습니다.</li>
<li>리액트 컴포넌트의 경우 props/state 값을 미리 알 수 있다.
<strong>객체지향 프로그래밍 지원</strong></li>
<li>인터페이스, 제네릭, 오버로딩/오버라이딩 등과 같은 강력한 객체지향 프로그래밍 지원은 크고 복잡한 프로젝트의 코드 기반을 쉽게 구성이 가능하다.</li>
</ul>

<ul>
<li>어떤 상황일 때 type, interface로 사용할 지 여부를 결정해보자!!
<ul>
<li>lastest 버전의 tslint에서 가이드를 제공해주고 있다.
<ul>
<li>Use an interface instead of a type literal.tslint(interface-over-type-literal)
<ul>
<li>타입은 리터럴 타입에서만 사용하고 Object 형태의 타입은 인터페이스를 쓰라는 가이드가 추가되었습니다.</li>
</ul>
</li>
</ul>
</li>
<li><strong>리터럴 타입(즉, primitive type, custom value)외에는 interface를 사용해 봅시다.</strong></li>
<li>참고페이지: <a href="https://luckyyowu.tistory.com/401">https://luckyyowu.tistory.com/401</a></li>
</ul>
</li>
</ul>
<p><strong>동일한점</strong></p>
<ul>
<li>명명된 타입은 Type, Interface 동일하게 사용됨</li>
<li>인덱스 시그니처 사용 가능</li>
<li>함수 타입 선언 가능</li>
<li>제네릭 사용가능</li>
<li>확장 가능
<ul>
<li>interface는 extends 키워드로 type은 &#x26; 로 확장</li>
</ul>
</li>
</ul>
<p><strong>다른점</strong></p>
<ul>
<li>
<p>유니온 타입</p>
<ul>
<li>Type으로는 가능 하지만, Interface는 할 수 없음
<ul>
<li>type yesOrNo = ‘yes’ | ‘no’</li>
</ul>
</li>
<li>유니온 타입을 확장하고 싶을때 interface로는 안됨</li>
</ul>
</li>
<li>
<p>튜플과 배열 타입</p>
<ul>
<li>type : 사용하기 쉽고 확장이 편함, interface: 다소 복잡하고 불편함</li>
</ul>

<h2 id="typescript-공식페이지-dos-and-donts-가이드">typescript 공식페이지: Do's and Don'ts 가이드<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#typescript-공식페이지-dos-and-donts-가이드"><span class="icon icon-link"></span></a></h2>
<p><strong>General Types</strong></p>
<ul>
<li>Don’t
<ul>
<li>Number, String, Boolean 또는 Object 타입을 절대 사용하지 마라. 이 타입들은 JavaScript 코드에서 대부분 적절하지 않게 사용되는 non-primitive boxed object1들을 의미한다.</li>
</ul>
</li>
<li>Do
<ul>
<li>number, string 그리고 boolean을 사용하라.</li>
</ul>
</li>
</ul>
<pre><code>/* WRONG */
function reverse(s: String): String;

/* OK */
function reverse(s: string): string;
</code></pre>
<p><strong>Callback Types</strong>
<strong>Return Types of Callbacks</strong></p>
<ul>
<li>Don’t
<ul>
<li>값이 무시될 콜백의 리턴타입으로 any를 사용하지 마라.</li>
</ul>
</li>
<li>Do
<ul>
<li>값이 무시될 콜백의 리턴타입으로 void를 사용하라.</li>
</ul>
</li>
</ul>
<pre><code>/* WRONG */
function fn(x: () => any) {
  x();
}

/* OK */
function fn(x: () => void) {
  x();
}

// 이유는? 확인되지 않는 방법으로 x의 리턴타입을 사용하는 실수를 방지해주기 때문에 void를 사용하는 것이 더 안전하다.
function fn(x: () => void) {
  var k = x(); // oops! meant to do something else
  k.doSomething(); // error, but would be OK if the return type had been 'any'
}

</code></pre>
<p><strong>Function Overloads</strong></p>
<ul>
<li>Don’t
<ul>
<li>더 구체적인 시그니처 전에 일반적인 시그니처를 두지 마라.</li>
</ul>
</li>
<li>Do
<ul>
<li>더 구체적인 시그니처 다음에 일반적인 시그니처를 두도록 정렬하라.</li>
</ul>
</li>
</ul>
<pre><code>/* WRONG */
declare function fn(x: unknown): unknown;
declare function fn(x: HTMLElement): number;
declare function fn(x: HTMLDivElement): string;
var myElem: HTMLDivElement;
var x = fn(myElem); // x: unknown, wat?

/* OK */
declare function fn(x: HTMLDivElement): string;
declare function fn(x: HTMLElement): number;
declare function fn(x: unknown): unknown;
var myElem: HTMLDivElement;
var x = fn(myElem); // x: string, :)
</code></pre>
<p><strong>Use Optional Parameters</strong></p>
<ul>
<li>Don’t
<ul>
<li>뒤에 나오는 매개변수들만 다른 경우 여러 시그니처를 작성하지 마라.</li>
</ul>
</li>
<li>Do
<ul>
<li>가능한 경우에는 선택적 매개변수를 사용하라.</li>
</ul>
</li>
</ul>
<pre><code>/* WRONG */
interface Example {
  diff(one: string): number;
  diff(one: string, two: string): number;
  diff(one: string, two: string, three: boolean): number;
}

/* OK */
interface Example {
  diff(one: string, two?: string, three?: boolean): number;
}
</code></pre>
<p>이 방법은 모든 시그니처의 리턴타입이 같은 경우에만 가능하다는 것을 주의!!</p>
<h4 id="use-union-types">Use Union Types<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#use-union-types"><span class="icon icon-link"></span></a></h4>
<ul>
<li>Don’t
<ul>
<li>오직 하나의 매개변수 타입이 다른 경우에는 오버로딩을 사용하지 마라.</li>
</ul>
</li>
<li>Do
<ul>
<li>가능한 경우에는 유니온 타입을 사용하라.</li>
</ul>
</li>
</ul>
<pre><code>/* WRONG */
interface Moment {
  utcOffset(): number;
  utcOffset(b: number): Moment;
  utcOffset(b: string): Moment;
}

/* OK */
interface Moment {
  utcOffset(): number;
  utcOffset(b: number | string): Moment;
}
</code></pre>
<ul>
<li>

<li><a href="https://nukeguys.github.io/dev/ts-do-and-dont/">https://nukeguys.github.io/dev/ts-do-and-dont/</a></li>
</ul>
</li>
</ul>

<h2 id="utility-type">utility type<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#utility-type"><span class="icon icon-link"></span></a></h2>
<h3 id="partial">Partial<t></t><a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#partial"><span class="icon icon-link"></span></a></h3>
<pre><code>특정 타입의 부분 집합을 만족하는 타입을 정의할 수 있습니다.

```tsx
interface Address {
  email: string;
  address: string;
}

type MyEmail = Partial&#x3C;Address>;
const me: MyEmail = {}; // 가능
const you: MyEmail = { email: 'gmm117@naver.com' }; // 가능
const all: MyEmail = { email: 'gmm117@naver.com', address: 'seoul' }; // 가능
```
</code></pre>
<h3 id="excludet-u">Exclude&#x3C;T, U><a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#excludet-u"><span class="icon icon-link"></span></a></h3>
<pre><code>T에서 U에 할당할 수 있는 교집합 속성을 제외한 타입을 구성합니다.
```tsx
type T0 = Exclude&#x3C;'a' | 'b' | 'c', 'a'>; // "b" | "c"
type T1 = Exclude&#x3C;'a' | 'b' | 'c', 'a' | 'b'>; // "c"
type T2 = Exclude&#x3C;string | number | (() => void), Function>; // string | number
```
</code></pre>
<h3 id="extractt-u">Extract&#x3C;T, U><a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#extractt-u"><span class="icon icon-link"></span></a></h3>
<pre><code>T에서 U에 할당 할 수 있는 교집합 속성을 추출하여 타입을 구성합니다.
```tsx
type T0 = Extract&#x3C;'a' | 'b' | 'c', 'a' | 'f'>; // "a"
type T1 = Extract&#x3C;string | number | (() => void), Function>; // () => void
```
</code></pre>
<h3 id="nonnullable">NonNullable<t></t><a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#nonnullable"><span class="icon icon-link"></span></a></h3>
<pre><code>T에서 null 과 undefined를 제외한 타입을 구성합니다.
```tsx
type T0 = NonNullable&#x3C;string | number | undefined>; // string | number
type T1 = NonNullable&#x3C;string[] | null | undefined>; // string[]
```
</code></pre>
<h3 id="readonly">Readonly<t></t><a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#readonly"><span class="icon icon-link"></span></a></h3>
<pre><code>T의 모든 프로퍼티를 읽기 전용(readonly)으로 설정한 타입을 구성합니다, 즉 생성된 타입의 프로퍼티는 재할당할 수 없습니다.

```tsx
interface Todo {
  title: string;
}

const todo: Readonly&#x3C;Todo> = {
  title: 'Delete inactive users',
};

todo.title = 'Hello'; // 오류: 읽기 전용 프로퍼티에 재할당할 수 없음
```
</code></pre>
<h3 id="pick">Pick<t></t><a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#pick"><span class="icon icon-link"></span></a></h3>
<pre><code>특정 타입에서 몇 개의 속성을 선택하여 타입을 정의합니다

```tsx
interface Address {
  email: string;
  address: string;
}

type MyEmail = Pick&#x3C;Address, 'email'>;
// email 속성 일부만 사용
```
</code></pre>

<h3 id="returntype">ReturnType<t></t><a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#returntype"><span class="icon icon-link"></span></a></h3>
