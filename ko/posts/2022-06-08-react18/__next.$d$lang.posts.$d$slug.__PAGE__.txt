<h2 id="동시성concurrent-기능">동시성(Concurrent) 기능<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#동시성concurrent-기능"><span class="icon icon-link"></span></a></h2>
<h3 id="starttransition">startTransition<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#starttransition"><span class="icon icon-link"></span></a></h3>
<p>전환 업데이터를 소개하기 전에 리액트의 상태 업데이트에 대해서 알아봅시다.</p>
<ul>
<li><strong>긴급 업데이트(Urgent updates)</strong>: 직접적인 상호 작용 반영(타이핑, 오버, 스크롤링 등)
<ul>
<li>사용자의 입력에 따라 즉각적으로 업데이트되지 않으면(화면 멈춤, 렉 등) 문제가 있다고 느끼는 영역입니다.</li>
</ul>
</li>
<li><strong>전환 업데이트(Transition updates)</strong>: 하나의 뷰에서 다른 뷰로의 UI 전환
<ul>
<li>화면에 즉시 나타나는 걸 기대하지 않는 영역입니다</li>
</ul>
</li>
</ul>
<p>리액트 17 이전까지는 긴급/전환 업데이트를 명시할 수 있는 방법이 없이, 모두 긴급 업데이트로 상태를 업데이트 하고 있었습니다.</p>
<p>그 문제점으로 사용자의 디바이스가 성능이 느리거나, 네트워크가 느려서 전환 업데이트가 느려질 경우라도 긴급 업데이트에 방해가 되면 안되지만, 17버전 이전까지는 방해가 되는 문제점을 가지고 있었습니다.</p>
<p>이런 문제점을 해결하기 위해서 setTimeout, throttle, debounce 같은 기술로 회피하는게 최선의 방법이였습니다.</p>
<p>리액트 18 버전 이후부터는 startTransition api를 제공해서 긴급 업데이트/전환 업데이트를 직접 명시할 수 있는 방법이 생겼습니다.</p>

<h3 id="usetransition-vs-usedeferredvalue">useTransition vs useDeferredValue<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#usetransition-vs-usedeferredvalue"><span class="icon icon-link"></span></a></h3>
<ul>
<li>상태 제어가 가능할때는 useTransition를 사용하고 props에서 값에만 접근이 가능한 경우엔 useDeferredValue를 사용</li>

<h2 id="서버-사이드-렌더링에-서스펜스-지원">서버 사이드 렌더링에 서스펜스 지원<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#서버-사이드-렌더링에-서스펜스-지원"><span class="icon icon-link"></span></a></h2>
<p>기존의 리액트 SSR는 다음 4단계를 거쳤습니다.</p>
<ul>
<li>서버에서 전체 앱의 데이터를 받습니다.(Data Fetching)</li>
<li>그 후, 서버에서 전체 앱을 HTML로 렌더링한 후 Response로 전송합니다.</li>
<li>그 후, 클라이언트에서 전체 앱의 자바스크립트 코드를 로드합니다.</li>
<li>그 후, 클라이언트에서 서버에서 생성된 전체 앱의 HTML과 자바스크립트 로직을 연결합니다(Hydration)</li>
</ul>
<p>중요한 것은, 앱 전체를 대상으로 각 단계가 완료되어야만 다음 스텝으로 넘어갈 수 있었으므로, 단계별로 지연이 발생할 경우 사용자는 흰 화면을 보게 되서 UX 안좋은 경험을 하게 됩니다.</p>
<p>문제점 도출</p>
<ul>
<li>특정 컴포넌트를 렌더링하는데 필요한 데이터 패칭이 오래 걸릴 경우</li>
<li>특정 컴포넌트 코드량이 커서 로딩이 오래 걸린경우</li>
<li>특정 컴포넌트의 로직이 복잡해서 시간이 오래 걸릴 경우</li>
</ul>
<p>리액트 18 버전 이후부터는 렌더링 비용이 많이 드는 서브 컴포넌트를 Suspend로 감싸서 전체 앱의 Hydration을 방해하지 않고 진행이 가능합니다.(추후에 서브 컴포넌트가 독립적으로 Hydration 진행)</p>
<p>Suspend를 사용하기 위해서는 renderToPipeableStream 함수를 사용해야 합니다.</p>
<ul>
<li>renderToString(React.Node): string: Be able to run ( Limited support Suspense)</li>
<li>renderToNodeStream(React.Node): Readable: Not recommended ( Fully support Suspense, barring stream)</li>
<li>renderToPipeableStream(React.Node, Options): Controls: <strong>The latest recommendation</strong> ( Fully support Suspense and stream)</li>
</ul>

<h2 id="usesyncexternalstore">useSyncExternalStore<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#usesyncexternalstore"><span class="icon icon-link"></span></a></h2>
<p>React 18부터 Concurrent read를 지원하게 되면서 외부 스토어를 강제로 동기화 하여 업데이트 하게 해주는 새로운 훅이다.</p>
<ul>
<li>External Store: 외부 스토어란, 리액트 내부가 아닌 외부에서 상태를 관리하고 구독하고 있는 것을 뜻합니다. 예로는 redux, mobx, 글로벌 변수, dom 상태 등이 이에 속합니다.</li>
<li>Internal Store: 리액트 내우베어 사용되는 상태를 뜻합니다. props, context, useState, useReducer 등이 이에 속합니다.</li>
<li>tearing: 하나의 상태가 여러 UI에 영향을 줄 경우에 컴포넌트 별로 업데이트 속도가 달라서 UI가 달라져 보이는 것을 의미합니다.</li>
</ul>
<p>리액트 18 이전에는 렌더링을 일시중지/지연이 불가능 했기때문에, 상태가 업데이트 되면 화면이 변경이 무조건 수행이 되었기 떄문에 문제가 없었습니다.</p>
<p>리액트 18 이후부터는 Concurrent 렌더링이 등장하면서, 일시중지/지연이 발생할 경우 컴포넌트 별로 업데이트가 다를 수 있어서 다른 값을 보여줄 수 있는 문제가 발생하게 됩니다.</p>
<p>해당 이슈를 해결하기 위해서, React 18에서는 useSyncExternalStore 훅을 제공하면서 UI를 항상 일관성이 있게 유지하도록 처리가 가능합니다.</p>
<p><img src="/blog-assets/2022/06/images/08/Untitled2.png" alt="Untitled"></p>
<p>외부 스토어 데이터와 화면의 불일치를 tearing</p>
<p><img src="/blog-assets/2022/06/images/08/210630_fin_03_tearing.gif" alt="210630_fin_03_tearing.gif"></p>
<p>tearing에 대한 테스트</p>
<p><code>useSyncExternalStore</code>는 두개의 함수를 인자로 받는다.</p>
<ul>
<li><code>subscribe</code>: 등록할 콜백 함수</li>
<li><code>getSnapshot</code>: 마지막 이후로 subscribe 중인 값이 렌더링된 이후 변경되었는지, 문자여이나 숫자 처럼 immutable한 값인지, 혹은 캐시나 메모된 객체인지 확인하는데 사용된다. 이후, 훅에 의해서 immutable한 값이 반환된다.</li>
</ul>
