f:T6d80,<h3 id="웹어셈블리-나온-이유">웹어셈블리 나온 이유<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#웹어셈블리-나온-이유"><span class="icon icon-link"></span></a></h3>
<p>구글의 <a href="https://developer.chrome.com/native-client">NaCI</a>(Native Client), 모질라의 <a href="http://asmjs.org/">asm.js</a>(JavaScript 서브셋) 등 네이티브 머신 코드를 웹으로 가져오기 위한, 그리고 빠르게 실행하기 위한 시도들은 결과적으로 웹어셈블리(이하 'wasm'으로 표기)로 귀결되면서 개발이 시작되었다.</p>
<p>2019년 12월, W3C는 현재 <a href="https://webassembly.github.io/spec/core/">1.1 버전</a> 상태인 wsam를 HTML, CSS 그리고 JavaScript에 이어 웹의 4번째 언어로 공식 권고함</p>
<h3 id="웹어셈블리-구동방식">웹어셈블리 구동방식<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#웹어셈블리-구동방식"><span class="icon icon-link"></span></a></h3>
<p>JavaScript 엔진 내에서 JavaScript 코드와 wasm의 실행 과정</p>
<ul>
<li>컴파일된 바이너리 포맷의 wasm 모듈은 JavaScript를 대신하거나 JavaScript 내에서 실행되지 않고, JavaScript와 같이 JavaScript 엔진 내에서 나란히 실행</li>
</ul>
<p><img src="/blog-assets/2022/01/assets/08/Untitled.png" alt="Untitled"></p>
<p>Emscripten은 C/C++ 코드를 가져와 LLVM을 통해 전달하고 LLVM 생성 바이트 코드를 JavaScript(특히 JavaScript의 하위 집합인 Asm.js)로 변환합니다.</p>
<p>WASM 생성과정</p>
<ul>
<li>C,C++ → [Clang툴(LLVM) → LLVM 바이트코드 생성 → Asm.js 변환]: Emscripten</li>
</ul>
<p><img src="http://i.imgur.com/1yoy1Fal.png" alt="http://i.imgur.com/1yoy1Fal.png"></p>
<p>emscripten 변천</p>
<ol>
<li>wasm 컴파일은 <a href="https://github.com/emscripten-core/emscripten-fastcomp/">fastcomp</a>(LLVM plus Emscripten's asm.js backend)가 백엔드를 담당</li>
<li>C/C++을 컴파일해 중간 표현식(IR)</li>
<li>fastcomp를 통해 asm.js로 컴파일</li>
<li><a href="https://github.com/WebAssembly/binaryen/blob/master/src/asm2wasm.h">asm2wasm</a>을 사용해 wasm으로 이어지는 컴파일 파이프라인</li>
</ol>
<p><img src="/blog-assets/2022/01/assets/08/Untitled3.png" alt="Untitled3"></p>
<p>V8 팀은 Emscripten에서 불필요한 asm.js 컴파일 과정을 거치지 않고, 네이티브 LLVM wasm 백엔드가 기본 파이프라인이 되도록 개선해 많은 영역에서 성능 개선을 이뤄냈다고 밝혔다.</p>
<p><a href="https://twitter.com/v8js/status/1145704863377981445">https://twitter.com/v8js/status/1145704863377981445</a></p>
<h3 id="wasm을-왜-사용하는걸까">wasm을 왜 사용하는걸까?<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#wasm을-왜-사용하는걸까"><span class="icon icon-link"></span></a></h3>
<p>JavaScript 엔진의 단계별 작업 과정</p>
<p><img src="/blog-assets/2022/01/assets/08/Untitled1.png" alt="Untitled"></p>
<h4 id="fetching">Fetching<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#fetching"><span class="icon icon-link"></span></a></h4>
<p>실행할 모듈/코드를 로딩하는 과정</p>
<p>⇒ wasm은 바이너리 파일임으로, 자바스크립트 minify, magling을 하더라도 로딩속도는 향상</p>
<h4 id="parse">Parse<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#parse"><span class="icon icon-link"></span></a></h4>
<p>다운로드한 소스 코드를 파싱해 인터프리터가 이해할 수 있도록 만드는 과정</p>
<p>Javacript: JS → AST → Javascript 엔진 이해할 수 있는 바이트코드 생성 → 실행</p>
<p>WSAM: LLVM을 통한 중간표현식(asm.js) → 디코딩, 오류여부 파악 → 실행</p>
<h4 id="compile--optimize">Compile + Optimize<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#compile--optimize"><span class="icon icon-link"></span></a></h4>
<ul>
<li>기준 및 최적화 컴파일러를 통해 컴파일되는 과정</li>
</ul>
<p>Javascript : <a href="https://en.wikipedia.org/wiki/Just-in-time_compilation">JIT</a>(Just-In-Time) 컴파일러를 통해 실행되는 동안 컴파일이 동시에 이뤄</p>
<p><img src="/blog-assets/2022/01/assets/08/Untitled2.png" alt="Untitled"></p>
<p>WSAM</p>
<ol>
<li>wasm 자체는 기계어에 가까우며, 명시적 타입(32 bit와 64 bit Float와 Integer로 구성된 <a href="https://webassembly.github.io/spec/core/syntax/types.html">4가지 원시 타입</a> - f32, f64, i32, i64)이 사용</li>
<li>JS 엔진 컴파일 시 타입체킹X</li>
<li>LLVM을 통해 여러 가지 최적화가 적용된 상태이므로, 컴파일과 최적화에 많은 작업을 수행할 필요가 없다.</li>
</ol>
<h4 id="re-optimize">Re-optimize<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#re-optimize"><span class="icon icon-link"></span></a></h4>
<p>JIT 컴파일러의 예측이 틀렸을 때 재최적화하거나 최적화 코드를 구제해 다시 기준 코드로 전달하는 재조정 과정</p>
<ul>
<li>이전 변수의 타입이 직전 반복과 다른 경우, 다시 최적화가 필요한 경우</li>
<li>WSAM: 최적화 상태이고, 타입에 대한 체크가 필요없어 재최적화 사이크 불필요</li>
</ul>
<h4 id="execute">Execute<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#execute"><span class="icon icon-link"></span></a></h4>
<p>코드의 실행</p>
<p>WSAM : 컴파일러를 타겟으로 디자인되어 있어 컴파일러 최적화된 결과물을 출력</p>
<p>Javascript: 최적화된 코드사용은 개발자의 역량에 의존</p>
<h4 id="gc">GC<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#gc"><span class="icon icon-link"></span></a></h4>
<p>할당되었지만 더는 사용되지 않는 메모리 영역을 해제하는 과정</p>
<p>WSAM: 메모리 생성,해제를 명시적으로 해주고 있기 때문에 GC가 불필요하다.</p>
<p>그외에 좋아진 점</p>
<p>사용 메모리 확장(2GB -> 4GB)</p>
<p>데이터 공유(web worker간 데이터 공유 → ShareArrayBuffer),</p>
<p>→ c++ pthread 이용해서 ipc 통신 가능</p>

<h4 id="추가설명">추가설명<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#추가설명"><span class="icon icon-link"></span></a></h4>
<p>Yew:</p>
<p><a href="https://webassembly.org/">WebAssembly</a>를 사용하여 다중 스레드 프론트 엔드 웹 앱을 만들기 위한 최신 <a href="https://www.rust-lang.org/">Rust</a> 프레임워크</p>
<p>DOM API 호출을 최소화</p>
<p>wasm_bindgen</p>
<p>js engine ↔ 웹어셈블리는 숫자타입만 지원가능(그외에 타입을 지원하기 위해서 추가)</p>
<p>JavaScript 파일은 Rust를 호출할 때 사용될 인터페이스 역할</p>
<figure data-rehype-pretty-code-figure=""><pre tabindex="0" data-language="rust" data-theme="github-light-high-contrast github-dark-high-contrast"><code data-language="rust" data-theme="github-light-high-contrast github-dark-high-contrast" style="display: grid;"><span data-line=""><span style="--shiki-light:#0E1116;--shiki-dark:#F0F3F6">export function </span><span style="--shiki-light:#622CBC;--shiki-dark:#DBB7FF">greet</span><span style="--shiki-light:#0E1116;--shiki-dark:#F0F3F6">(s</span><span style="--shiki-light:#A0111F;--shiki-dark:#FF9492">:</span><span style="--shiki-light:#0E1116;--shiki-dark:#F0F3F6"> string); </span><span style="--shiki-light:#66707B;--shiki-dark:#BDC4CC">// rust -> js</span></span>
<span data-line=""> </span>
<span data-line=""><span style="--shiki-light:#A0111F;--shiki-dark:#FF9492">const</span><span style="--shiki-light:#0E1116;--shiki-dark:#F0F3F6"> rust </span><span style="--shiki-light:#A0111F;--shiki-dark:#FF9492">=</span><span style="--shiki-light:#622CBC;--shiki-dark:#DBB7FF"> import</span><span style="--shiki-light:#0E1116;--shiki-dark:#F0F3F6">(</span><span style="--shiki-light:#032563;--shiki-dark:#ADDCFF">"./wasm_greet"</span><span style="--shiki-light:#0E1116;--shiki-dark:#F0F3F6">); </span><span style="--shiki-light:#66707B;--shiki-dark:#BDC4CC">// js -> rust</span></span>
<span data-line=""><span style="--shiki-light:#0E1116;--shiki-dark:#F0F3F6">rust</span><span style="--shiki-light:#A0111F;--shiki-dark:#FF9492">.</span><span style="--shiki-light:#622CBC;--shiki-dark:#DBB7FF">then</span><span style="--shiki-light:#0E1116;--shiki-dark:#F0F3F6">(m </span><span style="--shiki-light:#A0111F;--shiki-dark:#FF9492">=></span><span style="--shiki-light:#0E1116;--shiki-dark:#F0F3F6"> m</span><span style="--shiki-light:#A0111F;--shiki-dark:#FF9492">.</span><span style="--shiki-light:#622CBC;--shiki-dark:#DBB7FF">greet</span><span style="--shiki-light:#0E1116;--shiki-dark:#F0F3F6">(</span><span style="--shiki-light:#032563;--shiki-dark:#ADDCFF">"World!"</span><span style="--shiki-light:#0E1116;--shiki-dark:#F0F3F6">));</span></span></code></pre></figure>
