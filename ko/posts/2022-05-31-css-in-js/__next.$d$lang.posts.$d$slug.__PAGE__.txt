1a:T11661,<h2 id="css-in-js-왜-만들어졌나">CSS-in-JS 왜 만들어졌나?<a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#css-in-js-왜-만들어졌나"><span class="icon icon-link"></span></a></h2>
<p>CSS-in-JS는 단어 그대로 자바스크립트 코드에서 CSS를 작성하는 방식을 말합니다. 2014년 페이스북 개발자인 Christopher Chedeau aka Vjeux가 처음 소개하였습니다.</p>
<p><img src="/blog-assets/2022/05/images/31/Untitled.png" alt="Untitled"></p>
<p>Vjeux는 CSS를 작성하는 어려움을 다음과 같이 설명하였으며 CSS-in-JS로 이들 이슈를 모두 해결할 수 있다고 강조했습니다.</p>
<ul>
<li>
<p>Global namespace: 글로벌 공간에 선언된 이름의 명명 규칙 필요</p>
<ul>
<li>Issue
<ul>
<li>CSS 처음부터 document를 스타일을 하기 위해 설계되었기 때문에 모듈형식의 scope 개념이 없음(전역 스코프/네임스페이스)</li>
<li>CSS 방법론(BEM), Module/Scope 형식처럼 CSS rule이 여러 Element에 영향을 안받도록 했지만, 여전히 모듈단위 스코프를 지원하지 않음</li>
</ul>
</li>
<li>Solution
<ul>
<li>CSS-in-JS는 style을 JS에서 정의하기 때문에 style variable이 lexical scope(컴포넌트 단위 스코프)에 한정</li>
<li>CSS-in-JS는 style variable를 얼마든지 export/import 하여서 재사용이 가능합니다</li>
</ul>
</li>
</ul>

</li>
<li>
<p>Implicit Dependencies: 의존 관계를 관리</p>
<ul>
<li>Issue
<ul>
<li>JS/CSS 모듈이 분리 되어 있어 className/attribute 관계가 명시적이지 않기 때문에 개발자가 기억해서 관리를 해줘야하는 어려움이 있음</li>
</ul>
</li>
<li>Solution
<ul>
<li>CSS-in-JS는 CSS를 JS에 작성하기 때문에 정적 분석이 가능하고, IDE의 도움을 받아서 사용/미사용 여부를 관리가 쉬워짐</li>
</ul>
</li>
</ul>
</li>
<li>
<p>Dead Code Elimination: 미사용 코드 검출</p>
<ul>
<li>Issue
<ul>
<li>의존 관계 관리가 어려워서 사용되고 있지 않는(dead code) 인지 파악하기 힘들다.</li>
<li>구글 크롬의 coverage로 사용이 가능하지만, 추가적인 작업시간이 들어가게 된다.</li>
</ul>
</li>
<li>Solution
<ul>
<li>CSS-in-JS 를 사용한다면 eslint, IDE에 도움을 받아서 미사용되는 코드를 간단히 제거가 가능함.</li>
</ul>
</li>
</ul>
</li>
<li>
<p>Non-deterministic Resolution</p>
<ul>
<li>Issue
<ul>
<li>CSS rule은 specificity가 높은 것이 적용된다. 그런데 만약 같은 specificity를 가진다면, 뒤에 정의된 rule이 적용된다.</li>
<li>만약 같은 specificity를 갖는 CSS들을 async하게 불러오면 어떤 CSS rule이 적용될까? 답은 모른다.</li>
<li>이를 Non-deterministic Resolution이라고 한다.
<img src="/blog-assets/2022/05/images/31/Untitled1.png" alt="Untitled"></li>
</ul>
</li>
<li>Solution
<ul>
<li>HTML/CSS/JS를 모듈(컴포넌트) 단위로 강하게 결합시켜서 CSS 우선순위를 결정할 수 있게 처리가 가능하다.</li>
</ul>
</li>
</ul>
</li>
<li>
<p>Minification: 클래스 이름의 최소화</p>

</li>
