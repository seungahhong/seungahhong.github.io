<h3 id="no-event-pooling"><strong>No Event Pooling</strong><a class="heading-anchor" aria-hidden="true" tabindex="-1" href="#no-event-pooling"><span class="icon icon-link"></span></a></h3>
<ul>
<li>이벤트 풀링
오래된 브라우저에서 이벤트 객체를 사용 시 성능 저하되는 이슈가 있어서 리액트에서는 Synthetic Event pool를 만들어서 관리하고 한다.
<ul>
<li>사용자가 특정 이벤트가 발생할 경우
<ul>
<li>Synthetic Event pool 에서 syn Synthetic Event 객체의 참조 넘겨줌(→ 객체 생성시간 축소)</li>
<li>이벤트 정보의 Synthetic Event 객체를 넣어줌</li>
<li>사용자가 정의한 이벤트 리스너 수행</li>
<li>Synthetic Event 객체 초기화( → null 넣어줌으로써 GC 메모리 가져가도록 처리, 메모리 효율화를 위한 작업))
해당 기능으로 인해서 인해서 비동기 동작에서 에러가 나는 경우가 생기기 됩니다.</li>
</ul>
</li>
</ul>

</ul>
<p>v17 부터는 더 이상 구형 브라우저에서 성능 이슈 보완을 위한 동작을 지원하지 않기로 결정함</p>
<p>단, event.persist() 메서드는 그대로 존재하지만, 호출하더라도 아무런 동작을 하지 않음(하위호환을 위한 작업)</p>

<li><strong>React 17 부터는 Event가 document 가 아닌 React Tree Root 로 delegate 된다.</strong></li>
</ul>
<p><img src="/blog-assets/2022/02/images/13/Untitled.png" alt="Untitled"></p>
<p>여러 리액트 컴포넌트 수행되더라도 기본이 되는 Root Element 이벤트를 처리하기 때문에 구조/이벤트 방식이 독립적으로 수행가능하다.</p>
<p>리액트가 다른 기술과 사용하는 것을 더욱 용이하게 한다. 만약 외부에 jQuery가 존재하고, 내부에는 리액트가 존재한다면 이제 예상대로 이벤트 전파를 jQuery단까지 막을 수 있다.</p>
<p>단, DOM에 **<code>document.addEventListener</code>**를 활용하여 수동으로 이벤트를 붙여서 리액트의 모든 이벤트를 감지하는 코드가 존재할 수 있다. 리액트 16버전 에서는 이러한 코드가 가능했지만, 리액트 17 부터는 전파가 막히게 되므로 **<code>document</code>**에서도 이벤트가 발생하는지 알 수 없기때문에 capturing 방식으로 변경이 필요하다.</p>
